# Source map: src/tracker.rs (at af1b304)

## Behaviour traps
- Byte-offset interleaving (L588-597): each Piece is handled in stream order. Bytes go to the model, then the filter; a Marker mutates the model (tag/mark_line_start) BEFORE the next Bytes piece is advanced. If MarkerTracker returns ScreenCommands, they must be applied right after each marker, never batched to the end of the batch, or cells get the wrong tag.
- WindowName goes to the filter only, never to the model (L594: `Piece::WindowName(b) => self.filter.feed(&b, out)`). Routing it to the model makes the cursor drift (window_name_reaches_the_terminal_but_is_not_printed asserts column 4).
- Markers never reach `out`: `Piece::Marker(p) => self.on_marker(&p, model)` writes nothing to the output (markers_stripped_from_output).
- batch_markers counts EVERY OSC 697 marker, including ignored ones. `self.batch_markers += 1;` (L619) runs before the `val == Some("")` early return (L624) and before the lock gate (L627). A refactor that counts only handled markers changes when the Windows deferral flushes (L599-601).
- The deferred flush at the end of a batch runs only when the batch had zero markers. It uses the cursor at the END of that later batch (L598-601; windows_deferral_fifo: 'applies the queue in order, at the current cursor'), not at the original marker's offset.
- Mid-batch flushes: NoHistory calls `self.flush_deferred(model)` before setting the flag (L649), and pre_exec calls it before scraping (L712). The scrape must see the deferred NewCmd's tags and new cycle n.
- pre_exec scrapes the model at the PreExec byte offset (`self.extract(model)`, L713-716) and does NOT filter by at_prompt or alt screen. pty's `refresh` filters by both (pty.rs:801-805). Reusing pty's cached `cur` for pre_exec changes recorded history (the transient-prompt tests).
- Trimming differs per key and must not be unified: `let v = val.unwrap_or("").trim();` (L635) is used by most keys, but Dir uses the untrimmed `val.unwrap_or("")` (L654), NewCmd compares the untrimmed `val != Some(self.sid.as_str())` (L644), and PwshPrompts splits the untrimmed val (L670), as its comment says: 'untrimmed: the prompts end in spaces'.
- `Dir` without '=' gives val None and sets `cwd = Some(PathBuf::from(""))` (L654). Only `Dir=` (empty value) is ignored (L624).
- The lock allow-list is exactly `"NewCmd" | "PreExec" | "NoHistory" | "OSCLock" | "OSCUnlock" | "User"` (L630). StartPrompt and EndPrompt are dropped while locked (not deferred). Deleting the `user` field must not change this list's effect on the other keys.
- `"Shell" => { self.shell = Shell::from_name(v); ... }` (L656-658) can REPLACE a known shell with None (e.g. `Shell=sh`), while shell_name keeps the raw string. pty falls back with `self.tracker.shell.unwrap_or(self.shell)` (pty.rs:740). Do not write `from_name(v).or(self.shell)`.
- `"ExitCode" => self.exit_code = v.parse().ok()` and `"PID" => self.pid = v.parse().ok()` (L655, L661): an unparsable value overwrites the old one with None.
- new_cmd calls `self.exit_code.take()` (L694) BEFORE the pending lookup, so even a redraw or a nested shell's first prompt consumes ExitCode. `self.submitted = None` (L698) runs ONLY when a pending entry matched.
- The pending lookup `rposition(|p| p.pid == self.pid)` (L695) compares Option<i32>, so None == None matches when no PID was ever reported. `drain(k..).rev()` emits the innermost command first, and every drained entry gets the same exit code (nested_shell test).
- now_secs() is called per drained entry (L701) and at pre_exec (L743). The domain must take the time as input; one value per batch can differ only across a second boundary.
- The HistoryEntry built at L737-745: shell is the RAW `shell_name.unwrap_or_default()` (not Shell::name()), cwd is `p.display().to_string()` (lossy), hostname/end_time/exit_code come from `..Default::default()` (None). Phase 3's entity constructor must allow exactly this.
- `std::mem::take(&mut self.no_history)` (L732) resets the flag at PreExec. `"NoHistory" if !self.preexec` (L648) ignores it while a command runs. An empty command means 'do not record' and becomes Event::CommandEnded (L703-707).
- new_cmd order (L684-691): `redraw` is computed BEFORE the cycle increments; then tag(c{n}); then mark_line_start(from=c{old}), which reads `model.grid().cursor.template.hyperlink()` (L1005), i.e. the link the tag just set; then line_col0 is read from the cursor column. ScreenCommands must be applied in this order.
- mark_line_start (L1013-1029): cells before the cursor that are ours or untagged become the prompt tag, ours at or after the cursor get the template link, and it continues over WRAPLINE rows only when `from` is Some.
- There are two different 'at prompt' meanings. `Tracker::at_prompt()` (L614-616: cycle open and !preexec) is not `Extracted::at_prompt` (L500, L843-854: cursor on the command line). pty uses both in suppressed() (pty.rs:960-963). The EditBuffer VO must not merge them.
- EditBuffer.cursor is a BYTE offset (L494, L867 `e.buffer.len()`). strip_pwsh_prompts shifts by byte lengths `p.len()` (L929, L931), while the at_prompt check compares `self.pwsh_cont.chars().count()` cells (L841). Keep the mix.
- In extract (L876-885) the cursor check `if (r, c) == (cl, cc)` runs BEFORE the wide-char-spacer `continue`. Pending wrap sets cc = cols (L784-788), and that case is handled after the row loop (L902-904).
- Extract limits: `cl - start < 100` / `cl - top < 100` (L807, L834). The final trim is `keep = e.buffer.trim_end().len().max(e.cursor)` (L914). strip_pwsh_prompts runs before that trim and only when shell == Pwsh (L910-912).
- Suggestion test (L762-772): pwsh with a reported colour requires `cell.flags.contains(*f)` (ALL of its flags; an empty set always matches). Without a reported colour, `intersects(DIM|ITALIC)` (ANY). Zsh/fish without a reported colour, and bash, mean no suggestion.
- cell_col (L250): `Color::Named(n) => (n as usize).try_into().ok().filter(|i| *i < 16)`, so Foreground/Background/Dim* named colours map to None, which equals the 'default'/'normal' token (`Some(None)`, L214-216).
- parse_color: the fish flag disables decimal parsing (L226-230) and makes '#' optional (L233). parse_fish skips the token after -b/--background (L193-194). parse_zsh/parse_fish return None when nothing was parsed (L185, L199).
- parse_sgr splits on `[';', ':', '[', 'm']` and silently drops unparsable tokens (L951-952). `38;5;n` with n>255 still consumes 3 parameters with no colour set (L959). 0 resets colour and flags (L968). It returns None unless fg, bg or flags were set (L987).
- Splitter: a non-697 OSC is re-emitted byte-exact with its own terminator, BEL or ST (L146-148). Payloads are decoded with `from_utf8_lossy` (L142). An OSC overflow (L86-88) emits its prefix as bytes and the rest flows as plain bytes. A window-name overflow (L106-111) emits a WindowName chunk and STAYS in the Name state.
- Splitter ESC handling: OscEsc + another byte abandons the OSC and re-processes the ESC (L92-97). NameEsc + another byte ends the name WITHOUT the ESC, then re-processes it (L117-122). CAN/SUB are pushed into the name before it ends (L100-103). A trailing lone ESC is held in state across chunks.
- The Processor must be one long-lived instance per model (L546, L581). Escape sequences split across batches and the startup CUP (pty.rs:437) go through it. `advance` calls stop_sync after every chunk (L608-610) so synchronized updates never lag the model.
- OutFilter carry order in hold_utf8: `tail.append(&mut self.carry); self.carry = tail;` (L461-463) puts the UTF-8 tail BEFORE an escape carry set at L385. lf_to_ind checks `data[i - 1] != b'\r'` against the carry-prefixed data only, so a CR from the previous batch does not count (L400).
- OutFilter alt state (L414-421) is tracked separately from the model's TermMode::ALT_SCREEN, which pty uses for alt() (pty.rs:729). `ESC c` resets alt and partial_region (L389-392). DECSTBM is applied only when `top < bottom` (L428).
- Strip list outside the alt screen (L436-442): `?9001h/l`, `?u` with an empty rest, `=|>|<…u` when numeric, `>…m` when numeric. Anything else passes (`\x1b[u`, `\x1b[>c`, `\x1b[?2004h` are kept).
- `defer: cfg!(windows)` (L553). Every test constructor overrides it (tracker setup L1054, pty.rs:1790). If MarkerTracker::new takes `defer` as a parameter, the production call (pty.rs:419) must pass cfg!(windows) exactly, or the Windows CI behaviour changes.
- pty passes `Shell::from_name(program)` (an Option) to the tracker, NOT the fallback shell (pty.rs:414-419). The tracker must keep None for unknown programs (no colour-based suggestion detection).
- pty drains events after the WHOLE batch (pty.rs:750-753), in emission order (PreExec before NewCmd within one batch). Don't dispatch events at their marker offset.
- Tests build the model with `Config::default()` (L1057), while production uses scrolling_history 2000 (pty.rs:405-411). extract_prompt_scrolled_by_output depends on scrollback existing.

## Plan gaps
- Plan §4 says MarkerTracker takes 'cursor column in' (Phase 9.1). But pre_exec needs a full edit-buffer scrape (L713), taken AFTER flush_deferred's tags are applied (L712), mid-batch. A cursor column is not enough. MarkerTracker needs a scrape callback (std-only closure) or a two-step protocol (flush → apply commands → scrape → pre_exec).
- Tracker::feed (L587-603) has no home in the plan. It holds the splitter loop, the Bytes/WindowName/Marker routing, and the 'flush deferred when the batch had zero markers' rule. It must be placed (ProcessShellOutputUseCase or AlacrittyTerminalScreen) before tracker.rs is deleted in 9.2, because pty.rs still calls it until 9.5-9.7.
- Ordering problem: Phase 9.2 deletes tracker.rs, but pty.rs (deleted in 9.7) still uses Tracker's feed, extract, at_prompt, preexec, submitted, pwsh_list_view, shell, cwd and filter. Either an interim composite in pty.rs or a shim is needed between 9.2 and 9.7 (allowed within a phase, but the plan does not say so).
- parse_sgr (L949-988) and the pwsh_color field (L536) are not placed. They use alacritty Flags, which the domain cannot import, so a domain dim/italic type plus a mapping in edit_buffer_extractor is needed.
- SuggestionColor::matches(&Cell) (L202) mixes the domain VO with alacritty. The split (domain matches(Col, Col) + adapter cell_col) is not described.
- The suggestion_colors test is not placed. The plan counts 7 splitter + 4 filter + 26 marker/extract = 37, but the file has 38 #[test]s. suggestion_colors also has to be split between domain and adapter.
- No glossary type or port method exists for the MarkerTracker state that extract needs (open cycle n, shell, line_col0, pwsh_list_view, pwsh_cont, pwsh_prompt_text, zsh/fish/pwsh colours). The TerminalScreen port's `edit_buffer` method needs that input.
- The TerminalScreen port (§4) lacks a 'model-only advance', needed for the startup CPR CUP (pty.rs:437) and for the test extract_wrapped_long_command's model-only resize. It also lacks a 'terminal-only pass-through' for WindowName pieces; 'pass_through bytes → stdout bytes' alone cannot express the routing at L590-594.
- The tag URIs TAG_PROMPT/'tabsmith:c{n}' (SPEC D3) are not placed. The domain (ScreenCommand) and two adapters (cell_tagger, edit_buffer_extractor) all need them.
- The domain can't call types::now_secs (L701, L743): it is I/O, and the Clock port lives in shared/application, which the domain must not import. The plan does not say MarkerTracker takes the time as a parameter.
- Phase 3 makes HistoryEntry an entity with private fields (no serde). tracker.rs builds it with a struct literal and `..Default::default()` (L737-745), mutates `h.exit_code`/`h.end_time` (L700-701), and its tests read h.command/exit_code/pid/shell/session_id. tracker.rs and its tests must switch to the new API in Phase 3, which the plan does not list. ShellEvent's PartialEq also needs HistoryEntry: PartialEq.
- The 26 marker/extract tests are about 820 lines (L1217-2033), so §1's >500-line rule sends them to a sibling tests.rs. From there they cannot read the private fields t.pending (L1925), t.deferred (L2020), osc_lock, cycle, preexec, no_history, pwsh_list_view and submitted. They need #[cfg(test)] accessors. The plan does not name the destination file.
- `defer: cfg!(windows)` (L553) is a platform decision inside the future domain entity. The plan's platform_windows split does not mention it.
- pty tests write `s.tracker.submitted` / `s.tracker.pwsh_list_view` directly (pty.rs:2227, 2331, 2344). The Phase 9.5 use-case tests need setters, or must arrange the state with markers (PwshListView=1). Arranging with markers is a different setup, so check that it stays pure restructuring.
- Trap for Phase 8: the plan's dropdown `color_parser ← parse_color/xterm256` has the same name as tracker's parse_color (L209), but the grammar differs. rgb_to_256 is mathematically equal to render::xterm256 and could be deduped only with an equivalence check. The plan says nothing either way.
- Phase 11 updates SPEC §4.1, §4.3 and §10 only. SPEC §5.1's marker table (SPEC.md:679, 689) still documents `has_seen_prompt = true` and the ShellPath/TTY/User context fields that Phase 9.2 deletes.
