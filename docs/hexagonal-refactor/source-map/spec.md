# Source map: src/spec.rs (at af1b304)

## Behaviour traps
- reindex precedence (223): `for (persistent, list) in [(true, &self.persistent), (false, &self.options)]`. Options are inserted last, so they win a name collision. Within one list the later entry wins (219, 226). Reordering, or switching to entry().or_insert, flips lookups. Test 736 covers only options over persistent and 733 only subcommands; later-wins inside the options list is untested.
- reindex never dedupes the Vecs. A fully shadowed subcommand stays in `subcommands` (test 734 expects len 2). Do not filter shadowed entries in a constructor.
- Rc identity is behaviour. Rc::new is called at 304 (subcommands), 332/334 (options), 372 (args), 275/467 (Inline). Callers key on addresses: engine.rs:105-106 `hash2(Rc::as_ptr(arg) as usize, idx)`, engine.rs:500-502 arg_key (fuzzy reset), engine.rs:611 `Rc::ptr_eq(a, b)` (slot reuse), suggest.rs:692 dedupe `Rc::ptr_eq(x, y)`, parser.rs:218-221 by_json, and parser.rs:1271 `(*st.completion).clone()`, which is a shallow clone that keeps child Rc's. Keep Vec<Rc<_>> and derive(Clone). No by-value children, no Arc, no deep clone in constructors.
- The arg-level template generator is inserted at index 0 (379: `generators.insert(0, generator(&serde_json::json!({ "template": template })))`). The index feeds gen_key(arg, i) (engine.rs:649), so appending it changes GeneratorKeys and row order.
- Because the template generator goes through generator() (379), it gets the path defaults trigger Str("/") and getQueryTerm Str("/") only for filepaths/folders (414, 438, 444). history/help templates get None. A typed constructor must apply the same rule.
- Trigger and getQueryTerm fall back asymmetrically. An explicit but unrecognised trigger (`null`, a number, `{on:"x"}`) gives None and suppresses the path default, because `None if path_template` (438) fires only when the key is absent. An invalid or absent getQueryTerm falls back through `.or_else(|| path_template.then(..))` (444). Treating null as absent changes results.
- Trigger precedence (428-429): a string is checked before $fn, and "" becomes Trigger::Str("") (not None).
- Numeric casts saturate or truncate, and must not become checked conversions. isRepeatable `n.as_f64().unwrap_or(1.0) as u32` (357): -1→Times(0), 2.7→Times(2); suggest.rs:225 treats Times(0) like No. threshold `as usize` (433). ttl `as u64` (446). scriptTimeout `.map(|ms| ms as u64)` (454): negative→Some(0). debounce (391-395): `true`→200, `n.as_f64().filter(|&ms| ms > 0.0).map(|ms| ms as u64)`, so 0.5→Some(0); false/string/null→None.
- fn_id (517) `v.get("$fn").and_then(Value::as_u64).map(|n| n as FnId)`: floats like 1.0, negatives and strings are not functions; values above u32::MAX truncate. As a result, an object script `{"$fn":"x"}` becomes Script::Object (420).
- b() (512) `as_bool().unwrap_or(false)`: only JSON true counts, so `"hidden": 1` → false. parser.rs:495 truthy uses JS truthiness. Do not unify them.
- items() (488-495) wraps any non-null scalar, falsy ones included. parser.rs:482 make_array drops falsy values. So `{"name": ""}` → names [""] and Some(Suggestion) (248 only checks is_empty), and json!("") → Some(names [""]) (241). Deduping items with make_array changes this.
- strs() (501-505) silently drops non-string elements: `script: ["git", 5]` → Argv(["git"]), and `name: ["a", 1]` → ["a"].
- optionArgSeparators (323-327): a string becomes a set of chars, so `""` gives an EMPTY vec, not ["="]. An array goes through strs and may be empty. Anything else, null included, gives ["="]. A parserDirectives value that is not an object leaves has_directives false (317). The whole Directives struct is replaced, not merged, so missing flags become false.
- Directives::default (155-162) has `option_arg_separators: vec!["=".into()]`, and Subcommand's derived Default relies on it (test 555). Never switch Directives to derive(Default).
- requiresSeparator (361-365): a string, even "", gives Some(x); true gives Some(""), meaning use the first separator; false and others give None. isRepeatable (353-359): an absent key gives No and an explicit false gives Times(1). These differ (tests 629, 635).
- load_spec (461-471) and load_spec_result (269-278) differ on purpose. Static string → Global; function-result string → None (test 789). Static object with {name,type} → Inline subcommand; result → Location. Static array → None; result array → Locations, with invalid entries dropped, possibly empty. Static checks $fn; the result does not, so a returned `{"$fn":n}` becomes an Inline empty subcommand. A result object that has a `type` key, even null or invalid, gives `Locations([])` (273: `o.contains_key("type")`).
- location() (286): `PathBuf::from(s(v, "path").unwrap_or_else(|| "~/".into()))`. A missing or non-string path gives a literal "~/", which parser.rs:325 expands. `path: ""` gives an empty PathBuf, not "~/", whatever the JS `||` comment says.
- Script mapping (416-423): an empty array gives Argv([]), which engine.rs:163 script_exec_input turns into None → Done([]). number/bool/null → None. An object without $fn becomes Object(raw clone). At runtime engine.rs:166-170 builds `{cwd}` and then `m.extend(o)`, so the object's own cwd wins. The cache key is `input.to_string()` (engine.rs:856): the full merged JSON with unknown keys, in BTreeMap order since serde_json has no preserve_order. timeout is read with as_u64 and then overwritten (859-861). A deserialize error becomes `Outcome::Fail(format!("bad script input: {e}"))` at run time, and the debug log reads 'engine: generator failed: …' (engine.rs:721).
- suggestion_from_json (256-259): an unknown `type` string gives Some(ItemType::Arg) (types.rs:70 `_ => ItemType::Arg`), while a non-string type gives None, so the caller defaults it (suggest.rs:163). "mixin" maps to Special. The reverse, fig_type (suggest.rs:1345), is lossy. priority accepts ints via as_f64. Only context.templateType is read.
- Two JSON→suggestion paths exist and use this function differently. engine.rs:188-196 json_items (custom and filterTemplateSuggestions results): strings become bare suggestions with kind None. engine.rs:198-213 post_process_items: strings become script_string (Arg, insert_value, is_dangerous), empty strings are dropped, and objects need a truthy name. A typed SpecFunctionResult must keep the mapping per call kind.
- normalise error text (235) `anyhow::ensure!(v.is_object(), "spec is not an object")` reaches logs through parser.rs:260 `no(format!("{name}: {e}"))` and the generateSpec warn (parser.rs:1252, then `logger::warn(&format!("generateSpec ({}): {e:?}", ...))`). SpecError's Display must print exactly the same text. Only the top level is checked; malformed nested parts are skipped silently.
- Persistent split (330-336): an isPersistent option lives ONLY in `persistent`, and the bool in opt_index says which Vec to use (tests 583, 631). parser/tests.rs:63-66 `oarg` ignores that bool and always indexes `options`. Moving the helper to a 'correct' accessor would change what those tests read.
- subcommand(): objects() drops non-object entries ("junk" in test 726). A single object counts as a one-element list (test 728, `"args": {...}`).
- Derives: Suggestion, Arg, Opt, Generator, Subcommand and LoadSpec have no PartialEq. parser.rs:258 compares raw JSON (`*old == j`) to keep Rc identity. Do not replace that with typed equality (f64 priority, Rc pointers).
- Rc is !Send. The spec model lives only on the engine thread, so do not switch to Arc to satisfy a cross-thread port signature.
- sub_index and opt_index are HashMaps. Only look them up, never iterate them for output, because the order is random.

## Plan gaps
- Phase 5.1 'GeneratorScript::Object(Value) becomes a typed ExecRequest' changes behaviour. Malformed objects (missing or non-string command, non-string args) are accepted at normalise time today and fail at run time with 'bad script input: <serde msg>' in the debug log. Typing them up front means dropping them or failing the whole spec. It also changes the cache key (engine.rs:856 serialises the merged JSON, unknown keys included), and the cwd override order (`m.extend(o)`) has to be reproduced. Script::Fn results go through the same JSON→exec conversion at runtime (engine.rs:773-781), so that conversion has to live in the runtime adapter anyway. A behaviour-preserving option the plan omits: hold the object as opaque canonical JSON text in the domain (`x.to_string()`) and parse it in the adapter at run time.
- The plan's 'domain struct fields private' rule has no API for current mutation and construction. parser.rs:1270-1288 clones a Subcommand, reassigns subcommands/options/persistent/args and calls reindex(). parser.rs:1205-1214 reads has_directives/directives/persistent/args. Production builds Suggestion literals (engine.rs:180, suggest.rs:1300, 1335). suggest.rs tests build Subcommand/Opt/Arg/CacheCfg literals with ..Default::default() and never reindex (1491, 1497-1505, 1752-1793, 1806-1830, 1850, 2377-2381, 2543). Needed: a merge method (e.g. Subcommand::merged_with_generated) plus test builders. A builder that auto-reindexes is safe for the suggest tests, since assemble never reads sub_index/opt_index (only parser.rs:720, 756 do).
- SuggestionKind (from types::ItemType) is placed in the specs domain, but render.rs:604 `describe` (which goes to terminal_session overlay_renderer) and pty.rs tests (1772+) use ItemType. The §2 graph does not allow terminal_session → specs. Either add that edge or place SuggestionKind in completion/shared. Phase 5.1 also never says ItemType leaves types.rs; only from_fig is mentioned.
- SpecFunctionRef: the plan does not say whether it is a newtype or stays `type FnId = u32`. A newtype forces test edits (bare ints at 567, 618, 619, 654, 670, 682, 714, 741) and changes to the parser/tests.rs Mock HashMap<FnId, _> key (82) and the js.rs fn-table indexing (413, 516). The `as_u64` plus `as u32` rule must survive.
- The glossary has SpecLocation replace loc_key as identity. loc_key (parser.rs:203-208) uses the `dir.display()` string, while PathBuf Eq/Hash normalise components ("/p/" == "/p", "a/./b" == "a/b"). Deriving Hash and keying the spec and by_json caches on SpecLocation would merge entries that are separate today.
- normalise returns anyhow::Result (234), and the plan allows anyhow only in cli/pty/bootstrap. The plan's SpecError(Aborted, Timeout, NotFound, Invalid) does not fix the Display text, which must stay exactly 'spec is not an object' because it reaches the logs through the parser.
- Phase 6 completion code (CommandLineParser, generator use cases) calls normalise (generateSpec result), load_spec_result (loadSpec fn result), fn_id (versioned default detection, parser.rs:250, 291, 354) and suggestion_from_json (engine.rs:194, 209). All of these live in specs::infrastructure, and rule 3 bars completion from importing it. The plan relies on typed SpecFunctionResult (5.3), but its list must keep custom/filterTemplateSuggestions (json_items) separate from postProcess (post_process_items) and from the script/loadSpec/generateSpec mappings. The plan does not spell this out.
- DRY risk the plan does not address: fig_spec_mapper's items/strs/b and fig_version_diff's parser make_array/names/truthy both end up in specs adapters, and their semantics differ (falsy scalars kept vs dropped; strict bool vs JS truthy). They must not be merged.
- reindex moves to the domain entity, but its only tests stay in the mapper (normalise_shapes_and_collisions). That is acceptable as a verbatim move. If reindex becomes construction-time (in Subcommand::new), parser.rs:1288 still needs a way to re-index after the merge.
- Phase 5.5 deletes spec.rs, and shims never cross phases. So in Phase 5 the legacy importers must switch to the new paths directly: engine.rs (14, 194, 209), js.rs (12, test 1121), parser.rs (6-8, 250, 291, 354, 1188, 1288), parser/tests.rs (through super::*), suggest.rs (6, test 1455) and main.rs `mod spec;` (20). Moving fig_type from suggest.rs in 5.1 means touching a Phase 6 file early.
