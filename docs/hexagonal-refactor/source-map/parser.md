# Source map: src/parser.rs (+ src/parser/tests.rs) @ af1b304 (at af1b304)

## Behaviour traps
- Two different bin/console rules. spec_location L163: `None if name == "bin/console" || name.ends_with("/bin/console")` → php/bin-console. The single-token path L985-989 uses only `if last.text == "bin/console" { "php/bin-console" } else { "dotslash" }`, so a lone `vendor/bin/console` gives dotslash while `vendor/bin/console x` gives php/bin-console. Merging them into one SpecLocator rule changes behaviour.
- spec_location L169: an isCommand token is Global unless it starts with "/", "./" or "~/" (`!['/', './', '~/'].iter().any(|p| path.starts_with(p))`), so `../x` stays Global (and resolve_in rejects it later). First token L168 is Global only when there is no '/' at all, so `@withfig/autocomplete-tools` as a first token is Local. isScript L170 is always Local, and `script` → cwd.join("").
- SpecLocation.dir stays a PathBuf. L178 `cwd.join(...)` keeps the trailing slash ('/cwd/dir/'). Test equality is component-wise because Path eq ignores the trailing slash, but loc_key L206 `dir.display()` keeps it in the cache-key string. Turning dir into a String changes both.
- '~/' is not expanded at location time (L175-176, PathBuf::from("~/")). It is expanded only in spec_file L325-326 via settings::user_home(), which reads USERPROFILE (windows) or HOME. If user_home fails, `ok()?` returns None and the location is cached as missing (L244-246).
- disableForCommands L232-238 runs on EVERY load, including nested loadSpec, isCommand/isScript/isModule targets and the dotslash/php single-token load. It compares against the location's `name` (the base name for Local). It runs before the cache, returns Ok(None) and caches nothing, and parse_prefix L1040-1045 then falls through to the NEXT location.
- Dev-mode asymmetry. Loader skips cache reads but still writes: `self.specs.get(&key).filter(|_| !dev)` L241, insert L267; versions L282 vs L287. The prefix cache neither reads nor writes in dev (L1034, L1140). The generateSpec cache key is dropped in dev (`.filter(|_| !dev)` L1245). by_json identity is still used in dev (L257).
- Errors are not cached; only a missing file is. A load_module error L248, an error from versioned, or a normalise error L260 propagates without `self.specs.insert`. A missing file L245 and a non-object default L254 are cached as None.
- Match-arm order L249-254: `Some(v) if crate::spec::fn_id(v).is_some()` must come before `Some(v) if v.is_object()`, because {"$fn":n} is itself an object.
- Rc identity: `self.by_json.get(&key).filter(|(old, _)| *old == j)` L257 reuses the Rc when the JSON is equal. clear_caches L121-127 clears only loader.specs plus prefix/generated. It keeps versions, inflight, by_json and `first`. The engine's arg key (engine.rs `Rc::as_ptr(&pr.completion)`) depends on this.
- versioned: an unknown version is passed as JSON null (`version.map_or(Value::Null, Value::String)` L293). A result without versionedSpecPath gives `Ok(Some(r).filter(Value::is_object))` L296. The diff file is the sibling `<last segment>.js` (L299-300). The diff target is the RESULT's `version` field (L309), not the detected CLI version. Error text is '{file}: invalid versioned spec file' (L311-314).
- cli_version: `if name == "@usermn/sdc" { return Ok(None) }` L349 is hard-coded. inflight is keyed by name and `or_insert_with` L355 reuses a running task even if `f` changed. On Aborted L367-368 it returns WITHOUT remove/forget, so the task survives. On Ok (even a timeout with the task still pending) it does remove + forget (L370-371). A getVersionCommand result is used raw (`v.as_str()` L376, not cleaned), while exec output goes through `semver_clean(stdout)` L377-380, so 'git version 2.39.0' gives None. The exec command is the location name (the base name for a Local spec), run in the generator's cwd/env.
- Only successful detections are memoised (L286-288), so a failed probe runs again on every uncached load.
- apply_versions L388-398 applies EVERY diff whose key is ≤ target, cumulatively, in semver order (`base = merge_subcommand(&base, &diffs[k])`). It does not pick only the newest. An unparsable target applies all diffs (`target.filter(|t| semver(t).is_some())` L392), and so does None. sort_by is stable, so equal keys keep serde_json Map order (BTreeMap, preserve_order is off in Cargo.toml). Unparsable keys sort as 0.0.0 (L539-543).
- merge_named L445 drops a matched item on `d.get("remove").is_none()`, i.e. when ANY remove key is present, even false or null. An unmatched diff item that has remove is pushed as-is (L442). merge_args L465 instead uses `truthy(d.get("remove"))`, indexes AFTER filtering, and drops base args beyond the diff length (L467-469). merge_subcommand L405 shallow-merges first, so a falsy diff.subcommands (null) overwrites the base, while `[]` is truthy and keeps the base.
- semver L509 `trim().trim_start_matches(['=', 'v'])` strips any run of '='/'v' characters. Build metadata is cut first, and the first '-' starts the prerelease. Main parts reject leading zeros; prerelease numeric parts do not. u64 overflow gives None. In semver_cmp L551-552 numeric<alphanumeric comes from Result<u64,String> ordering (Ok<Err), and the shorter prerelease is smaller. semver_clean drops the build part.
- update order L733-746: subcommand → option_or_chain → option_arg (only when prefer_opt_arg) → subcommand_arg, evaluated lazily. can_subcommands L697 ignores end_of_options, so after `--` a token can still be parsed as a subcommand; only suggest_* are suppressed (result L938-939).
- subcommand fin=true L760-762 only annotates ('siblings stay suggestable'). Non-final: `if child.has_directives { s.directives = child.directives.clone() }` replaces the whole object, persistent is APPENDED (parent first), passed is cleared, and opt_args are reset.
- find_option L720-727: only `Some(&(false, i))` hits the level's own options. Persistent options (the own level's too) are found through st.persistent with the first match winning, so the parent wins a name clash.
- option L777-786: Repeat::Times(n) counts passed options sharing ANY name. Repeat::No and Unlimited are not limited. fin=true only annotates; opt_args and passed stay unchanged.
- option_or_chain: a final '-' or '--' returns None (L818). A non-final '--' sets end_of_options (L821-827). A non-final '-' takes the POSIX branch with an empty loop and becomes a zero-part composite of kind Option, i.e. it is consumed. The non-POSIX branch L838 also handles tokens that do not start with '-'. Separators match single chars only (`s.len() == c.len_utf8() && s.starts_with(c)` L844), at the first matching char. `option(st, flag, false)` L847 runs with fin=false even for the final token, so passed includes --opt for a final `--opt=al`. An option with more than one arg rejects inline values (L848, L892). No arg slot gives None and the token falls back to a positional (L851). requiresEquals/requiresSeparator reset opt_args (L862-864).
- POSIX chain: passed is snapshotted BEFORE each flag (L873). An unknown or over-repeated letter at i>1 turns the rest into the value (L876-878). Only mandatory or variadic args consume the rest (L886). parts are '-a' and then bare letters (L884). For a final token, `cur.passed = passed` L900 keeps the letter being typed suggestable, but once a value was consumed passed = cur.passed (L896). The truncate in composite L829 removes annotations pushed by the inner calls.
- result L912-929: a composite always uses opt_args for current_arg. When the last part is OptionArg: only_args=true and raw = `raw_last_token.strip_prefix(flag).unwrap_or(t)`, so a quoted raw falls back to the unquoted text. Otherwise option_chain=Some(text), which includes a lone '-m' because the chain branch always builds parts. tokens.last is replaced by last_text (L931-934). suggest_args is always true.
- parse L978 errors with 'no tokens' on an empty buffer. A single token without '/' L981-984 uses the shared `self.first` Rc, spec_name "" and first_token=true, and loads nothing. An unconsumable FINAL token gets an AnnKind::None annotation (L1002-1006). An unconsumable NON-final token errors with `cannot consume {token:?}` (L1078), which puts the typed text in the engine's debug log.
- Prefix-cache key L1026-1033: built from the ORIGINAL (pre-alias) token texts minus the last, joined with ' ' (ambiguous when a token contains a space), then ',' + loc_key + ',' + cwd.display(). Lookup checks every location in order before any load (L1035). The first location that loads Some wins, and a load ERROR propagates immediately without trying the next one (`host.load(loc)?` L1041). Depth limit is `depth > MAX_DEPTH`, so 65 levels (L1022). The cache is cleared wholesale when len >= 1000 before insert, even if the key exists (L1141-1144). Nested returns (L1056, L1131) skip caching at this level. The nested call caches under its own key with its own tokens, and the caller adds index and prepends the prefix (L1198-1202).
- generateSpec runs at the TOP of every loop iteration while the level has generate_spec (L1061-1065): on the iteration that then breaks for the final token, and again for each arg consumed at the same level, because the merged clone keeps generate_spec. Its tokens are cur.tokens[start..] including the partial final token (the test expects ["cmd","generateSpec",""]).
- Alias L1081-1098 applies only when the token was consumed as the predicted arg kind (last_type == last_kind) and its text is not yet in `substituted`. On success it re-parses the same i (continue, no i+=1, substituted not cleared). On failure: with nothing substituted yet, or on Aborted, it returns Err at once. After an earlier substitution the error is deferred (alias_err): a nested loadSpec can still win (L1119-1132), otherwise it returns Err (L1133-1135). The value is trim_end()-ed (L1168). Messages: 'alias did not return a string' and 'invalid alias for {token:?}'.
- loadSpec precedence L1099-1118: for a Subcommand it is the child's load_spec. For an arg (only when last_type == last_kind): arg.load_spec, else isCommand/isScript → spec_location(token, cwd, Some(is_script)), else isModule → Global{prefix+token}. Function-loadSpec errors propagate (`host.call(...)?` L1189, not swallowed). Function loadSpec at the root is skipped (L1191), but root Inline/Locations are applied, and root Locations re-parse from the SAME start. load_spec_result for a non-array/object gives None. An empty Locations vec errors with 'failed loading spec for {token}'.
- Inline loadSpec L1205-1216 REPLACES st.persistent (inherited persistent options are dropped), unlike subcommand(), which extends it. It replaces the last path entry (set_completion) instead of pushing. It resets entered_sub_args, passed and opt_args, keeps end_of_options, and replaces directives only if has_directives.
- generate_spec: the cache-key fn is called with ONE arg `json!({"tokens": tokens})` and no Exec (L1236-1239). A non-Aborted error or a non-string result gives no key, and it still generates. The key is `format!("{}:{k}", tokens[0])`, i.e. the command token, not the spec name. The generate call is [Json(tokens), Exec]. Aborted propagates. Other errors log `crate::logger::warn(&format!("generateSpec ({}): {e:?}", tokens[0]))` with ParseError's Debug, e.g. `NoSuggestions("spec is not an object")`, and return the state unchanged.
- generate_spec merge L1274-1295: a base item is dropped only if ALL its names are shadowed. Generated items are appended after the kept ones. args are replaced only if the level has none (and sub_args is reset then). reindex() follows. `st.persistent = generator.persistent ++ st.persistent`, so generated options win, the opposite of the parent-first order. A NEW Rc is created on every uncached parse, so the arg key changes unless the state comes from the prefix cache.
- ArgState::advance L609-621: a variadic arg stays put and counts. Advancing past the last arg gives ArgState::default() (args dropped). can_options L707-715 is asymmetric: a variadic option arg can be broken unless `!= Some(false)`, while a variadic positional blocks only on `== Some(false)`.
- The generator context for every parser JS call comes from gen_ctx L193-200: cwd, env and shell only, with search_term "" and is_dangerous false. An empty env becomes the wrapper process env when the JSON is built (js.rs context_json). Unifying with engine::gen_context_json must not inject the request's search term into these calls.

## Plan gaps
- Phase 6.3 'Move the disableForCommands rule into CompletionRequestPolicy' changes behaviour. Today (L232-238) it applies to every location load: nested loadSpec, isCommand/isScript/isModule, dotslash/php/bin-console. It matches the Local base name, and a disabled location returns 'not found', so parse_prefix tries the next location. A request-level policy on the first token cannot reproduce that. It has to stay a per-location filter in or around the SpecRepository.
- Section 4 says 'spec_version_selector ← version pick (newest ≤ target)', but apply_versions L388-398 cumulatively applies ALL diffs ≤ target in semver order. Unparsable or None target applies all, ties keep BTreeMap string order, and unparsable keys count as 0.0.0. A selector returning one 'newest' version breaks version_pick ('8.10.0' must also carry 8.2.0's subcommands). Section 4 also lists apply_versions under fig_version_diff, which contradicts this.
- SpecRepository is `find(&SpecLocation) -> Result<Rc<Subcommand>, SpecError>`, which does not carry what a load needs: (a) per-request context: settings (disableForCommands, developerMode, devCompletionsFolder), SpecIndex, and the GeneratorContext cwd/env/shell for the version probe and the versioned default() call; (b) a cache invalidation that matches clear_caches (specs map only, keeping by_json/versions/inflight); (c) the Ok(None) vs Err split. With NotFound as an Err variant, parse_prefix must treat NotFound as 'try the next location' and every other error as 'propagate now' (L1041). Disabled must map to NotFound.
- Not placed by the plan: the Parser facade, Parser::clear_caches (needs to be split between the spec repository and ParsePrefixCache, keeping `first`), ParseCtx, JsHost (only 5.4 mentions it), TIMEOUT (used by both the repository and the parser callbacks), dev_mode, gen_ctx, no(), From<JsError>, MAX_CACHED, MAX_DEPTH, and the generic generate_spec merge<T>.
- The logging rule conflicts. generate_spec L1266 calls crate::logger::warn inside what becomes the application service CommandLineParser. Lifting it into a returned warning must keep the exact text and Debug format, and must still emit the warning when the parse later fails (e.g. generateSpec fails, then a later token cannot be consumed). Today the warn is always logged.
- The application cannot use serde_json (architecture rule 2), but generate_spec, substitute_alias and apply_load_spec build `json!` args and read Value results (as_str, normalise, load_spec_result). Typed SpecFunctionCall variants must keep the argument shapes: GenerateSpecCacheKey{tokens} with NO exec, GenerateSpec{tokens}+exec, LoadSpec{token}+exec, Alias{token}+exec. Typed results must keep: non-string cache key → no caching; non-string alias → error 'alias did not return a string'; non-array/object loadSpec → None; normalise failure of the generated spec → warn and leave the state unchanged (not an abort).
- QuickJsSpecRepository (← Loader) needs untyped JSON: module exports as Map<String,Value>, default() results as Value, diff merging on Value, and by_json equality on Value. The typed SpecRuntime port does not give that. Either the repository adapter uses QuickJsSpecRuntime concretely, or the port keeps a JSON-level call. The plan does not say which.
- The plan deletes Host, so substitution now goes straight to command_line_tokenizer::substitute_token, and CommandLineParser needs the Shell (from ParseCtx.shell today). git_alias_directive switches from the Mock's whitespace splice to the real tokenizer. The texts match for its buffers, but this changes how the test is arranged.
- The plan's spec_locator combines parser::spec_location with the 'bin/console, dotslash rules', but the single-token rule (L985-989: exact 'bin/console', else dotslash, only when the text contains '/') differs from spec_location's ends_with('/bin/console') rule (L163). They must stay two separate rules.
- Phase 5.2 says to split spec_location_table into a pure domain part and an fs adapter part, but that test is already pure, so there is nothing to split. Only specs.rs resolve_order touches the filesystem.
- The glossary has no name for argv State/ArgState. command_line_parser mutates State fields directly: tokens L1139, command_index L1198, tokens L1202, directives/persistent/opt_args/passed/sub_args/entered_sub_args L1208-1215, sub_args/persistent L1286-1295. With private domain fields, argv_parser needs intention-revealing mutators: apply_inline_spec, merge_generated_spec, prefix_tokens.
- Making ParsedCommandLine and TokenAnnotation fields private breaks suggest.rs (ParseResult struct literal in tests at suggest.rs:1459, field reads in assemble/static_options/help_items) and engine.rs (7 fields read). That needs constructors and accessors, which the plan does not mention.
- The Phase 5.4 guard test spec_identity_survives_dev_reload_and_cache_clear spans both the specs repository and the completion cache (it reads `p.caches.first`), and it calls Parser::load_spec, which Phase 11 deletes. It must be split, with one half keeping the name, before 6.7 deletes parser.rs.
- The guard test cli_version_detection_survives_an_aborted_parse needs types::EngineMsg::Complete(Request) on the Js channel. Once EngineMessage moves to bootstrap (6.6), the test in specs infrastructure needs a RuntimeEventSource double with a pending newer request, and it needs that double in 5.3/5.4 already.
- Many tests assert exact load sequences or counts (single_token_paths, relative_path_first_token_loads_local_spec, prefix_cache, cached_nested_state_keeps_this_commands_prefix, recursive_load_spec, is_command_recursion, load_spec_and_is_module, exceptions_and_first_token). So InMemorySpecRepository must record every find and must not cache. The plan only says '+ InMemory'.
- Expanding '~' in Local spec dirs (spec_file L325-326) reads HOME/USERPROFILE through settings::user_home. DataDirectory covers tabsmith's home, not the user's home, so the plan's 'paths from env only in data_directory_from_env' rule needs a separate user-home source for this adapter.
- loc_key's format ('global,,{name}' / 'local,{dir.display()},{name}') is shared by the specs repository cache and the completion prefix-cache key (L1030). It has to live on the SpecLocation VO, verbatim, or the two will drift.
