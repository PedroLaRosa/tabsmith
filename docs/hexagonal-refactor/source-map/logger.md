# Source map: src/logger.rs (at af1b304)

## Behaviour traps
- L5-12 + L85/L90: the filter `level <= l.level` relies on the derived Ord of variant order `Error = 1, Warn, Info, Debug, Trace`. Reordering or inserting variants changes which records pass.
- L97: `format!("{ms} {level:?} {} {msg}\n", l.session)`. Debug names `Error|Warn|Info|Debug|Trace` are the SPEC §3.1 on-disk format `<unix ms> <Level> <sid|-> <msg>`. Renaming a variant (e.g. Warning) or switching to Display/uppercase silently changes pty.log/cli.log, and no test covers this.
- L36-45: `0 => env TABSMITH_LOG_LEVEL ... unwrap_or(Level::Warn), 1 => Level::Warn, 2 => Info, 3 => Debug, _ => Trace`. The env var is read ONLY when verbose == 0. A single -v gives Warn, the same as the default, but it ignores the env: `TABSMITH_LOG_LEVEL=trace tabsmith -v` logs at Warn.
- L24 `s.to_ascii_lowercase()`: matching is case-insensitive with no trim ('debug ' -> Warn). Unknown values, 'off' and non-UTF-8 all give Warn. There is no off level, so Error is always recorded.
- L53 `stderr: stderr && verbose > 0`, with the caller passing `!is_pty` (main.rs:104-108, `matches!(cli.command, Some(Command::Internal(InternalCmd::Pty { .. })))`). The env level alone never mirrors to stderr, and `_ pty` never does. Moving the `verbose > 0` check or the is_pty detection (when InternalCmd moves to bootstrap/cli.rs) could print log lines over the user's shell, and `_ pre-cmd` runs on every prompt.
- L49 `std::env::var("TABSMITH_SESSION_ID").unwrap_or_else(|_| "-".into())`: raw and unvalidated, read once. An empty value stays "", which gives a double space in the line. Non-UTF-8 gives "-". In `_ pty` the session's own sid is generated later (pty.rs:413) and only set on the child (pty.rs:472), so pty.log carries the parent env's sid or "-". Do not validate it through terminal_session::SessionId and do not swap in the generated sid.
- L50 `let _ = LOGGER.set(...)`: the first init wins silently. Tests never call init, so every log call is a no-op there (L85/L89 `LOGGER.get()`). Do not switch to get_or_init or lazy defaults, or `cargo test` starts appending to the real ~/.tabsmith/logs.
- L46-48: `settings::home().ok().and_then(|home| open_log(&home.join("logs"), name))`. A home error (HOME unset or empty; empty TABSMITH_HOME ignored) means no file, but the stderr mirror still works. TABSMITH_SETTINGS_PATH does not affect logs. The data_directory_from_env replacement must keep settings.rs:8-17 precedence exactly: TABSMITH_HOME if non-empty, else USERPROFILE on windows or HOME, falling back to HOME, then filter empty.
- L63 `if !dir.parent().is_some_and(|p| p.is_dir()) { return None; }` and L66 `let _ = std::fs::create_dir(dir);` (not create_dir_all, error ignored). This purge guard checks the DATA ROOT, not logs/. It differs from write_private (integrations.rs:516-520), which returns Err on NotFound, so unifying with AtomicFile changes behaviour.
- L72 chmods the dir to 0700 on every open, even when it already existed, and it follows symlinks. L73 `opts.mode(0o600)` affects only newly created files, so L79 `file.set_permissions(0o600)` is what fixes pre-existing ones. All permission errors are ignored.
- L69-80: two separate `#[cfg(unix)]` blocks, each with its own `use std::os::unix::fs::...`. Hoisting those uses to the top of the file without a cfg breaks the Windows build. Windows does no chmod at all.
- L98-102: an unbuffered `std::fs::File` in append mode, with one `write_all` of the fully formatted line. With O_APPEND, records stay whole across concurrent processes: several `_ pty` sessions share pty.log, and background `_ pre-cmd` jobs share cli.log. `writeln!(f, ...)` (several writes) or a BufWriter would interleave records or lose them at `std::process::exit` (main.rs:139/143), because the OnceLock never drops.
- L99 `if let Ok(mut f) = f.lock()`: a poisoned mutex silently drops the record. L104 `eprint!` runs after the guard is dropped. Keep it outside the lock, because the pty panic hook (pty.rs:46) re-enters `logger::error`.
- L90 returns early before the timestamp is taken. Callers format eagerly (`format!` at every site), and `enabled()` is never used. Do not add a closure/lazy API.
- L93-96 SystemTime `as_millis()` (u128), with 0 before the epoch. Do not route it through the Clock port or `types::now_ms`: shared cannot import crate::types, and Clock is not global.
- Messages are not escaped. Panic records from pty.rs:46 `format!("panic: {info}")` contain a newline (Rust's panic Display), and `debug logs` (cli.rs:886-890) tails the last 50 LINES. Do not sanitize.
- main.rs:141-142: `logger::error(&format!("{err:#}"))` runs BEFORE `cli::print_error(&err)`. With -v the error appears twice on stderr, log line first. Keep both, in that order, in bootstrap.
- main.rs:103-108: init runs after `Cli::parse()` (clap errors are never logged) and before dispatch. `Settings::load`'s warn (settings.rs:105) and the pty panic hook rely on init having run first.
- Log texts reach users through pty.log and -v stderr, but no test asserts them: engine.rs:495 'engine: no suggestions: {e}', engine.rs:721 'engine: generator failed: {e}', and parser.rs:1266 `{e:?}` with its privacy rule 'spec name only: logs never hold typed text'. Moving these sites must keep the text, the level and the format spec (`{e:#}` / `{e}` / `{e:?}`).
- Global `OnceLock<Logger>` + `Mutex<File>` is called from the engine thread (engine.rs:48-57), the LLM worker (engine.rs:1199) and js threads (js.rs:268/608). Do not turn it into an `Rc<dyn Logger>` port.

## Plan gaps
- SharedKernel rule (plan §1 rule 4; HEAD architecture_tests.rs:145-147 `["crate", module, ..] if *module != "shared"`): logger.rs:46 `crate::settings::home()` fails once shared is registered, which is Phase 1's done criterion. Phase 1.4 says 'each later phase switches its own callers', but the logger must switch to `data_directory_from_env` (or receive the logs dir from main.rs) INSIDE Phase 1, and that function must mirror settings::home() exactly.
- ModuleBoundary rule 3 (HEAD architecture_tests.rs:134-142, `["crate", module, "infrastructure", ..] => *module != own_module`) has no exemption for `shared`. Every registered module whose adapter logs through `crate::shared::infrastructure::logger::*` will be flagged: settings.rs:105 (Phase 2), inline.rs:30/83/115 (history, Phase 3), integrations.rs:325 (Phase 4), js.rs:268/608 (Phase 5), and so on. Plan §1 ('never import another module's ... infrastructure') does not carve out the shared kernel's infra. The same applies to atomic_file, json_document_store, terminal_style and os/*.
- Plan §1 says 'Only infrastructure logs; domain/application return errors or warnings', and fitness rules 1-2 forbid `logger`/`::infrastructure`. But log calls sit in code the plan sends to domain or application: parser.rs:1266 warn (argv parser goes to completion domain), engine.rs:495/721 debug (completion use cases), and engine.rs:311 error (SpecIndex load in Engine::new). The plan defines no warning-return type or channel for them. Converting them must keep text, level, format spec and record order.
- Phase 11 names only `logger::trace` for dead-code deletion. `logger::enabled` (L84-86) has zero callers at af1b304, so it will also be flagged once main.rs:3 `#![allow(dead_code)]` is removed. Deleting it is fine, but it is unlisted.
- Phase 1.3 says temp_dir.rs 'replaces the 5 ad-hoc helpers', but af1b304 has 8 ad-hoc `std::env::temp_dir()` test sites: cli.rs:915, doctor.rs:819, engine.rs:1210, inline.rs:635, integrations.rs:1297, logger.rs:130, settings.rs:399, suggest.rs:2461. The plan does not say whether logger's test is in scope. A verbatim move is the safe default.
- The log path is known in three places. logger.rs:48 `home.join("logs")` plus L75 `format!("{name}.log")`; cli.rs:882-884 debug_logs (`dir.join("pty.log")`, `"cli.log"`), which goes to diagnostics file_log_reader / debug_logs_command in Phase 10; and doctor.rs:217, which hard-codes '~/.tabsmith/logs/pty.log'. The glossary's DataDirectory covers 'logs', but the plan's DataDirectory joins do not name it. If a `logs()` join is added, the purge guard must still test the data root (the parent of logs/).
- The 'cli'/'pty' file name and the stderr flag come from main.rs:104-108 matching `Command::Internal(InternalCmd::Pty { .. })`. The plan keeps init in main.rs but moves Cli/Command/InternalCmd to bootstrap/cli.rs (Phase 1.1) and the Pty args to terminal_session pty_command (Phase 9). It does not say how main.rs keeps the is_pty decision, e.g. a bootstrap helper, and that decision must keep `_ pty` with no stderr mirror.
- Plan §6 maps logger.rs only to `shared/infrastructure/logger.rs`, and nothing says the 26 call sites in 8 files (engine, inline, integrations, js, main, parser, pty, settings) must be rewritten in Phase 1. The 'shims never cross phases' rule forces that rewrite, or `src/logger.rs` survives as a re-export shim into Phase 2 or later, which the plan forbids.
