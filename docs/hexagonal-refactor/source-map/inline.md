# Source map: src/inline.rs (at af1b304)

## Behaviour traps
- History file line format: `serde_json::to_string(&entry).unwrap_or_default() + "\n"` (L71). HistoryRecord must keep field order command, shell, pid, session_id, cwd, start_time, end_time, exit_code, hostname (types.rs L211-221), and must write None as `null` (no skip_serializing_if), so lines stay byte-identical.
- History parse is strict per line: `filter_map(|l| serde_json::from_str(l).ok())` (L42). HistoryEntry has no #[serde(default)], so a line missing a non-Option field (command, shell, session_id, start_time) is dropped. Adding #[serde(default)] to HistoryRecord would start loading lines that are skipped today. Unknown fields are ignored.
- `std::fs::read_to_string(&path).unwrap_or_default()` (L38). Any read error, including one invalid UTF-8 byte anywhere in the file, gives an empty history with lines=0. Per-line lossy decoding would change this.
- `lines` counts every raw line, corrupt and blank ones too (L39). Compaction keeps the last 5000 RAW lines, corrupt ones included (L106-107), while memory keeps the last 5000 PARSED entries (L44). The two can differ. Compaction is `> 10_000`, so it starts at 10 001 lines (L50, L90).
- Compaction rewrites with `text.lines()` + `join("\n") + "\n"` (L106-109), which turns CRLF into LF. The temp file is `path.with_extension(format!("tmp-{}", pid))` → `history.tmp-<pid>`, and `std::fs::rename(&tmp, path)` (L110) REPLACES a symlinked history.jsonl with a regular file. settings::Store::save canonicalizes first (settings.rs L79) and keeps symlinks. Routing compaction through the planned shared AtomicFile ('keeps symlinks', create_dir_all) would change this.
- open_private (L121-135) sets mode 0o600 only when the file is CREATED. An existing 0644 history.jsonl stays 0644 across appends and is only 0600 after a compaction. Do not add set_permissions on append.
- Purge guard: `let purged = path.parent().is_some_and(|p| !p.is_dir());` (L73). When the data dir is gone the write is skipped, the parent is never recreated, `lines` is not incremented (`Ok(()) if purged => {}` L80), and the entry is STILL pushed to memory (L87). A write error logs `history: appending to {path}: {e}` and also still pushes to memory.
- Blank skip uses `entry.command.trim().is_empty()` (L67), Unicode trim, before any file I/O. Engine CommandFinished calls append directly (engine.rs L396-398). If RecordCommandUseCase owns the check, the adapter must not let blanks through any other path.
- History::load does not create ~/.tabsmith. If home() fails it logs `history: {e:#}` (the anyhow context text from settings.rs L15) and runs memory-only (L29-32). SharedDependencies must not abort when DataDirectory is unresolvable. That memory-only fallback is a production path for InMemoryHistoryRepository.
- The engine's history is a load-time snapshot plus this process's own appends. Other sessions' appends are invisible until restart. A JsonlHistoryRepository::recent that re-reads the file would change ghost text, history rows and LLM context. It is also read per keystroke (engine.rs L1121).
- history_ghost: `e.command.len() > buffer.len() && e.command.starts_with(buffer)` (L251-252) is strict, byte-wise and case-sensitive. The newest entry with `exit_code == Some(0)` wins, then the newest of any kind, including exit None (L253, L256-257). No privacy filter here: private commands do ghost from history. Only the LLM path filters.
- spec_ghost: `strip_suffix(' ')` removes ONE trailing space (L265), so the ghost of 'a  ' is 'a ' (test L965-966). `cursor_back <= text.len() - stripped.len()` (L269) allows cursor_back 1 only when a space was stripped. It checks `i.kind`, not `original_kind`. `find_map` takes the FIRST qualifying item in ranked order.
- Local ghost dispatch (engine.rs L1123-1126): Specs → specs only; History AND Profile(_) → history only; HistoryAndSpecs AND Err(_) → `history().or_else(specs)`. An invalid or missing profile falls back to history+specs locally, while engine.rs L1175 sends `Ghost{text: None}` for anything but Ok(Profile). An exhaustive match on Result<GhostTextSource, _> must keep the Err arm's fallback.
- Ghost is computed inside engine::reply for BOTH Parse and Generators phases (engine.rs L1085) and for error replies only when the `ghost` flag is set, with items=None (L564-565). Gate: `inline.enabled` (default true), non-empty buffer, `cursor != req.buffer.len()` using the engine's cursor (L1115-1118).
- GhostCache.insert gives priority by index WITHIN one call: `if i == 0 { 0.0 } else { 1.0 }` (L291). The engine always inserts a 1-element slice (engine.rs L1194), so every entry is 0.0. lookup uses `min_by(total_cmp)` (L302), which returns the FIRST (oldest) minimum: the oldest matching completion wins, not the newest. No dedupe. The cap `drain(..len.saturating_sub(50))` runs after the loop (L294). Strict `full.len() > buffer.len()` (L301).
- GhostCache concurrency: the cache is cleared on CommandFinished/CommandEnded on the engine thread (engine.rs L399-401). A worker started before the clear can insert afterwards (L1193-1195), so a stale completion survives into the next command. Poisoned mutex → `.lock().ok()` treats it as a silent miss or skip. A cache hit replies synchronously with no thread (L1179-1185). Thread spawn failure logs `engine: llm worker: {e}` and sends NO Ghost reply (L1198-1200).
- llm_history: `rev().filter(usable).take(count)` then reverse (L310-317). usable = `exit_code.is_some() && !is_private` (L394). count = `settings.i64("inline.historyCount", 49).max(0) as usize` (engine.rs L155). i64 getter: a float 2.0 → default 49.
- is_private: `s.to_lowercase()` (Unicode) then substring match on PRIVATE_WORDS (L388-391), including the trailing space in "bearer " and the colon in "authorization:". It is applied to the buffer (L400) and to every history line (L405).
- history_prompt cost: `c.len() + 8` per line, total `sum - 1` (no trailing newline) (L410-411). Oldest lines are dropped until `total <= 10_240`. `if skip + 1 == lines.len() { return None }` (L414): the buffer alone being too long means no request. Numbering restarts at 1 after the drop, as `format!("{:>5}  {c}", i + 1)` (L423). It assumes at most 5 digits, which holds only because memory history is capped at 5000.
- User message: `"OS: {}\nShell: {}\nCWD: {}\n\n{prompt}"` with `std::env::consts::OS`, `shell.name()` and `cwd.display()` (L332-337). A private or too-long buffer returns None BEFORE any HTTP and without logging (L331 `?`).
- API key precedence (L338-343): the session env map value wins when non-empty (`.filter(|k| !k.is_empty())`). Otherwise the PROCESS env `std::env::var` is read on the worker thread per request (an empty process value is accepted as ""). An empty key means no auth header (L438, L449), but `anthropic-version` is always sent. The env map is engine.env(): session env if non-empty, else the wrapper env (engine.rs L437-443).
- HTTP: a NEW ureq Agent per request with `timeout_global(Some(Duration::from_secs(5)))` (L345-348). Headers are added in order. ureq 3 treats non-2xx as Err by default. Only send/read_json errors log, as `inline: profile '{name}' request to {url} failed: {e}` (L359-362). parse_response None, clean None and validate false are SILENT. A Result-returning use case whose driver logs every error would add log lines.
- build_request: `base_url.trim_end_matches('/')` strips ALL trailing slashes (L434). OpenAI URL `{base}/chat/completions` with header ("authorization", "Bearer {key}"). effort is ignored for OpenAI. Anthropic URL `{base}/v1/messages` (default base has no /v1, OpenAI's default does) with headers x-api-key then ("anthropic-version","2026-10-21") (L452). `output_config: {effort}` is added whenever effort is Some, including Some("") (L459-461). No temperature/top_p/top_k.
- parse_response: OpenAI reads `choices[0].message.content` as_str, so null content (refusal) gives None and finish_reason is not checked (L470-472). Anthropic: `stop_reason == "refusal"` → None. Non-array content → None. All `type == "text"` blocks are CONCATENATED and thinking blocks ignored. Empty content array → Some(""), which clean then turns into None (L474-483).
- clean: `text.lines()` (L491) also strips a trailing \r, so a CRLF reply is accepted. Splitting on '\n' would leave \r, which the control check rejects. The unquoted path keeps the UNTRIMMED line (`.unwrap_or(line)` L503), so leading spaces survive (" status"). The quote path uses the trimmed text, with quotes tried in order ` " ' and the inner text not containing the quote. A history number is stripped only when digits are followed by exactly two spaces (`strip_prefix("  ").unwrap_or(s)` L508), otherwise s is unchanged. The buffer prefix is stripped once, then trim_end only, then any `char::is_control` (C0, \t, DEL, C1) rejects the whole completion (L515). The order is fixed: quotes → number → buffer → trim_end → control.
- parse_profile check order is user-visible through `inline show-customizations`: reserved name (L200) → not a JSON object (L203) → provider type/value/missing → model type, then empty → "missing model" (L219-221) → max_tokens → base_url type → api_key_env type → effort type. The struct literal evaluates `s("base_url")?` after max_tokens is computed (L226-240). Exact strings: "'{name}' is a reserved source name", "not a JSON object", "{k} must be a string", "unknown provider '{p}' (expected openai or anthropic)", "missing provider", "missing model", "max_tokens must be a positive integer".
- parse_profile values: JSON null counts as absent for every string field and for max_tokens (L205, L227). base_url "" and api_key_env "" are KEPT, not defaulted (unwrap_or_else only on None). max_tokens uses `as_u64()` + `1..=u32::MAX` (L229-230): 32.0, 1e3, -1 and 0 are rejected. Defaults: openai (https://api.openai.com/v1, OPENAI_API_KEY, 64), anthropic (https://api.anthropic.com, ANTHROPIC_API_KEY, 1024). These defaults show up in show-customizations JSON (cli.rs L591).
- profiles(): `with_prefix("inline.profiles.")` over a FLAT dotted-key map (settings.rs L147-154). A key `inline.profiles.a.b` becomes a profile named "a.b", and the bare key `inline.profiles.` becomes a profile named "". Sorted with byte-order `a.0.cmp(&b.0)` (L179). A tree-shaped settings model would change both.
- source(): `settings.string("inline.source").unwrap_or("history+specs")` (L185). A non-string value counts as unset → HistoryAndSpecs. Error texts are "profile '{name}' not found" / "profile '{name}' is invalid: {e}". Today no caller displays them: doctor uses `Err(_)` and prints its own message (doctor.rs L574-577).
- validate: an open quote (split_words None) passes. Anything but exactly 2 words with the first == "cd" passes (`cd`, `cd a b`, `cd space in name`). expand None (unknown $VAR, unclosed `${`, no home) passes. An absolute non-dir fails (L533). Otherwise `cwd.join(path).canonicalize().is_ok_and(|p| p.is_dir())` (L536), so `cd -`, `cd ~user` and relative non-existent paths FAIL. Keep both fs calls exactly.
- split_words: `let escapes = !cfg!(windows)` is decided at compile time, not from the Shell (L541). Inside double quotes a backslash escapes only `" \\ $ \``, otherwise the backslash is kept (L564-566). `''` and a trailing lone `\\` create an EMPTY word through get_or_insert_default (L549, L573). Splitting uses Unicode `is_whitespace`. Do not dedupe with completion's command_line_tokenizer.
- expand: only `~`, `~/` (and `~\\` on Windows) expand. Home comes from env map HOME, then USERPROFILE, then settings::user_home() (process env, USERPROFILE before HOME on Windows) (L586-594). `$` followed by a non-identifier keeps a literal '$'. `${}` stays literal. Variables come ONLY from the passed env map. Do not dedupe with completion's path_template::shell_expand.
- Only failures of the HTTP/JSON read get the inline warn. The history warns use the prefix `history:`. The logger is a global (logger.rs L111). These messages are log-file output and should be kept verbatim.

## Plan gaps
- Phase 2 forces part of Phase 7 early. Phase 2.5 deletes settings.rs and gives Settings::get a SettingValue instead of serde Value. inline.rs's parse_profile(&Value)/profiles()/source() (L174-242) and the profiles_and_source test (Settings::from_map(json!)) must be rewritten in Phase 2, and the legacy inline.rs is not deleted until Phase 7. The plan only mentions 'LlmProfile from SettingValue' under Phase 7.
- SettingValue number model. The plan's canonical example is `SettingValue::Number(10.0)` (f64). parse_profile relies on `as_u64()`, which REJECTS 32.0/1e3 (L229-230), and engine/pty rely on `as_i64` (historyCount, debounceMs). An f64-only SettingValue would start accepting `"max_tokens": 32.0`, which is a behaviour change visible in show-customizations. SettingValue needs to keep integer and float apart, and Null as well (L205, L227 treat null as absent).
- open_private (L121-135) and the compaction temp+rename are not placed. Section 4 says shared AtomicFile unifies Store::save / write_private / write ('temp+rename, 0600/0700, keeps symlinks, purge guard'). Using it for history compaction would keep symlinks (today they are replaced, L110) and might create_dir_all (settings.rs L77). Keep both private in jsonl_history_repository.rs.
- HistoryRepository 'trait {append, recent} + InMemory (← History::from_entries)' puts InMemory under #[cfg(test)] by the section-1 rule. But production uses from_entries as the fallback when home() fails (L31), so InMemoryHistoryRepository must be a production type that keeps the 5000 cap on append (L88-89). How `recent` limits results is unspecified. It must return exactly the in-memory ≤5000 window from load time plus this process's appends, and must not re-read the file.
- The blank-command skip is planned for RecordCommandUseCase (section 4, Phase 3.3). The moved adapter test history_file_round_trip_and_compaction asserts that `append("   ")` is skipped at the adapter (L1072, L1080). Either the adapter keeps the trim check or that single assertion moves to the use-case test. Removing it from the adapter without moving it changes behaviour for any caller that bypasses the use case (engine.rs L397 calls append directly until Phase 6).
- Phase 7.1 says 'the five services with their 11 pure tests'. Section 4 lists SIX services (history_ghost_text, spec_ghost_text, llm_prompt_builder, llm_completion_cleaner, cd_target_validator, ghost_text_source_resolver). inline.rs has 8 service tests, one of them cd_validation, which is NOT pure (real fs). Add 2 GhostTextCache tests and the 2 GhostText tests from pty.rs and the count is 12, not 11. Counting tests will not match the plan.
- cd_target_validator 'dir probe injected' covers is_dir/canonicalize but not expand's home fallback `crate::settings::user_home()` (L591), which reads the process env. Domain code cannot read env, so the fallback home (or a ShellEnvironment-like port) must be injected too. The plan also does not say whether the probe keeps the two distinct calls (`path.is_dir()` for absolute paths and `cwd.join(path).canonicalize().is_ok_and(is_dir)`). Collapsing them into one is_dir call could differ on symlinked or Windows paths.
- cd_validation cannot move verbatim into a domain file. It needs a real fs probe. Importing the FsDirectoryProbe adapter from a domain test violates architecture rule 1, because architecture_tests.rs scans lines and does not skip #[cfg(test)]. The test has to sit at adapter level, or define its own std::fs probe.
- The json! helper in profiles_and_source cannot stay in a domain file (rule 1 forbids serde_json even in test modules). It must be rebuilt with SettingValue literals.
- llm_complete reads the API key from the process env (`std::env::var`, L342), builds the ureq agent and logs. The plan assigns 'request_llm_ghost_text ← engine::llm + llm_complete pipeline' to application and 'openai/anthropic_llm_client ← build_request/parse_response + ureq' to infrastructure. It does not place: (a) the key lookup (session env map first, then process env), (b) which component picks the OpenAI or Anthropic client by LlmProvider (a single LlmClient port with two adapters needs a dispatcher, or one adapter matching on provider), (c) the exact warn text, which includes `{url}`, so the adapter must log it rather than the driver.
- engine::llm_history wrapper (engine.rs L152-157) and its test llm_history_honours_history_count (engine.rs L1257-1280) are not placed. engine.rs is deleted in Phase 6 while ghost_text arrives in Phase 7. They belong with RequestLlmGhostTextUseCase or a settings-to-count step in it. The same holds for engine::ghost (L1114-1128), engine::llm (L1173-1201) and the Arc<Mutex<GhostCache>> field: Phase 6.6 only says the engine server 'calls the legacy inline.rs', so this glue lives in bootstrap/engine_server.rs for one phase.
- The event table maps only `Complete(request)` to `CompleteCommandLine → SuggestLocalGhostText`. Today ghost is recomputed for EVERY reply, including Generators-phase replies from ProgressGenerators (engine.rs L1085, where generator items can change spec_ghost), and for error replies with items=None when the flag is set (L564-565). Following the table literally would leave the ghost stale or missing on generator follow-ups.
- GhostTextCache crosses threads: the engine thread looks it up and clears it, the worker thread inserts. Section 1 says in-process aggregates are owned by the driver and passed as &mut. The plan does not say that ClearGhostTextCacheUseCase and RequestLlmGhostTextUseCase share an Arc<Mutex<GhostTextCache>>, or how poisoned-lock silence (`.lock().ok()`) is kept.
- Cross-module dependency direction. suggest.rs test empty_search_term_is_no_prefix_match (suggest.rs L1627-1645) calls crate::inline::spec_ghost. In Phase 6 it lands in completion services, but the module map allows ghost_text → completion and not the reverse. It must move to ghost_text/domain/services/spec_ghost_text.rs tests, which may use completion's filter/to_item. The plan does not mention it.

- GhostTextError: the plan wants one error enum per module, but parse_profile/source return String, and those strings are printed verbatim by render_sources. The Display impl must reproduce them exactly, including the nested "profile '{name}' is invalid: {e}". Tests comparing `unwrap_err() == "..."` need `.to_string()`.
- PROFILES_PREFIX (L171) and the test helper item() (L926-949) are not placed. item() should become a builder in completion/domain/test_fixtures.rs, because Item/Insertion fields may go private in Phase 6.
