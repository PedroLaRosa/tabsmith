# Source map: src/doctor.rs (at af1b304)

## Behaviour traps
- Lazy group construction: `r.group(.., dotfile_checks(..)) && r.group(.., setup_checks(&ctx)) && r.group(.., env_checks(..))` (183-192). env_checks, including `Settings::load()` (479), `var("TABSMITH_SESSION_ID")` (480) and the session_kind input (519), only runs after the setup group passed, so after its fixes (for example the settings reset). A SystemFacts snapshot taken up front changes when files are read, adds process spawns (pwsh, bash/fish --version, sw_vers, cmd /C ver) that an aborted run never does today, and moves the corrupt-settings `logger::warn` (settings.rs Settings::load).
- The re-run after a fix calls the same lazy closure again (`let again = self.outcome(c);` 136), so it reads live state again (ctx.data.is_dir(), Store::load, specs_index.is_file(), is_installed, script_bins). A facts-based catalog must probe again after each fix, or a successful fix still reports Err and aborts.
- Skip checks are never evaluated: `checks.iter().filter(|c| c.kind != Kind::Skip)` (115). The test's 'skipped' check panics if run. Checks after an abort never run ('after' panics).
- A Soft error becomes Warn before the fix logic: `Outcome::Err { reason, .. } if c.kind == Kind::Soft && !self.strict => Outcome::Warn(reason)` (95). Its info and fix are dropped, so Soft dotfile checks are never auto-fixed without --strict, and with --strict they are fixed.
- Print order without --all: the spinner is dropped (`self.spinner = None` 118, which clears the stderr line) right before the first non-Ok print. The fix path prints exactly `Attempting to fix automatically...`, then either `Failed to fix: {e:#}` + blank line, or `Re-running check...` + blank line + the re-run outcome, printed even when it is Ok (`✔ name`). An abort prints a blank line and does errors += 1 directly (145-147), not through count(). A failed re-run drops its fix: no second attempt.
- --all: the header is `paint("2", header)` only with --all (113), with a blank line after each group (149-151). There is never a fix or an abort, and the spinner is never started (181).
- print_outcome prints Warn as `● {m}` WITHOUT the check name (70), while Ok is `✔ {name}` and Err is `✘ {name}: {reason}`, plus a blank line and `  {l}` per info line only when info is not empty (73-78).
- System group results are ignored: `let (e, w) = (r.errors, r.warnings); r.group(..); (r.errors, r.warnings) = (e, w);` (195-200). It still prints, and a Normal Err there (fish < 3.3.0) aborts the rest of the group, then `✔ Everything looks good!` is printed. With --strict, the Soft bash check stays Err and aborts, so the Fish check never runs.
- Exit code: `failed = r.errors > 0 || (args.strict && r.warnings > 0)` → `Ok(i32::from(failed))` (204, 241). Root without --all returns Ok(1) before Ctx::from_env (157-171). Root with --all only prints the bold-red stderr line and continues. Root lines use epaint (stderr tty check), everything else is stdout.
- Hard-coded hint `  tabsmith still not working? Check ~/.tabsmith/logs/pty.log` (217), even with TABSMITH_HOME. Do not 'fix' it through DataDirectory. `✔ Everything looks good!` is printed only without --all (213-215).
- Restart reminder (220-240): read even when the run failed. Only `as_bool() == Some(true)` counts. It prints two lines, then INSERTS false (does not remove the key) and calls Store::save, rewriting the whole state.json (recency keys kept, pretty, sorted, 0600) and ignoring errors. A corrupt state.json is silently skipped. Fixes in the same run call mark_restart, so the PS lines appear in that same run.
- Dotfile severity (256-262): the current shell (from the PARENT exe only, 174-175) is Normal even when it is not on PATH. Other shells are Soft if `which` finds them, else no check at all (no pwsh spawn). Shell::ALL order is Bash, Zsh, Fish, Pwsh. session_kind falls back to TABSMITH_SHELL (557) but dotfile_checks does not, so do not unify the two into one 'current shell' fact.
- An integrations() error produces one check named `{shell} integration check` whose reason is `format!("{e:#}")` of the anyhow chain (266), e.g. `could not ask pwsh for $PROFILE: timed out after 5s`. A typed error must render the same chain.
- Dotfile check name is `{shell} {short_path} integration check`. short_path uses `rel.display()` after `~/` (247), so on Windows the separators are mixed (`~/Documents\PowerShell\...`). The reason strips the prefix for NotInstalled/Improper (`m.clone()`, 298) and uses the full Display otherwise (`File does not exist: …`, `Permission denied: …`, `{path}: {io}`). PermissionDenied gets no fix (301-307).
- The info line contains an inline styled span: `Run {paint("35", "tabsmith integrations install dotfiles {shell}")} to reinstall shell integrations for {shell}` (290-296). Moving it to domain data loses the magenta span unless the reporter rebuilds it byte for byte.
- Both integration fixes call integrations::mark_restart() UNCONDITIONALLY after a successful install (311, 393), even when install_dotfiles returns Ok(false). integrations_cmd only marks the restart when something was installed. The stale-binary fix is `install_dotfiles(ctx, &shells)` (install-if-not-installed, with backups), NOT `integrations reinstall` (uninstall then install, integrations.rs:1072-1075).
- script_bins (325-354) overrides the profile with `pwsh_profile: Some(ctx.pwsh_profile.clone().unwrap_or_default())`, an empty PathBuf, so it never spawns pwsh a second time. It still checks pwsh script files when $PROFILE lookup failed earlier. It covers only shells on PATH (332), unlike dotfile_checks. `integrations(..).unwrap_or_default()` swallows errors. Missing files are skipped (`.ok()?`). The bin is the raw text between the first two `'` (`.split('\'').nth(1)`, with a ponytail comment at 345); fish-escaped `\\` and pwsh `''` are not unescaped. `shells.dedup()` (390) only removes consecutive duplicates, so it relies on files being grouped by shell in Shell::ALL order. The reason uses the FIRST stale bin: `Integration scripts reference {old}`.
- Settings-corruption predicate is `Store::load(&settings_path).is_ok()` (404). Missing or whitespace-only files are OK. Invalid JSON, non-object JSON, and ANY non-NotFound read error (EACCES, EISDIR) count as corrupted. settings_path honours TABSMITH_SETTINGS_PATH (359).
- The settings fix (408-415) copies to `path.with_extension(format!("json.bak-{}", now_secs()))`, which REPLACES the extension (`settings.conf` → `settings.json.bak-N`, no extension → `x.json.bak-N`). It then writes `{}\n` with std::fs::write: not atomic, follows symlinks, keeps the existing file mode. A repository save through AtomicFile (temp+rename, 0600) would differ.
- The data-dir fix is plain `std::fs::create_dir_all(&ctx.data)` (371), using the default umask with no 0700. Its reason is `No directory at path {}`.
- The specs check tests `ctx.data/specs/<specs::version()>/index.json` (360-364), but the fix `specs::ensure_extracted()` resolves its root from `settings::home()` (specs.rs:28), not from ctx.data. Without the embed-specs feature the fix fails with `no specs in … (built without the `embed-specs` feature)`.
- Fix errors print as `Failed to fix: {e:#}` (132), the anyhow alternate chain. install_dotfiles errors start with `\n\n` (`bail!("\n\n{}", errs.join("\n\n"))`, integrations.rs:1007) and contain `paint("1", describe)`. io errors print as `… (os error N)`. A CheckFixer port must hand back this exact string.
- Terminal-integrations rule ORDER and messages (491-515): Warp, then cmd (parent basename eq_ignore_ascii_case `cmd.exe`/`cmd`), then INSIDE_EMACS (present, even if empty), then SecureCRT, then PROCESS_LAUNCHED_BY_TABSMITH (present), then CI (present, even `CI=` empty), then TABSMITH_TERM == env!("CARGO_PKG_VERSION"). Unset gives `tabsmith is not running in this terminal…`. Any other value, including empty, gives an Err with info `TABSMITH_TERM={v}`. `var` is std::env::var(..).ok(), so a non-UTF-8 value counts as unset. `has` uses var_os (presence). All of these are Normal with no fix, so the env group aborts.
- Session check: severity is Normal only if TABSMITH_SESSION_ID is set (Some("") counts) AND the shell resolved from parent, else TABSMITH_SHELL, is not Pwsh (554-563). The outcome only checks `ctx.data/run/{sid}.json` is_file, giving Ok or a Warn, never Err.
- Inline: inline_kind is Soft when disabled (481-485), but the outcome is then always Warn(`Inline is disabled, to re-enable run: tabsmith inline enable`), so Soft is dead there. Keep it anyway. On a source() error the message is `Inline source '{settings.string("inline.source").unwrap_or("")}' is not a valid profile` and the resolver's own message is discarded (574-577). The API key counts only from the env (var_os, non-empty, 547); llm_complete also reads env from a map (inline.rs:338-342) but doctor does not. is_local is a substring check for `://localhost`, `://127.0.0.1`, `://[::1]` anywhere in the URL (586-588).
- Settings getters with explicit defaults: `bool("inline.enabled", true)`, `bool("autocomplete.disable", false)`, `bool("autocomplete.developerMode", false)`. A wrong type falls back to the default (settings.rs:119-121). The catalog defaults match today (settings.rs:182-184, 296-298, 319).
- Version parsing (592-599): the first token split on non-[0-9.] that contains '.' and starts with a digit. Empty parts are dropped (`3.` → [3]). One u32 overflow makes the whole result None. A failed spawn, a timeout or a version without a dot gives None, and the check is Ok (632, 648, 666).
- Version comparisons are LEXICOGRAPHIC slice comparisons: bash `v.as_slice() < [4, 4]` (632), so [4] is unsupported. Fish `< [3, 3, 0]` (649), so `fish, version 3.3` → [3,3] is 'outdated'. A semver-style compare that pads zeros changes the result. Bash message: `Bash {v[0]}.{v.get(1).unwrap_or(&0)} is not supported (needs >= 4.4 for PS0); install a newer bash or switch to zsh`. Fish shows the found version joined with '.'.
- The bash version probe runs the PARENT exe path when current == Bash (616-620), not `bash` from PATH.
- OS rules: an old macOS (<11 via `sw_vers -productVersion`) and an unknown OS are Warn, not Err (667-683). Windows build < 17763 is Err in the setup group (464, Normal, aborts) but Warn in the system group (679). `windows_build` is called twice.
- Windows Console check (436-459): stdin AND stdout must both be consoles, so `tabsmith doctor > file` on Windows fails the setup group. The info lines contain an empty string, which prints as two spaces (`  {l}`).
- Spinner: only without --all and only when stderr is a tty (695-698). Frames `⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏` with `\x1b[?25l\r{frame} Running checks...` every 80 ms. Drop sets the stop flag, JOINS the thread, then prints `\r\x1b[2K\x1b[?25h`. It is dropped again at 202 before the summary.
- The SIGINT handler is installed once per Spinner::start and never removed (729-737). A Ctrl-C at any later point, including during fixes, prints `\x1b[?25h` and calls exit(1), not the default 130. The Windows handler likewise exits 1.
- Ordering in run(): is_root, then Ctx::from_env()?, then parent_exe(). If bootstrap builds SharedDependencies/DataDirectory before dispatch, a missing HOME would error before the root message, and the error text would change from `could not determine the home directory` (user_home, which Ctx::from_env calls first).

## Plan gaps
- §4 diagnostics says 'launch rules reuse shell_integration::LaunchPolicy instead of duplicating them'. Doctor's terminal check (491-515) is NOT launch_decision (integrations.rs:412-445): the order differs (doctor: Warp > cmd > Emacs > SecureCRT > PROCESS_LAUNCHED > CI > TABSMITH_TERM; launch: FORCE > DISABLED > PROCESS_LAUNCHED > TABSMITH_TERM > Emacs > Warp > SecureCRT > __PWSH_LOGIN_CHECKED > CI > VSCODE > TERM > stdin). The messages differ. The cmd.exe rule exists only in doctor. TABSMITH_TERM is a version-equality check in doctor but a presence check in launch. Example: TABSMITH_TERM + INSIDE_EMACS gives 'Emacs is not supported' in doctor but 'already inside tabsmith' in launch. Following the plan literally changes output.
- CheckFix::ReinstallIntegrations (glossary) suggests ReinstallIntegrationsUseCase (uninstall + install, integrations.rs:1072-1075). The legacy fix is install_dotfiles (install-if-not-installed) + an unconditional mark_restart (391-394). Name or bridge it as an install, or behaviour changes (uninstall removes traces and makes different backups).
- The CheckFixer bridge row says 'settings repository reset'. SettingsRepository {load, save, last_modified} has no backup-copy step. The legacy fix copies to `with_extension("json.bak-<secs>")` and then does a non-atomic fs::write of `{}\n` that keeps the file mode (408-415). Saving an empty Settings through JsonFileSettingsRepository/AtomicFile would skip the backup and force 0600 with temp+rename.
- The restart reminder read/clear at the end of the run (220-240) is not placed. RestartReminder and its repository live in shell_integration, and the diagnostics ports list (system_facts_probe, doctor_reporter, check_fixer, log_reader) has no slot for them. build_diagnostics_module(&SharedDependencies) cannot receive StateRestartReminderRepository (shell_integration infrastructure) without a bootstrap-injected trait object, which the plan does not list.
- SystemFactsProbe needs integration statuses (Integration::is_installed), the integration list (pwsh $PROFILE spawn), the script-file bin paths (script_bins needs script_path and When), specs::version() (embedded_spec_bundle, specs infrastructure) and ghost_text profile resolution. os_system_facts_probe is diagnostics infrastructure, and architecture rule 3 forbids it from referencing shell_integration or specs ::infrastructure or other modules' use cases. Only CheckFixer is listed as a bootstrap bridge; a facts bridge (or extra ports) is missing.
- The plan does not say SystemFacts must be probed again after each successful fix (136) or probed lazily per group (183-192). A single up-front snapshot breaks the re-run after a fix (a fixed check stays Err and doctor aborts), and adds process spawns and the settings-load warn log that an aborted run never triggers today.
- CheckOutcome must be 'data, no closures' in the domain, but dotfile_check's info string embeds a tty-dependent styled span (paint("35", …), 290-293). The plan does not define how the domain represents a styled fragment so that terminal_doctor_reporter reproduces the bytes.
- anyhow is allowed only in infra/cli, pty and bootstrap, but the output `Failed to fix: {e:#}` depends on anyhow's alternate chain formatting (contexts from ensure_extracted, the `\n\n` prefix from install_dotfiles bail, io errors). The CheckFixer port's error type is not specified; returning a pre-rendered String from the bridge is the behaviour-preserving option.
- Interim phases are unplanned for doctor.rs. Phases 1, 2, 4, 5 and 7 delete or rename what it imports (integrations::{Ctx, Integration, IntegrationError, When, integrations, install_dotfiles, mark_restart, is_root, parent_exe, which, paint, epaint, output_with_timeout, is_console}, settings::{Settings, Store, settings_path}, specs::{version, ensure_extracted}, inline::{source, Source}, types::{Shell, now_secs}). The 'shims never cross phases' rule means doctor.rs and its test doctor_script_bins_skip_orphans (Ctx literal, install_dotfiles) must be rewired in each of those phases. Phase 4 especially: Ctx disappears, yet doctor needs is_installed, install, script_path and the Ctx field set (home, data, bin, zdotdir, fish_dir, pwsh_profile).
- Phase 2.2 adds default-equality tests only for autocomplete.height, autocomplete.width, inline.enabled, autocomplete.theme and inline.source. Doctor also passes call-site defaults for autocomplete.disable=false and autocomplete.developerMode=false (530, 540). Add them so the catalog switch cannot drift.
- Phase 1 moves os helpers to shared/infrastructure/os/process_info.rs. Doctor's `is_root()` runs BEFORE Ctx::from_env (157-173). If bootstrap builds SharedDependencies (data_directory_from_env) before dispatch, the error and exit path for a missing HOME is reached before the root message. Keep the root check before data-directory resolution for doctor.
- 'Run' name collision: the plan's completion module has `generator_run ← Run/Step/Outcome` (engine.rs) and diagnostics has `DoctorRun ← doctor::Run`. Both legacy files also have an `Outcome` type. Not a behaviour issue, but grep-based moves must target the right one.
- §1 'tests stay in the same file' versus doctor_script_bins_skip_orphans: wherever it lands (the probe adapter in diagnostics), it needs shell_integration's install to seed files. The architecture test (rule 3, text-based) would flag a #[cfg(test)] import of shell_integration::infrastructure from diagnostics. The test should either live in bootstrap/bridges.rs or write the script bytes directly, and the plan does not say which.
