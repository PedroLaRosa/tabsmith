# Source map: src/specs.rs (at af1b304)

## Behaviour traps
- L11/L15 include paths are relative to the source file; the move must rewrite them (plan §6 last row). L15 `.trim()` must stay: SPECS_VERSION is "2.692.3\n" and the trimmed value names the dir that doctor.rs:363 also joins.
- L30-33 the 'installed' test is only `dir.join("index.json").is_file()`, and the fast path still runs touch+cleanup on every call. Engine::new calls ensure_extracted twice (engine.rs:308-309 plus L139). That is harmless, but don't add a cache that skips touch: the touch at each engine start is what keeps other binaries from deleting the version.
- L37-41 the non-embed branch's exact text is "no specs in {} (built without the `embed-specs` feature)". Under embed-specs the bail is not compiled at all. The cfg gating must stay on ARCHIVE, the ensure branch, bundle_subset, full_bundle and embedded_index_shape.
- L48 `format!("{ver}.tmp-{}", std::process::id())` is coupled to cleanup's `split_once(".tmp-")` (L84). Other installed binaries also clean these names, so the format is a cross-version on-disk contract, like `.last-used` (L19).
- L49/L53/L61 anyhow contexts "creating {root}", "extracting specs into {tmp}" (the tmp path, not dir) and "renaming specs into {dir}". These are printed with {e:#}, behind "could not extract the completion specs" (integrations.rs:1205) and in the log "engine: specs: {e:#}" (engine.rs:310).
- L51-54 on unpack error the temp dir is removed and cleanup is NOT run. root itself stays created (the test at L384 expects root to exist but be empty).
- L55-57 a leftover dir without index.json is removed before the rename. L58-63 the concurrent 'loser' relies on std::fs::rename failing when the target dir exists and is non-empty, then succeeding because the winner's index.json is there. Replacing this with AtomicFile, a copy or remove-then-rename changes the race behaviour (test L322-330).
- L64-65 extract_to itself does touch+cleanup. full_bundle (L275) and all four extract tests depend on that.
- L70-71 touch ignores every error; File::create truncates; the mtime comes from SystemTime::now, not a monotonic clock.
- L84-91 'ours' means a stem of dot-separated, non-empty, all-digit parts. user, dev, notes.tmp-1 and pre-release names are kept. A single number like "5" counts as ours.
- L96 compares the FULL name `name != ver`, not the stem. So stale tmp dirs of the CURRENT version are removed (test L367-377). Switching to `stem != ver` breaks that.
- L92-94 age is the mtime of <dir>/.last-used, else of the dir. L98 uses `t.elapsed().unwrap_or_default() > max`: a future mtime counts as age 0 (kept), the comparison is strictly greater, and a metadata error keeps the dir. If ported to the Clock port, keep the future-mtime-means-zero rule.
- L79 swallows read_dir errors (`into_iter().flatten().flatten()`); L100 ignores remove_dir_all errors; L97 skips non-dirs.
- L112-116 skips any entry whose file_name starts with "._", at any depth. Only EntryType::Regular is unpacked: dirs, symlinks, hardlinks and contiguous entries are skipped. `unpack_in` returning Ok(false) (path traversal) is silently ignored. Don't change the tar::Archive options (mtime/permission preservation).
- L146-148 `completions` has no serde default: an index.json without it is a "parsing {path}" error. diffVersionedCompletions defaults to []; unknown keys are ignored. A hand-rolled Value walk that defaults completions to [] would change behaviour.
- L155-165 completions order is index.json order (duplicates kept) followed by user stems in read_dir order, each deduped against the list so far. The extension must be exactly "js" (case-sensitive), is_file follows symlinks, non-UTF-8 stems are skipped, and only top-level files count (user `foo/index.js` is resolvable but never listed). The order feeds suggest::first_token_items push order (suggest.rs:1432), so don't turn it into a set.
- L176-177 `home().ok()?` comes after dev_folder, so a missing HOME/TABSMITH_HOME returns None even when a dev folder is configured. Injecting precomputed roots would change this.
- L175-180 roots are rebuilt from the CURRENT Settings on every resolve. A settings reload that toggles developerMode or devCompletionsFolder takes effect at once; caching roots at construction would break that.
- L185-188 an empty devCompletionsFolder means None. A non-string value means None (settings.rs:123 as_str). developerMode defaults to false (the catalog default is also false). The check order doesn't matter because both are pure.
- L191-195 `strip_prefix("~")` strips a whole component only ("~user/x" stays literal). If the home lookup fails, it falls back to the literal path, not None. That differs from parser.rs:324-327 (a Local `~` gives None). A relative dev folder stays relative to the engine process cwd.
- L202-208 names are validated with Path::components, all Component::Normal, which depends on the platform: "C:foo" is a Prefix on Windows but Normal on Unix. Multi-segment names ("aws/s3") are allowed, interior "." is normalised away, and an empty name is rejected. Don't reimplement this as string splitting.
- L209-216 a diff-versioned name skips `<name>.js` in EVERY root, user and dev included. Lookup is root-major (both patterns in one root before the next). The test is is_file, not exists, so a directory named git.js doesn't match. The first root wins.
- L235-239 TmpDir names are tabsmith-test-{tag}-{pid}-{nanos}-{counter}, created eagerly and removed on Drop. Some tests assert exact directory listings of a TmpDir (L362, L377, L384), so the helper must not create anything inside it.
- L263 bundle_subset matches `path.strip_prefix(".")` exactly against the requested paths and asserts unpack_in()==true. L275 full_bundle uses version "x" and returns the ROOT (all_bundle_modules walks root, including .last-used).
- CI (ci.yml) runs `cargo test --locked --release -- --ignored all_bundle_modules`: the fn name must keep that substring wherever js.rs's test lands, and full_bundle must remain reachable from it.
- L513-515 embedded_index_shape hard-codes 1484 completions, 6 diff-versioned and heroku, all tied to assets/specs.tar.zst.

## Plan gaps
- The plan does not place testutil::bundle_subset or full_bundle (L255-277). They cannot go to shared/testing (they need ARCHIVE and extract_to, and shared must not import specs), yet js.rs tests (L1257, L1312, L1787) depend on them and move in Phase 5.3. Proposal: #[cfg(test)] test support inside embedded_spec_bundle.rs.
- The plan does not place SpecIndex::load (L138-140), nor say who builds the SpecIndex for completion (engine.rs:308-313: ensure, then load, else default plus a log line). It needs a SpecBundle port method or a use-case return value, with the double ensure kept or dropped consciously.
- Error type: §1 limits anyhow to infrastructure/cli, pty and bootstrap, yet EmbeddedSpecBundle (infrastructure/adapters) and InstallSpecBundleUseCase (application) produce anyhow context chains today. SpecError {Aborted, Timeout, NotFound, Invalid} has no I/O or bundle variant. To keep the {e:#} output identical, a new variant needs a Display + source() chain matching the 5 context strings plus the home() error and the no-embed message.
- 'ensure_extracted orchestration -> use case' collides with extract_to doing its own touch+cleanup (L64-65). Moving both into the use case forces the extract tests to go through the use case; keeping both duplicates the step. Pick one and keep the test assertions.
- The cfg(feature="embed-specs") split (L35-41) has no planned home. It belongs in the adapter, and the application layer must not see the feature.
- Arch rule 3 ('a module other than bootstrap that references another module's ::infrastructure') would flag every module's use of shared::infrastructure::testing::TempDir and SharedDependencies unless shared is exempted. Rule 1 (as implemented at HEAD) scans every line of a domain file, #[cfg(test)] included, so the domain half of resolve_order cannot use TempDir.
- version() consumer doctor.rs:363: diagnostics may use specs ports and domain only, not EmbeddedSpecBundle. The plan doesn't say how doctor gets the version or the installed check (SpecBundle port method, or a SystemFacts field).
- The joins specs/, specs/user and specs/<ver> appear at L28, L125, L178-179 and doctor.rs:360-364. The glossary says DataDirectory owns 'specs', while §4 puts user_dir in embedded_spec_bundle, so ownership is ambiguous. The difference home()? vs home().ok()? (L28 vs L177) must survive.
- SharedDependencies {data_directory, clock} has no user-home source. dev_folder (L193) and parser Local specs (parser.rs:325) both need the user's home, not ~/.tabsmith, and they react differently when it is missing (literal fallback vs None), so one shared tilde helper would change one of them.
- SpecLocator merges parser::spec_location and resolve_in, but resolve_in's Component::Normal validation and diff-versioned skip apply only to Global names. The Local branch (parser.rs:324-334) applies neither, so a unified locator must not extend them to Local.
- dev_folder_expands_tilde depends on Settings::from_map with serde_json Values (L483-487). Phase 2 changes Settings while the code still lives in specs.rs, so Phase 2 must restructure this test (it falls under 'switch every crate::settings::* import', but isn't called out).
- If the retention or touch code moves to the Clock port (ms/secs), it must still give elapsed() semantics: now minus mtime, with a future mtime counting as 0 and a strict > comparison.
- The glossary has no SpecLocator, BundleRetentionPolicy, SpecBundle, EmbeddedSpecBundle or TempDir entries, although §3 says every named type must match it.
