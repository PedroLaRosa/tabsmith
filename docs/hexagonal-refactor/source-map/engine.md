# Source map: src/engine.rs (at af1b304)

## Behaviour traps
- Drain-then-serve (370-381): every queued message is handled in arrival order, and only then is the last pending Complete computed. A CommandFinished (reset_slots, cur=None) or Settings that arrives after a Complete is applied before compute runs. Per-event use cases must keep this: no compute per Complete.
- Abort paths return without a reply: parse Aborted (493), getQueryTerm Aborted (592), trigger Aborted (632). pump Aborted (963) returns and keeps the runs. js.wait aborts as soon as any Complete sits in Js.deferred (js.rs:474-480), and next_msg/try_next_msg return deferred messages first (js.rs:334-357). One queue, deferred-first.
- Partial mutation before an abort: user_fuzzy/last_arg_key (504-507) and the alias cache (475) are updated even when queries or update_slots then abort. prev_search (639) is not updated when a trigger aborts, and cur keeps the old request.
- Fuzzy: `if arg_key != self.last_arg_key { self.user_fuzzy = self.settings.bool("autocomplete.fuzzySearch", false) }` (504-507). ToggleFuzzy (424) sends no reply and lasts only until the arg changes. Settings (412-418) does not reset it. Strategy Prefix/Fuzzy override it (511-515).
- Ghost eligibility on errors: the mid-word guard and non-char-boundary give `self.error(req, cursor, false)` (472), so no ghost. No current_command (477) and NoSuggestions (496, plus logger::debug) give ghost=true. cursor is clamped `req.cursor.min(req.buffer.len())` (464). Completion::error sets arg_key 0 and fuzzy false.
- Env: `wrapper_env: std::env::vars().collect()` (339) is a one-time snapshot, and std::env::vars panics on non-UTF-8 vars. An empty session env falls back to it (437-443, 479-483). GenCtx.cwd is `to_string_lossy` (517).
- Fire rules (618-636): a new arg (`Rc::ptr_eq` false or either None) or `i >= slots.len()` fires. A path template fires on `dir_changed(new, old, ctx.shell == Shell::Pwsh.name())` (a string comparison). `trigger: None` fires ONLY when `arg.debounce.is_some()`. A Fn trigger is called with ctx None and SYNC_CALL and read through truthy(); `Err(_) => true` (a throwing or timed-out trigger fires).
- `let debounce = arg.debounce.map(|ms| if ms > 0 { ms } else { 200 });` (673): debounce 0 becomes 200 ms. The deadline is one per run across all steps: `debounce.unwrap_or(0) + 2 * floor.max(gens[i].script_timeout.unwrap_or(0)) + 1000` (675-676). Plain u64 arithmetic: a huge scriptTimeout (f64 `as u64` saturates) overflows, and Instant + Duration can panic. Keep it verbatim.
- Two script_timeout functions disagree. engine.rs:144 uses `settings.f64(..).max(0.0) as u64`; js.rs:210 uses `settings.i64(..)`. So `"autocomplete.scriptTimeout": 7500.5` gives 7500 for the run budget and exec timeout here but 5000 for the js host default. Any dedupe changes this.
- script_input (857-861): `let key_src = input.to_string();` is taken BEFORE `input["timeout"] = json!(timeout)`, with sorted keys (serde_json has no preserve_order). timeout = max(floor, g.script_timeout, input.timeout.as_u64()), so float or negative timeouts in the object are ignored. A failed ExecInput deserialization (for example an argv whose a[0] is not a string) → `Outcome::Fail("bad script input: ..")` → slot [].
- script_exec_input Object (168-172): cwd is inserted first and then `m.extend(o)`, so the object's own cwd wins, even `"cwd": null` (ExecInput.cwd None; js::exec then falls back to ctx cwd). The legacy string becomes `sh -c` on every platform (166). Empty array, empty string, null, number or bool → None → Done([]).
- Template generators never run script or custom (742-767). The dir is listed only when the template is path-type and cwd is non-empty. Help items are appended to EVERY template generator's items (754), so `history` gives only help rows. filterTemplateSuggestions receives template_json(items). A non-template generator with an empty cwd → [] (768).
- exec_output (880-903): splitOn wins over postProcess. The whole stdout is trimmed, but split items are NOT trimmed and empty items are kept as rows (`"a\n\nb"` gives 3 rows). Exit status is ignored. Neither set → [].
- Two different JSON→suggestion rules. json_items (190) goes through suggestion_from_json: strings → kind None, insert_value None, not dangerous, "" KEPT. post_process_items (201): strings → script_string (kind Arg, insert_value, is_dangerous from ctx), "" dropped, objects need `o.get("name").is_some_and(truthy)` (name [] passes the check, then suggestion_from_json drops it). Do not merge them.
- custom_result: `x.get("context").is_some()` on the FIRST array element (907-910). `"context": null` counts as templated. A non-array or undefined result → [] (917).
- Cache (advance 932-937): the owner stores the raw task value BEFORE the superseded check, so superseded runs still fill the cache. Failures never stay cached (`cache.fail`). Stale-while-revalidate clones a background run with the SAME gen_id (827-833). Its success overwrites the slot and causes a Generators reply; its failure is silent (722-724). Lookup::Shared runs have store None and never store. The cached value is the raw input of the next step (exec JSON or custom return), not suggestions.
- pump (967-994): per finished task, owners (`store.is_some()`) run before sharers. `js.forget(&[*task])` follows each finished task. An expired run calls `cache.fail` and forgets its task ONLY if no live run shares it (990). A run expires on `now >= r.deadline` using a second Instant::now() (982). The reply is sent only when `changed && self.cur.is_some()` (995). The wait deadline is min(run deadlines, now+SLICE).
- A Generators-phase reply recomputes the WHOLE reply: history rows, ranking with the current recency and current settings, insertions, and the ghost from the new items (1085). triggered_generators is filled only for Phase::Parse (1101-1105). `loading: self.slots.iter().any(|s| s.loading)` (1107). views come from `slots.zip(&cur.queries)`, which truncates (1033-1043).
- First token: `let mut list = if pr.first_token { cur.first.clone() }` (1030-1031), and cur.first is empty unless autocomplete.firstTokenCompletion (531-539), so the first token never gets assembled spec items. The 10 s first-token cache (1011-1014) ignores alias and PATH changes. Only Settings (417) and Session (422) clear it, not CommandFinished.
- Ranking: `s.string("autocomplete.sortMethod") != Some("alphabetical")` (1064), so any other value, including a non-string, uses recency. Recency is keyed by `pr.tokens.get(pr.command_index)` (1063). The recency mutex stays held during suggest::rank (1065-1072). A poisoned lock means no recency.
- Local ghost (1114-1128): needs inline.enabled (default true), a non-empty buffer and `cursor == buffer.len()`. `Ok(Source::History) | Ok(Source::Profile(_)) => history()`: LLM-profile users get local history only. `_ => history().or_else(specs)`: an invalid inline.source falls back to history+specs.
- CommandFinished/CommandEnded (395-404), in order: history.append (Finished only; blank commands skipped inside History), ghost_cache.clear(), reset_slots(), cur = None. runs and GenCache are NOT cleared. In-flight runs finish into missing slots and settle returns false.
- Settings (412-418): js.set_settings (runtime timeout), self.settings, parser.clear_caches(), reset_slots(), first_token_cache = None. clear_caches keeps spec identities (parser.rs:118-127), so arg_key stays stable. cur, GenCache, aliases, ghost cache and user_fuzzy are NOT touched. Session (419-423) clears only aliases and the first-token cache; slots stay.
- record (1133-1162): `if name.contains('↪') { return; }` duplicates menu.rs:361. The throttle: the first insert spawns a thread that sleeps 1 s, `saving.store(false)`, THEN snapshots the LATEST map (1152-1153). A design that hands the saver a snapshot taken at record time loses inserts made inside that second. Spawn failure → synchronous save. state_path None → memory only (1140).
- Shutdown flush is conditional: `if self.saving.load(SeqCst) { self.save_recency_now(); }` (386-388). An unconditional flush would write `{"autocomplete.recency":{}}` to state.json on every exit. Nobody joins the engine thread (pty sends Shutdown, kills children, exits), so the flush is best-effort. Making it blocking changes exit latency.
- save_recency: the purge guard `if !path.parent().is_some_and(Path::is_dir) { return Ok(()) }` (75-77) exists because Store::save calls create_dir_all. A corrupt state.json → Err (warn) and NO write. A recency value of the wrong shape (one float or negative ts) fails `from_value` as a whole: load gives an empty map, and save REPLACES the whole on-disk map (79-84). Merge is max per (cmd, name). Other sessions' entries never reach this process's in-memory map.
- llm (1173-1201): a non-profile source → immediate `Ghost{text: None}`. A cache hit → immediate reply on the engine thread. The worker inserts `format!("{buffer}{t}")` into a cache that CommandFinished may have just cleared (race). A thread spawn failure → only logger::warn and NO Ghost reply. The history snapshot and the env (session or wrapper) are taken at request time.
- Startup order (49-53, 307-321): Js::new runs first. If it fails, the thread ends before ensure_extracted runs. If ensure_extracted fails → `SpecIndex::default()` even when an older index on disk could load. Recency is loaded in Engine::with.
- The inbox never disconnects: Js keeps a Sender clone (`inner`, 46; js.rs:238). The doc claim on line 43 ('or when all senders are dropped') is false, and the loop ends only on Shutdown. ExecDone/Timer arms (425) are unreachable because js.internal consumes them.
- GenKey and arg_key are DefaultHasher over `(Rc::as_ptr as usize, usize)` (98-107, 500-503). The values flow to pty and menu (triggered_generators, Item.generator, menu last_inserted_gen). slot_arg and runs hold Rc<Arg>, which prevents address reuse while they live. Changing the hashed tuple type changes the values (harmless across processes; keep it consistent within one).
- getQueryTerm: `Ok(Value::String(s)) => Query::Value(s)`. Any other value, Timeout or Other error → `Query::Value(pr.search_term.clone())` (591-593). Path templates force `Query::Path{backslash: shell == Pwsh}` and ignore getQueryTerm (577-580). JS call order: getQueryTerm fns first (524), then trigger fns (530).
- Generators receive tokens from command_index onward (525-529). The default cache key for custom is `run.tokens.join(" ")` (791). For scripts it is the exec JSON (857). `cache_key` prefixes the cwd only with cacheByDirectory.
- gen_context_json (217) vs GenCtx::context_json (js.rs:63): same keys. js falls back to `std::env::vars_os()` when env is empty; engine passes ctx.env as-is (empty → {}). The engine's env is empty only when the wrapper env is empty, so a dedupe must keep the as-is pass-through or prove that case away.
- Outcome::Fail logs `engine: generator failed: {e}` at debug level even for superseded runs (721). Expired runs fail with "timed out" (993). Other log strings: "engine: no suggestions: {e}" (495), "engine: specs: {e:#}" (311), "engine: js host: {e:#}" (53), "engine: spawn: {e}" (57), "engine: saving recency: {e:#}" (1155, 1169), "engine: llm worker: {e}" (1199).

## Plan gaps
- Phase ordering: Phase 6.7 deletes engine.rs, but ghost (1114), llm (1173), llm_history (152) and the test llm_history_honours_history_count belong to ghost_text, which is built in Phase 7. 6.6 says only 'dispatch calls the legacy inline.rs until Phase 7'. The interim home is not named (bootstrap/engine_server.rs or inline.rs).
- Event table, 'idle with generator tasks pending → ProgressGenerators → reply if changed', leaves out SuggestLocalGhostText. Today reply() recomputes the ghost for every Generators reply from the new items (1085), so spec ghosts update when generators finish. Followed literally, those updates are lost. The Complete row also needs the use case to report ghost eligibility (472 false vs 477/496 true).
- 'Domain uses std only' conflicts with moving the step transitions (713-948) and GeneratorCache into the domain. GenCache (suggest.rs:1105) stores serde_json::Value. The steps read v["stdout"] (881), `x.get("context")` (910), run JSON timeout merging and ExecInput deserialization (857-865), and build cache keys from JSON text. A typed SpecFunctionResult per step must keep these: the cache holding raw pre-step values, the json_items vs post_process_items rules, and context-key presence including null.
- GeneratorCommand {StartCall, StartExec, StartSleep, Settle} is not enough. begin lists a directory synchronously (745-753, DirectoryLister I/O mid-transition). fetch clones a second background run (827-834). cache.start(&key, task) needs the TaskId back synchronously (831, 845). Fresh/Stale hits continue in the same call (803, 874). The domain needs a two-phase protocol or several commands per step.
- Not placed by the plan: truthy (117), env_var (127), post_process_items (201), SLICE (33), SYNC_CALL (35), the wrapper-env source (`std::env::vars()`, 339), Engine::new's I/O (308-320), CompletionSession fields last_arg_key/prev_search/next_gen/slot_arg, and `index.completions` used by first_token_items (1017). Also the engine tests js_truthiness, post_process_filtering and legacy_string_script_runs_through_sh_c have no named destination.
- script_string (179) is listed under fig_spec_mapper's 'JSON halves', but it has no JSON and the domain split_on path needs it (889). It belongs in specs domain, for example as a SpecSuggestion constructor.
- Section 4 puts engine::{json_items, script_exec_input, script_string} in fig_spec_mapper, but the Phase 5 steps (5.1 lists 'the 8 spec tests, from_fig and fig_type') never say when they move. 5.1 also makes Script::Object a typed ExecRequest, yet script_exec_input must still convert runtime JSON from Script::Fn results (942), so the JSON path cannot go away.
- 'One generatorContext JSON builder (dedupes engine::gen_context_json / GenCtx::context_json)' changes behaviour when env is empty: js.rs:63-77 falls back to process env vars_os, while the engine passes {}. Dedupe only with the engine's pass-through for custom generators, or record why env is never empty.
- There are two script_timeout functions (engine.rs:142 f64, js.rs:210 i64). The plan puts the engine one in GeneratorTriggerPolicy and says nothing about the js one. Merging them changes fractional values (7500.5 → 7500 vs 5000).
- Moving 'autocomplete.disableForCommands' out of the loader into CompletionRequestPolicy changes behaviour. Today Loader::load checks it for EVERY spec load (parser.rs:231-237): nested isCommand args (`sudo <disabled>`), loadSpec locations and Local specs. A single pre-parse check on the root command would not cover those.
- The Phase 2.2 per-key default tests skip the engine's call-site defaults: autocomplete.insertSpaceAutomatically true (1079), inline.historyCount 49 (155), autocomplete.scriptTimeout 5000/20000 per cfg!(windows) (146), beta.history.mode "off" (1046) and autocomplete.sortMethod (1064, None today vs catalog "most recent"; still equivalent). The wrong-type fallback must also stay: i64 on a float → default, f64 accepts ints.
- 'Shutdown | driver stops; the recency adapter flushes' must stay conditional on a pending save (386-388). Otherwise every session exit writes state.json.
- The RecencyRepository trait shape is not specified. The throttled saver must write the LATEST map after 1 s (1152-1153), and reply() ranks under the same lock (1066). So either the adapter keeps a shared latest-pending snapshot updated on every save, or SuggestionRecency stays behind an Arc<Mutex> shared by the session and the saver thread.
- The composition root conflicts with use cases holding `Rc<dyn Port>`, because QuickJS is !Send. build_completion_module (and the spec runtime and repository) must be called inside the engine thread closure (49-55), not in bootstrap::run on the main thread. Section 1's `build_<module>_module(&SharedDependencies)` does not say this.
- RuntimeEventSource: the deferred queue lives inside Js today (js.rs:226, 334-357, 474-504). The plan keeps a single channel but does not say who owns `deferred`. The server's next message must return runtime-deferred messages first, in order, and the runtime's wait must see a deferred Complete to abort.
- Engine → pty replies (Msg::Completion at 378 and 996, Msg::Ghost at 1176-1196, the last from the llm worker thread) have no port. The plan defines only pty → engine (terminal_session::CompletionEngine). bootstrap would send terminal_session's session_message type directly.
- GhostTextCache must stay `Arc<Mutex<..>>`, shared with the LLM worker threads (1188-1195) and cleared on the engine thread (399-401). The ghost_text section lists the entity but not the cross-thread sharing or the insert-after-clear race.
- session_update_refreshes_first_token_items (1330) needs a real QuickJS Js only because handle() takes one. After the split it must be rebuilt around ApplySessionContextUseCase. The plan's 'existing test names are kept' still works, but Phase 6.5 does not list this test.
