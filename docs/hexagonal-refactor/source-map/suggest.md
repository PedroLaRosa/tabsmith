# Source map: src/suggest.rs (at af1b304)

## Behaviour traps
- Query::of Str: `search_term[search_term.rfind(g).map_or(0, |i| i + g.len())..]` (32). The index is in bytes, and an empty g yields "". In insertion, the Str delete count is taken from c.raw, not the search term: `c.raw[c.raw.rfind(g.as_str())...]` (893).
- insertion delete branch order (888-913): AutoExecute→0, then `q == c.search_term` → raw.len(), then Query::Str, then Query::Path, then the function getQueryTerm logical-tail match, else the approximation of `2 per whitespace, 1 otherwise, .min(raw.len())`. Reordering changes deletes.
- assemble shows a loading generator's stale results only when `!g.loading || g.query == Query::Term` (276). Path templates get Query::Path (engine 577-580), so their stale results are hidden while loading, even though the GenView comment says Term ⇔ no getQueryTerm.
- additional_suggestions are added regardless of suggest_subcommands/args/options (286-294). Inside an option chain only typed rows are kept: `.filter(|s| chain.is_none() || s.kind.is_some())` (290).
- static_options runs `seen.extend(...)` (220) BEFORE the exclusive_on and repeat-limit checks. A local option that is excluded or used up still hides an inherited persistent option with the same name. Order: comp.options → pr.persistent → comp.persistent (210-215).
- Repeat limit: `Repeat::No | Repeat::Times(0) => Some(1)` (225). Options are computed even when !suggest_options (295) because option_chain needs them (300).
- from_opt separator (119-127): no separator if the first arg is optional. `Some("")` → first optionArgSeparator, else "=". An option with NO args but requires_equals still gets "=", because `o.args.first().is_some_and(optional)` is false.
- from_sub should_add_space: `mandatory || s.requires_subcommand.unwrap_or(!s.subcommands.is_empty())` (112-113).
- option_chain keeps only `ItemType::Option | ItemType::Arg` (312), dropping subcommands, files, folders and special rows. It pushes the matching short option only when !options_flag (314-321). The matching option is renamed in place and KEEPS its insert_value (328-333). Other short options get `names = [chain+x]` and insert_value = the same (335-337). Arg rows get `Query::Value(String::new())` (324).
- cmp_locale is not ICU: `a.to_lowercase().cmp(&b.to_lowercase()).then_with(|| a.cmp(b))` (170-172). It also sorts list_dir (1290). sort_by is stable everywhere.
- history_rows walks `entries.iter().rev()` (351), so the newest comes first. Frequency is counted over duplicates before dedupe (366 vs 373), so "git checkout main" twice plus "dev" once gives 75.3. Priority is `75.0 + f.min(10) as f64 / 10.0` when f>1, else 50 (379-383). Matching uses strip_prefix (byte-exact) + trim_end. Multi-line/control entries are skipped (359). Description is "past command".
- mix_history with show=false returns history rows only, dropping spec rows (392-394). by_word uses HashMap insert, so the last wins (397). `existing` holds full spec names, compared with the full history row name (405). Spec rows are boosted by max over all their names (412-416). Output order is spec rows first, then extra rows.
- update_priorities: 0 counts as unset and becomes 50 (437). "../" never gets recency (432), and recency 0 is ignored (435). Values are clamped to 0..100 except AutoExecute (438-440). `rec.is_some() && (50.0..=75.0).contains(&p)` → `75.0 + boost`, else `p + boost`, with boost = ms/1e13 (436-445).
- rank sorts with stable sort_by on priority desc, and NaN counts as Equal (714-718). Dedupe runs only when `!out.is_empty() && out.len() <= 50` (720).
- filter: an exact match ignores `hidden`. The hidden check is only on the partial branch (`else if !s.hidden`, 636), so an exactly typed hidden row IS shown. The display_name partial check (641-645) runs for every row, including hidden and exact-matched ones, which creates duplicates that are only removed when ≤50.
- filter auto-exec: only the first exact match gets it (`added`, 618), and only if `plain` (615-617), not dangerous unless run_dangerous, and its first arg is optional or absent. For a folder, the name loses its trailing '/' and the description is "folder" (627-630). Dot/folder/current-token rows are added only when `!added && !auto_exec_hidden` (659). `exec_after_space` matters only for an empty search term (601).
- Exact strings to keep byte-for-byte: "↪", "Immediately execute", "Enter the current directory", "Enter the current argument", "folder", "past command", "{cursor}", "../", "folders", "filepaths", "help".
- partial: fuzzy with a prefix hit returns `(p as f64 / 10.0, true)`. With an empty fuzzy query, `Some(0)` is the fuzzy score (569-579).
- fuzzysort: `lower = |c| c.to_lowercase().next().unwrap_or(c)` takes the first char only (464). Word beginnings use ASCII checks on the original case (486). Without a strict match the score is `*= 1000` (540-542), then `-= (tn - qn)` (543). Indexes are in chars.
- highlight fuzzy uses `max_by_key(score)` (1021), which returns the LAST segment among equal scores. Offsets add `+ 2` for ", " (1014) and must match Item::title's `join(", ")` (types.rs:124). Non-fuzzy highlights EVERY segment whose lowercase starts with q (1027-1031). display_name replaces names entirely.
- name_match verbose picks the longest name with a strict `>` (746), so the first wins ties, and only for Option|Subcommand (743). It falls back to all names only when display_name is Some (766-770). Otherwise no match gives None and the insertion text is "" (926-927).
- insertion: insert_value is used verbatim except for File/Folder rows (`Some(v) if !path`, 925). Separator + `{cursor}` are appended only on the name branch (940-943), never with insert_value. Trailing \n's collapse to one (947-951). The space is appended after `{cursor}`, so `--out=` gives cursor_back 1 (952-953, test 1946-1955).
- insertion order: the don't-retype check needs `deleted == q && text.starts_with(&q)` (957) and drains q.len() bytes. execute is detected (961) BEFORE `text.retain(|ch| !ch.is_control())` (967), so inner \r and \n are stripped while the trailing \n still means execute. Only the first `{cursor}` is consumed (969), and a quoted spec name containing `{cursor}` still becomes the cursor marker.
- escape_posix: `c.is_alphanumeric()` is Unicode-aware (786). The tilde rule applies only to path rows (789), and the `$VAR` passthrough only to non-path rows (791). When the only unsafe char is a space it uses backslash-space (794-795). A folder keeps `/` outside the quotes (798-799). It calls integrations::quote(shell, ..), so fish gets different escaping.
- escape_pwsh: folders are backtick-escaped even when the user opened a quote, since the quote flag skips the early return and reaches the `if folder` branch (811-818). SPECIAL includes U+2018-201E (808-809).
- unquote match arm order (834-849): the escape arm `_ if ch == esc && i + 1 < raw.len()` comes before the closing-quote arm, so `\"` inside double quotes is literal. A lone trailing escape char is kept literal. pwsh `''` inside single quotes yields one quote. The pwsh escape char is '`'.
- escape_in_quote: in bash/zsh double quotes `!` becomes `"'!'"` (873). Fish double-quote specials are only `\ " $` (867). The pwsh single-quote case slices the quote() output as `q[1..q.len() - 1]` (860), which assumes quote() wraps in 1-byte `'`. ShellQuoting must keep pwsh_sq doubling of `'` and U+2018-201B (integrations.rs:301-310).
- same_row compares args with `Rc::ptr_eq` (692). Changing `Vec<Rc<Arg>>` to owned or Arc, or deep-cloning Arg, changes which rows dedupe.
- triggered: `last` counts chars as a lastIndexOf stand-in (1061), not UTF-16 units. Threshold compares char counts, `new > n && old <= n` (1065). Fn returns None and the engine maps it to true (engine 635).
- GenCache: TTL is inclusive, `now.saturating_sub(*at) <= cfg.ttl_ms` (1117). Past TTL with max_age gives Shared or Miss, never Stale (1119-1120). SWR refresh = `inflight.is_none()` (1124). `start` keeps the old value (1137-1144). `store` overwrites the whole entry and clears inflight (1148-1155). `fail` removes only value-less entries (1160-1165).
- cache_key always has a leading comma: `format!("{},{key}", if cache_by_directory { cwd } else { "" })` gives ",git branch" (1081).
- shell_expand: `~` expands only when alone or followed by `/` (1178), not `~\` even in pwsh. Home is HOME, then USERPROFILE, else literal "~" (1174-1177). Pass 1 `$NAME` runs before pass 2 `${..}`, so an env value containing `${X}` is expanded twice. `${X:-}` (empty default) is left literal (`.filter(|&j| j > 0)`, 1218). A set-but-empty var does NOT fall back to the default (1227-1230).
- inserted_directory always joins with '/' even in pwsh (1256; the test expects `C:\\w/src\\`). `Path::new(dir).is_absolute()` (1260) depends on the OS (cfg(windows) differs).
- list_dir: std::fs::metadata follows symlinks (1277), so a broken symlink lists as a file. `.DS_Store` is skipped case-insensitively (1284) and control-char names are dropped (1285). Sort is dot-names last, then cmp_locale (1287-1291). "../" is always appended unsorted, even for an empty dir (1292), but an unreadable dir returns [] without "../" (1270-1272). insert_value = name. Names are converted with to_string_lossy.
- help_items takes the last annotation of kind Subcommand|Option (1318-1322). Only Subcommand with `n >= 2` uses the parent level and excludes the trigger's aliases (1325-1326). Otherwise it uses path.last() or completion. Rows are kind Special with template "help".
- template_json emits nulls for a missing name, insertValue or templateType (1365-1367). serde_json is built without preserve_order (Cargo.toml), so keys are sorted. A derived Serialize struct with skip_serializing_if or a different field order would change what the JS filterTemplateSuggestions sees.
- exe_name: on cfg(unix) any x bit keeps the full name (1388). On cfg(not(unix)) the extension is stripped, PATHEXT defaults to ".COM;.EXE;.BAT;.CMD", and names without '.' are dropped via `rsplit_once('.')?` (1393-1397). executables uses `out.sort()` (byte order, per dir, 1411), not cmp_locale.
- first_token_items order: specs (is_root_spec allows only `@scope/x` with a slash), then aliases sorted as (k,v) tuples (1435-1436), then PATH dirs in split_paths order, each dir sorted. A single `seen` set means a spec name beats an alias or exe with the same name (1425). Empty names are skipped. split_paths separator is platform-specific (1441). An ExecutableCatalog port that returns a globally sorted or deduped set would reorder rows.
- from_suggestion: `kind.unwrap_or(ItemType::Arg)` (163), `is_dangerous || dangerous` (158), `priority.unwrap_or(0.0)` (156). Sugg::new defaults to query Term and priority 0.
- Naming collision during renames: inside suggest.rs `Suggestion` means spec::Suggestion (to become SpecSuggestion), while `Item` becomes the completion `Suggestion` VO. A mechanical rename can swap them.

## Plan gaps
- GenCache, CacheEntry and Lookup store serde_json::Value (1088-1100), but the plan places generator_cache in completion/domain/entities, where the rule is std only. Phase 6.4 needs either a generic `GeneratorCache<T: Clone>` or the typed SpecFunctionResult from Phase 5.3. Test cache_ttl_swr_max_age uses json!(1).
- GenView (182-189) is not placed by section 4 or the glossary. It is the assembler's input (key, query, loading, &[SpecSuggestion]).
- after_sep is placed in suggestion_filter.rs, but it is mainly used by the Query::of VO (36) and also by insertion (897), dir_changed (1075) and inserted_directory (1252). Putting it in the filter makes a VO depend on a service. suggestion_query.rs is the natural home.
- same_row is placed in suggestion_filter.rs, but its only caller dedupe is in suggestion_ranker.rs. It is private today, so it should move with dedupe.
- exe_name is listed with first_token_suggestions (domain) in section 4 (`first_token_items minus fs, is_root_spec, exe_name`). It takes &std::fs::Metadata and uses PermissionsExt under cfg(unix), so it belongs in path_executable_catalog with executables.
- list_dir is called synchronously inside the generator step machine (engine::begin 744-754, Outcome::Done right away). The plan makes GeneratorRun a domain entity returning GeneratorCommand {StartCall, StartExec, StartSleep, Settle}, with no ListDirectory command. Following it literally means either adding a command or listing in the use case before the step. Making the listing asynchronous would change the reply phase in which template items appear.
- template_json's only caller (engine 759) passes JSON into filterTemplateSuggestions. Once GeneratorRun is domain, StartCall must carry typed Vec<SpecSuggestion>, and QuickJsSpecRuntime must call fig_spec_mapper::template_json. The plan does not say this. Also, Phase 5.1 names only fig_type, while section 4 moves template_json in Phase 5 even though suggest.rs survives until Phase 6.
- Section 1 says 'Domain struct fields are private'. 15 of the 23 tests build or mutate Sugg, ParseResult (pr_for 1457-1478), Annotation, Opt, Subcommand and HistoryEntry by struct literal or field assignment. Keeping them 'locked' needs test builders or with_* methods that set exactly the same values. No test plan step covers this.
- Sugg::first (95), from_sub (99), from_opt (118), auto_exec (583) and cmp_first (175) are private today. After the split each is used from another file (assembler, ranker, history_suggestions, insertion_composer test), so they need pub(crate). This only changes visibility.
- Test empty_search_term_is_no_prefix_match (1628-1645) calls crate::inline::spec_ghost. Section 2 allows completion → shared, settings, specs, history only, so this test cannot stay in completion after Phase 7. It must move to ghost_text/domain/services/spec_ghost_text.rs (the plan's Phase 7 test list omits it).
- Phase 6.2 says the '3 fs tests move to the adapters'. first_token_sources (2512) checks the merge of spec names, aliases and PATH exes (domain) together with the exe scan (adapter). After the split it needs the service wired to the real adapter, or one extra pure test with an in-memory catalog.
- Phase 1.3 ('removes suggest → integrations') must touch suggest.rs: integrations::quote at 799, 800, 820, 859 and test line 2323. The plan's Phase 1 list doesn't say suggest.rs is edited.
- The cache_key assertions (1793-1801) sit inside cache_ttl_swr_max_age, but cache_key goes to generator_trigger_policy.rs while GenCache goes to entities/generator_cache.rs. The test must be split, and the plan does not mention that.
- help_items is placed in path_template.rs although it has nothing to do with paths. That is harmless, but it may confuse the next reader.
- The glossary renames GenKey (a u64 alias) to the GeneratorKey VO. Sugg.generator, GenView.key and Item.generator all carry it, and the identity is hash(Rc ptr, idx) (engine 105-107). Making it a VO must not change the hash, because generator_keys_differ_per_index and the menu rely on the keys being equal.
- The engine passes the pwsh backslash flag in two ways: a string compare `ctx.shell == Shell::Pwsh.name()` (engine 621, 750) and an enum compare `shell == Shell::Pwsh` (engine 579). If GeneratorContext.shell becomes typed, both must stay equivalent.
