# Source map: src/js.rs (at af1b304)

## Behaviour traps
- The id space is shared and finish() routes by membership: `if h.live.contains(&id) { h.done.insert(id, r); return; }` (586-588), else `__ts.settle`. Tasks, exec ops and setTimeout ops all come from one `next_id` (184-187). Splitting the counters, or typing tasks and ops apart, makes ids collide and misroutes results.
- Bad exec input MUST be reported asynchronously: `let _ = h.tx.send(EngineMsg::ExecDone { id, out: Err(format!("bad exec input: {e}")) })` (280-283). JS registers the resolver only after __ts_exec returns: `__ts.op(__ts_exec(ctx.id, JSON.stringify(input)))` (152). Settling synchronously (calling finish inline) loses the result and the JS promise hangs forever. Same for `__ts_sleep(0)`: it must fire on a later pump.
- RefCell borrow scoping: start_call drops `host.borrow_mut()` before `ctx.with` (415-421), finish drops it before settle (584-591), and pump drops it before running jobs (616-621). JS jobs call back into __ts_exec/__ts_sleep/__ts_done, which take borrow_mut. Holding a borrow across any ctx.with panics with BorrowMutError.
- wait aborts only on Complete, and also on a Complete deferred earlier: `if self.deferred.iter().any(|m| matches!(m, EngineMsg::Complete(_))) { return Err(JsError::Aborted); }` (475-481) runs BEFORE pumping. Every other message (Settings, Shutdown, ToggleFuzzy) is pushed to `deferred` without aborting (503-504), in FIFO order, and is replayed first by next_msg/try_next_msg (336-338). Shutdown during a wait waits for the deadline.
- Partial delivery: `if finished || now >= deadline { return Ok(self.collect(tasks)); }` (490-491). collect removes the finished results (they are delivered once) and returns None for pending ones. A forgotten or duplicate id gives `Some(Err(format!("unknown task {t}")))` (649). Passing a task twice yields the result and then "unknown task". The engine dedups (engine.rs:953-954).
- call() vs cli_version: call forgets the task on timeout AND on abort (526-533). parser::cli_version deliberately does not forget on abort, so the detection survives (parser.rs:367-371). A typed port must keep both paths.
- CPU limits differ from wait deadlines. pump: `let stop = deadline.max(now + MIN_PUMP);` and per job `d.set(Some(stop.max(Instant::now() + SLICE)))` (625-629): at least 50ms of jobs even with a past deadline, and each job gets at least 1000ms CPU. Tying the interrupt to the 50ms engine slice breaks long_callback_survives_short_pump_slices. arm_off() after every JS entry (394, 449, 606, 635): a deadline left armed spuriously interrupts later settles.
- Due timers fire in insertion order, not due order: `h.timers.drain(..).partition(|t| t.0 <= now)` (618). If several are due in one pump, the settle order (and so the order of JS reactions) is the push order. Sorting by due time is a behaviour change. clearTimeout only drops the JS-side id (130). The host timer still fires and wakes wait.
- Overflow panic kept as-is: `Instant::now() + Duration::from_millis(ms.max(0.0) as u64)` (295) saturates to u64::MAX for setTimeout(fn, Infinity) and panics on Instant overflow. Do not 'fix' it with checked_add during the move.
- The exec ctx is looked up by callback task id: `h.ctxs.get(&(ctx_id as u64)).cloned().unwrap_or_default()` (276). ctxs is removed in collect (645) and forget (553), so exec from a callback whose result was already delivered runs with GenCtx::default() (wrapper env, process cwd). start_exec does not insert into ctxs (457-462).
- JSON details visible to JS: the start ctx is `{"id", "exec":[...]}` plus `cwd` only `if !generator.cwd.is_empty()` (434-437). mkExec does `{ cwd: ctx.cwd, ...input }` (155), and the legacy string form resolves to stdout only (154). The exec result reaches JS as `serde_json::to_value(ExecOutput)` text, keys stdout/stderr/status (570, 593). Rejections are `new Error(v)` (150), so String(e) is "Error: failed running executable (...)".
- __ts_done: results for non-live tasks are silently dropped (306). A payload JSON parse failure becomes Err(serde message) (308). The rejection payload is JS `String(e)` (163). The success payload is `JSON.stringify(this.ser(v) ?? null)` (148). ser: functions become {$fn:id} with stable ids by identity (138-139), bigint and RegExp become strings, undefined/symbol properties are dropped, an undefined array slot becomes null, cycles or depth>200 become null, and shared refs are duplicated.
- `__ts.fns` only grows, and FnIds are indexes into it (136-139, comment 227-228). Recreating the Context or runtime (e.g. per load) invalidates every cached spec's FnId. load_module cache: `.filter(|(s, _)| stamp.is_some() && *s == stamp)` (373), so a file that cannot be stat'ed is never a hit, an empty file caches an empty map, and errors are not cached.
- load_module error text: `format!("{}: {e}", path.display())` (378, 399, 405) and `"{}: no trailing export clause"` (383). Timeout is decided by `Instant::now() >= deadline` after any failure (396). Module top-level promises are NOT pumped during load: they run in a later wait's pump.
- Evaluation mode: `ctx.eval::<(), _>(PRELUDE)` and `EvalOptions::default()` (316, 386) are global + strict in rquickjs 0.14 (EvalOptions::default sets strict: true). Spec bodies run inside an IIFE, so their top-level `var`s are function-local. Changing to module eval or non-strict changes semantics.
- wrap_module: it picks the LAST `export` followed by `{` (659-662), even if `export default` also exists ('esbuild form still wins'). The clause is cut at the first `}` (676), and everything after the clause is dropped (`&src[..at]`, 688). `split_once(" as ")` needs single spaces. The hand-written path uses rfind("export default"), strips `export ` only at the start of a line (668), and lines() drops `\r`. The template strings are asserted byte-for-byte by the test at 1179.
- exec cwd: `[input.cwd, Some(ctx.cwd)] ... .find(|p| !p.as_os_str().is_empty() && p.is_dir())` (700-706), so a RELATIVE input.cwd is tested against the wrapper's process cwd. native ls instead joins it under ctx.cwd: `.map_or(cwd, |c| Path::new(&ctx.cwd).join(c))` (713). The inconsistency is intended ("cd nonexist/ must list nothing"). Do not unify. Fallbacks: current_dir, then "C:\\" or "/".
- exec short-circuits run before any spawn and in this order: ls with trimmed args == ["-1ApL"] (707) goes to native_ls (ignores env); command "fig" or "tabsmith" returns status 1 with empty output (716-721), whatever the args.
- Child env order (737-762): env_clear + session env only when ctx.env is non-empty; remove LS_COLORS/CLICOLOR_FORCE/CLICOLOR/COLORTERM; set PROCESS_LAUNCHED_BY_TABSMITH=1, HISTFILE="", HISTCONTROL=ignoreboth, TERM=xterm-256color, NO_COLOR=1; THEN input.env (so it can override TERM etc., and None removes); THEN NoDefaultCurrentDirectoryInExePath=1 when the program stem eq_ignore_ascii_case "cmd". That happens on unix too (the test at 1622 relies on it) and overrides input.env.
- The `var` closure (723-735): an input.env entry wins even when its value is None (returns None, no fallback to the session or wrapper env); then the session env if non-empty, else std::env::var_os. key_eq is case-insensitive only on cfg!(windows) (793-799). find_exe resolves to an absolute path with this env (829-832). Switching to Command::new(name) would let std search the parent PATH instead.
- find_exe details (836-871): absolute paths are returned without an existence check; names with more than one component resolve under the resolved cwd; Windows tries the bare name first only if it has an extension, then PATHEXT (default ".COM;.EXE;.BAT;.CMD", empty segments filtered); unix requires is_file plus an exec bit. Error strings: "failed running executable ({cmd}): not found" (830), "failed running executable ({cmd}): {e}" (789).
- Timeout floor: `default_timeout_ms.max(input.timeout.unwrap_or(0))` (786), so input can only raise it. The default is host.timeout_ms captured at spawn (191).
- wait_output returns only when the status is known AND both pipes have reached EOF (946). A grandchild holding a pipe makes a finished child run into the timeout. A signal exit gives `s.code().unwrap_or(1)` (950). Timeout: kill(-pgid, SIGKILL), then the job kill, child.kill(), child.wait(), and "timed out after {timeout_ms} ms running executable ({label})" (965-967). try_wait error: "waiting for {label}: {e}".
- Drop order matters in wait_output: `let job = job::Job::assign(&child); let _live = job.as_ref().map(...)` (913-915). _live is declared after job so it drops first, removing the entry under the LIVE lock before CloseHandle. kill_live_children holds the lock while terminating (1012-1020). If Job::assign fails, the child is never registered (Windows).
- atexit: registered lazily, once, at the first Live::new on unix (987-996), as an `extern "C" fn` with no state. kill_live_children must therefore stay a free fn over the static LIVE. It cannot become a method on a ProcessExecutor instance. pty.rs:103 calls it explicitly because exec skips atexit.
- clean order: `.replace("\r\n", "\n").replace("\x1b[?25h", "").trim_matches('\n')` (1083-1087). CRLF is folded before the ESC is removed, and only `\n` is trimmed (not spaces or a lone `\r`).
- native_ls: read_dir order is not sorted. It follows symlinks with fs::metadata, so a dir symlink gets "/" and a broken symlink gets none. Unreadable entries are skipped by flatten(). Names are lossy. Joined with "\n" with no trailing newline. Error: stderr "ls: {dir}: {e}", status 2 (1110-1114).
- script_timeout uses `settings.i64(...)` = Value::as_i64 (210-216). 7500.5, 1e4 or values above i64::MAX fall back to the default 5000/20000. engine::script_timeout (engine.rs:143-150) uses f64 and accepts them. The two are intentionally different today.
- Logging strings: `crate::logger::debug(&format!("js console.{level}: {msg}"))` (268) and `crate::logger::warn(&format!("js settle {id}: {e}"))` (608). The worker thread name is "tabsmith-exec" (193).
- serde_json has no preserve_order in Cargo.lock, so Map/Value objects iterate in sorted key order. Namespaces and exec-output objects are sorted. Converting them to HashMap-backed typed structs changes the iteration order wherever callers iterate.

## Plan gaps
- Js::next_msg/try_next_msg (332-357) and the `deferred` queue have no destination. The plan moves the inbox to bootstrap/engine_server behind `RuntimeEventSource`, but wait() needs to: (a) receive runtime events, (b) recognise a foreign 'newer request' (EngineMsg::Complete) to abort, (c) keep foreign messages in arrival order for the engine loop's next read, and (d) let exec workers SEND ExecDone into the same channel (Host.tx, 178/191). A receive-only port cannot do (d). Typing the channel as Sender<EngineMessage> makes specs depend on bootstrap. The port needs a sender half (e.g. a `Fn(RuntimeEvent)+Send` sink) plus a shared deferral contract.
- The 'one generatorContext JSON builder' dedupe would change behaviour. GenCtx::context_json (63-87) falls back to the wrapper's env when ctx.env is empty. engine::gen_context_json (engine.rs:217-220), the production path used for custom generators at engine.rs:797, emits `environmentVariables: {}` instead. Keep the engine semantics for production. context_json is used only by the test at 1366 (non-empty env, so it is unaffected).
- `os/executable_lookup.rs ← integrations::which (+ js::find_exe dedupe)` would change behaviour. which (integrations.rs:160-175) reads the process PATH only, defaults PATHEXT to ".EXE;.CMD;.BAT;.COM" (different order), never tries the bare name, does not filter empty segments, checks is_file only (no exec bit), and does not handle absolute or relative-with-separator names. find_exe uses the effective child env through `var`, the cwd, PATHEXT ".COM;.EXE;.BAT;.CMD", and the unix exec bit. If deduped, both behaviours must stay selectable. The phase is also ambiguous: Phase 1 lists the shared os helpers, but find_exe lives in js.rs until 5.3.
- js::script_timeout (210-217) is not placed. It must NOT be merged into completion's generator_trigger_policy::script_timeout, which comes from engine.rs:143 (f64 vs i64 semantics). Also, Phase 2's `Settings` with the same getter surface must keep `i64` = serde_json as_i64 (None for floats or 1e4). If SettingValue stores numbers as f64 (the plan's example `SettingValue::Number(10.0)`), as_i64 semantics are lost and this default fallback changes.
- Not listed in process_executor's source set: `find_exe`, `is_executable`, `live()`, `struct Live` (+Drop). The plan names only `LIVE`.
- JsArg::Json(Value), TaskResult = Result<Value,String> and the load_module Map<String,Value> are serde_json types, which the application layer forbids (fitness rule 2). A typed SpecFunctionResult needs the call kind known at start (start_call takes only FnId + args). Today each caller interprets the raw Value itself: engine post_process_items/json_items/custom_result, parser `versionedSpecPath`, the `as_str` for alias/version, cli_version `stdout`. The engine GenCache stores and shares these raw Values across the Exec/Custom/PostProcess steps (engine.rs fetch). The mapping must be lossless and must not move the failure points: malformed results map to [] today, not to errors.
- The location of the ExecInput serde record is unspecified. The serde error text reaches users and spec code: "bad exec input: {e}" (282) is a JS-visible rejection, and engine.rs:862-865 has "bad script input: {e}". The same derive attributes (#[serde(default)] fields, Option<u64> timeout, HashMap<String,Option<String>> env, unknown fields allowed) must be kept on an infrastructure record. The ExecOutput→ProcessOutput VO also needs an infrastructure serializer that emits exactly stdout/stderr/status (570).
- SpecError (Aborted, Timeout, NotFound, Invalid) does not match JsError (Aborted, Timeout, Other(String)). js.rs never produces NotFound: a missing file is Other("<path>: No such file or directory (os error 2)"). Other carries free-form text: load errors, JS `String(e)` rejections, CaughtError text. Display must stay `{s}` with no prefix, plus "timed out" and "aborted by a newer request", because ParseError::NoSuggestions(e.to_string()) (parser.rs:87) is logged and the alias test matches by substring.
- wait_aborts_and_defers_on_complete (1722) imports EngineMsg::{ToggleFuzzy, Complete, Shutdown}, types::Request and Shell, and calls next_msg/try_next_msg. After the move, a test inside specs/infrastructure would depend on bootstrap and completion types. The plan lists it as a guard test but gives it no home. Move it to bootstrap/engine_server.rs once the inbox lives there, or restructure it over a RuntimeEventSource double with the same assertions.
- The 5.3 guard says 'all 18 js tests, wait_aborts_and_defers_on_complete'. The latter is one of the 18 #[test]s in js.rs, not an addition. timeout_kills_grandchildren runs only on Windows, and 6 tests are unix-only, so no single OS runs all 18.
- Test support is not placed: specs::testutil::{bundle_subset, full_bundle} (used at 1257, 1312, 1787; only TmpDir is mapped to shared/testing/temp_dir.rs) and the js.rs fake_bin helper, which is needed by both quickjs_spec_runtime tests (1311, 1344) and process_executor tests (1622).
- exec_children_die_with_the_wrapper hard-codes its own module path `"js::tests::exec_children_die_with_the_wrapper"` (1640) for a self re-exec with --exact. Moving it verbatim makes it fail (0 tests run, then unwrap on the missing "pgid="). Updating the string is restructuring and is required.
- Bridge table: `GeneratorProcessReaper ← specs ProcessExecutor::kill_live_children`. It must remain a stateless free function over the global LIVE, because the atexit hook (989-995) is an `extern "C" fn` with no captured state. A per-instance registry would stop killing children at std::process::exit. Between Phases 5 and 9, pty.rs:103 and pty.rs:1288 must call the new path directly.
- Use cases hold `Rc<dyn SpecRuntime>`, but every runtime operation mutates (start/wait/forget/load). The adapter would need interior RefCell. Today `&mut Js` is threaded explicitly, e.g. JsHost holds `&mut Js` while Loader::load uses it (parser.rs:568-582). With CommandLineParser and QuickJsSpecRepository both holding the runtime, a nested borrow (the parser borrows the runtime, then calls repository.find, which borrows it again) panics. The plan does not say how the borrows are scoped.
- Moving PRELUDE to quickjs_module_wrapper.rs separates it from the host-function registration (__ts_log/__ts_exec/__ts_sleep/__ts_done) that it relies on. The protocol names are a contract between the two files, and the prelude must be evaluated exactly once per Context (top-level let/const). The plan does not mention either constraint.
- If GeneratorContext types `shell` as the Shell enum, the default context's `currentProcess: ""` (GenCtx::default, used for start_call(None) and unknown exec ctx ids) cannot be represented. Keep a string, or an Option rendered as "".
