# Source map: src/icons.rs (at af1b304)

## Behaviour traps
- slot L140-145: emoji check runs BEFORE `if g == Graphics::Off` -> a wide-emoji spec icon shows as text even in ASCII mode. Test L443-451 comment says 'text in both modes' but only asserts Direct, so Off is unguarded; reordering the checks silently drops emoji in ASCII mode.
- slot L143-145: in Off mode fig:// icons are ignored entirely (only emoji survive); fig:// in Off mode has no test.
- slot L159 `_ => text(&s.text)`: in Tmux a badge slot loses its image AND gets badge:false (text() L232), so render.rs:492-498 draws it in the base pen, not white. Test L566-567 checks only image.is_none() and text, not the badge flag.
- placeholders L166-167: `if id >> 24 == 0 { "" } else { "\u{30d}" }` hard-codes diacritic value 1 for ANY nonzero top byte; correct only because tinted ids are exactly 0x01RRGGBB (L256). Exact string asserted at L560-563.
- placeholders width: U+10EEEE counts 1 and U+0305/U+030D count 0 under per-char unicode-width; the 2-column assertions (L553, L538) depend on per-char width.
- color L171-176: id<256 -> `;38;5;{id}`, else `;38;2;{id>>16&255};{id>>8&255};{id&255}` (top byte dropped, carried by the diacritic). Leading ';' is appended AFTER fg/bg in Renderer::pen (render.rs:476) so it overrides fg; it is emitted as 24-bit even when truecolor=false. Routing it through Renderer::rgb (256-colour downsampling) or reordering pen params breaks tmux images.
- Image ids L245: PNG id = PNGS index + 1 (alphabetical list L17-60): option=34, template=39, git=23. Inserting/reordering a name changes every id (tmux 38;5 fg, Renderer.sent cache). Tinted id L256 `0x0100_0000 | r<<16 | g<<8 | b`. Test L551 asserts option id < 256.
- badge_slot(None) L259: invalid/missing color gives the plain template PNG (Source::Png, f=100, id 39), NOT a tinted RGBA; same id as fig://icon?type=<unknown>.
- tinted L275-277: scale = a*b/256 (not /255) so 255*255 -> 254 (asserted L431); alpha copied; chunks_exact(4) drops any remainder.
- wide_emoji L181-184: strips EVERY U+FE0F, then requires exactly 1 char and per-char width 2. Swapping to UnicodeWidthStr::width (handles VS16/ZWJ) or allowing multi-char sequences changes which icons render (⭐ kept, ⚙️ rejected -> type icon, L505-512).
- spec_image L188-196: exact prefixes `fig://icon?` / `fig://template?`; no percent-decoding; missing type -> "template" (L190); empty or unknown type -> template PNG via png_slot fallback (L239-241); missing badge -> "". Anything else (https URLs, fig://path) -> None -> type default.
- hex L305-311: requires byte length 6, no '#', no trim, case-insensitive; u8::from_str_radix accepts a leading '+' so "+f+f+f" -> (15,15,15); multibyte input -> None via s.get. Must not be replaced by render::parse_color (requires '#', accepts 3/8 digits and rgb()).
- param L297-303: first matching key wins; split_once on first '=' (value may contain '='); pairs without '=' skipped; '&' inside a badge truncates it.
- badge_slot L261-269: U+FE0F removed from badge; empty -> text "  " and badge:false; pad2 only pads width-1 strings, so a badge of width >=3 (`badge=abc`) stays 3 columns and width-0 stays 0. Existing behaviour; do not 'fix' with fit-to-2.
- type_image L199-211: Special = tinted (0x62,0x8d,0xad) + "➡️" -> "➡ " (narrow, padded); Shortcut = (0x34,0x98,0xdb) + "💡"; History is text 📚 with NO image even in Direct/Tmux; Arg -> box, AutoExecute -> carrot.
- ascii_slot L214-226: " {c}" right-aligned; Arg and Special share '*'; AutoExecute '↪' (U+21AA, width 1). Both matches are exhaustive with no `_` arm; keep it that way.
- tmux_graphics L125-135: trim, then split_once(' '): first field must be exactly "on" or "all"; remainder (termname + termtype) is substring-checked case-sensitively for "kitty"/"ghostty". An empty allow-passthrough shifts the fields -> Off (L593).
- detect L102-121: TMUX set, even to "", takes the tmux path, and inside tmux KITTY_WINDOW_ID/TERM_PROGRAM/TERM are ignored (never Direct). env::var(..).ok() treats non-UTF-8 as unset. TERM_PROGRAM=="ghostty" and TERM=="xterm-kitty" are exact; KITTY_WINDOW_ID is any value. argv order `tmux display -p [-t $TMUX_PANE] <fmt>`; exit status ignored; spawn error -> "" -> Off; NO timeout (reusing shared process_runner/output_with_timeout would add one). No test covers detect.
- detect call site pty.rs:441-447 runs before the engine and child spawn ('Everything that can fail goes before the child exists'), once per session; keep it at module build time, not lazily per frame.
- transmit L316-346: first chunk is `\x1b_G{action},i={id},{format},q=2,m={more};…\x1b\\` in exactly that key order; later chunks carry only `m=`; CHUNK = 4096 base64 chars; more = (k+1)*CHUNK < enc.len(); empty payload -> empty string. Direct `a=t`; Tmux `a=T,U=1,c=2,r=1`. Tmux wraps EVERY chunk in `\x1bPtmux;…\x1b\\` and doubles every ESC, including the APC's own ST (L340, asserted L576-579).
- place L350-352: `p` is the frame's patch index + 1 (render.rs:379), not the image id; c=2,r=1,C=1,z=-1,q=2. CLEAR_PLACEMENTS `a=d,d=a,q=2` is only emitted in Direct (render.rs:306,350); tmux never gets placements or deletes (render test tmux_images_are_placeholders).
- base64 L357-373: hand-rolled standard alphabet with padding. base64 0.22/0.23 exist only as transitive deps in Cargo.lock; using one would add a direct dependency (AGENTS.md: no new crates).
- Slot.text is always exactly 2 columns for every ItemType in Direct, Off and Tmux (loop L521-539); PNG slots are two spaces "  " that the image covers in Direct.
- tinted() currently runs on every slot() call (every frame for each badge row); moving the tint to transmit time is invisible ONLY if the Renderer.sent dedupe stays keyed on the same u32 id (render.rs:373).
- png_slot/badge_slot `.expect("template is in PNGS")` (L241, L259): any split of the name list must keep "template" or this panics at runtime.
- Visibility: items are `pub` in a private `mod icons` (main.rs:8) under #![allow(dead_code)] (main.rs:3); making them pub(crate) is fine, but removing the allow (Phase 11) will flag nothing here, since every item is used.

## Plan gaps
- Layering contradiction: plan 8.3 puts slot/png_slot/badge_slot + 'tint maths' in dropdown/domain/services/icon_resolver, but png_slot embeds PNGS bytes (L246) and badge_slot calls tinted() over TEMPLATE_RGBA (L257, L278), which plan 8.5 puts in terminal_session/infrastructure/adapters/icon_assets. dropdown must not depend on terminal_session (section 2 graph), and domain must not import infrastructure (fitness rules 1/3). Taken literally this fails to compile or breaks the architecture test. Behaviour-neutral fix, which matches the glossary's 'IconId = which icon': IconSlot carries IconId {Png(index) | Tinted(r,g,b)}. The ordered 42-name list and the kitty id formula (index+1, 0x01<<24|rgb) live in dropdown domain. icon_assets resolves bytes BY NAME, and kitty_graphics/overlay_renderer builds the byte-carrying Image at transmit time, tinting there via a domain tint(template, rgb).
- With the split above, the id order lives in domain and the bytes in infra. If infra indexes bytes by position, it needs a guard test that both lists are equal in order. That is a new test, which plan step 3 allows for new seams.
- placeholders (L165) and color (L171) are not placed. placeholders must remain inside slot()'s output, because tmux_uses_placeholders asserts slot().text byte-exact, so it goes to the domain. color encodes the other half of the same id, so keep it beside placeholders in dropdown domain (icon_id.rs) and let overlay_renderer import it. The plan's kitty_graphics list does not include it.
- Unplaced items: CLEAR_PLACEMENTS (L355), CHUNK (L66), Source (L74), Image-with-bytes (L69), the pngs! macro (L10), and helpers text/png_slot/badge_slot/pad2/width/param/hex. The glossary has no name for Source, and the bare word clashes with inline::Source (-> GhostTextSource).
- Tests: 8.3 names only resolves_like_q and 'the tint test'. tmux_uses_placeholders mixes domain asserts (slot/placeholders/color) with infra asserts (transmit Tmux, tmux_graphics), so it must be split. That conflicts with 'existing test names are kept' for the infra half (new name, +1 test). base64_matches_rfc4648, transmit_chunks and assets_are_pngs are not mentioned. 8.5's 'round-trip tests unchanged' refers to the render tests images_fill_the_icon_slot and tmux_images_are_placeholders (render.rs:1308-1352), which use icons::CLEAR_PLACEMENTS and Graphics and need import updates.
- The tint test is sent to dropdown (8.3) but reads TEMPLATE_RGBA (L422-425), which goes to terminal_session infra. dropdown may not import it. Decide: either put the test in icon_assets, or give the domain test its own include_bytes! of assets/icons/template.rgba.
- Section 1 rule 'Domain struct fields are private' applied to Suggestion (<- types::Item) breaks slot()'s direct field reads (it.icon L139, it.kind L144/L148) and the tests' struct-update construction `Item { icon: .., ..item("x", kind, "") }` (L439-442, L544-547). completion/domain/test_fixtures.rs needs an icon-setting builder, and Suggestion needs icon()/kind() accessors.
- Dedupe hazard: plan creates color_parser (<- parse_color) and icon_resolver side by side. icons::hex has a different grammar (no '#', 6 digits only, '+' quirk), so merging them changes which fig://template colours are accepted. Deduping icons::width with text_fitting::width (render.rs:829-835) is safe: both sum per-char UnicodeWidthChar widths.
- include_bytes! paths (L12, L63) are relative to src/. Section 6 says the include paths are updated, but at adapters depth that means ../../../../assets/icons/; a CARGO_MANIFEST_DIR concat is less fragile.
- Phase ordering: 8.5 moves kitty_graphics, icon_assets and Renderer into terminal_session/infrastructure before terminal_session exists (Phase 9). terminal_session is only registered in the architecture test after Phase 9, so no fitness check catches a bad cross-import from 8.3/8.5 until then. Imports of Item/ItemType change earlier, in Phases 5/6 (SuggestionKind, Suggestion), and the fixture import (menu::tests::item) changes in 8.2.
- detect() has no test and no port. The plan keeps it as a plain adapter function, which is fine; no step should add a timeout or a `which tmux` lookup while moving it, since both would change behaviour.
