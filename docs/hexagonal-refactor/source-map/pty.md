# Source map: src/pty.rs (at af1b304)

## Behaviour traps
- Panic routing, two tiers (59-70 vs 688-697). A panic inside guard() turns the session into a pass-through and the child keeps running. A panic outside guard (step's batching 610-633, next_deadline, the probe strip if moved out of guard, cleanup) reaches the outer catch_unwind and exec's a NEW fallback shell (70) while the wrapped shell may still be alive. Moving logic across that boundary, for example 'late probe replies stripped by the driver' (today inside guard(|s| s.on_input) at 606), changes which tier handles a panic.
- `std::panic::set_hook(... logger::error("panic: {info}"))` (46) is process-wide and is set before start. It also stays installed for debug_shell's code after pty::run (cli.rs:832-836).
- Shell resolution order (47-55): explicit, then TABSMITH_SHELL (non-empty), then on Windows "pwsh", else $SHELL. Windows never reads SHELL. Login is only when `TABSMITH_IS_LOGIN_SHELL == "1"` (56).
- argv (80-82): a first extra arg not starting with '-' replaces the shell, even when shell is None. `--login` is added only for Bash/Zsh/Fish (Shell::from_name accepts paths) and BEFORE the extra args (87-95).
- Two different shells (414-419): Session.shell defaults to Pwsh on Windows and Bash elsewhere, but Tracker::new gets the raw `Shell::from_name(program)` Option. shell() (740) prefers tracker.shell. Do not merge them into one value.
- `modes` handoff (401-402): `*modes = Some(m)` runs immediately after sys::enter, so every later failure in start still restores raw mode in run (67-69). Modes is Copy and is restored again in cleanup (1289).
- Ordering comment at 441: everything fallible (renderer, spawn_resize, engine::spawn, openpty, spawn_command) runs before the child exists. icons::detect() (447) spawns `tmux display -p` before the PTY. The title OSC `\x1b]0;{base}\x07` is written AFTER spawn (483-484), with base = rsplit on '/' and '\\'.
- Probe (423-439): PROBE goes out through write_stdout directly, not emit. The loop breaks only when a CPR is seen or the 300ms deadline passes. probe_until is set only when there is no CPR. With a CPR the model gets a synthetic `\x1b[{r};{c}H` via tracker.advance. Without one, `\x1b[H\x1b[2J` clears the real screen (438). Leftover typeahead is sent to the PTY writer after spawn_input (509-512).
- Child env (467-474): TABSMITH_TERM=CARGO_PKG_VERSION; TABSMITH_TERM_TMUX only if TMUX is set; TABSMITH_SESSION_ID; TABSMITH_SHELL and TABSMITH_IS_LOGIN_SHELL removed. cwd = current_dir if is_dir, else settings::user_home() (the user's home, NOT the data dir). fallback sets TABSMITH_TERM_DISABLED=1 instead (112-114).
- `drop(pair.slave)` (476) right after spawn is required for EOF on the reader. Credits: sync_channel(4) pre-filled with 4 sends (488-491).
- session_id format (303-313): 32 lowercase hex digits = `{:016x}{:016x}` of (nanos as u64, pid ^ nanos.rotate_left(17)). The shell scripts echo it in NewCmd={sid}. A Clock with only ms/secs would change it.
- Main loop (565-594): on_timers runs after EVERY message and every timeout, not only on timeouts, and is skipped in passthrough. exit_at is checked after each message. Disconnected ends the loop. Exit code = `exit_code.unwrap_or(0)`.
- Batching (610-633): all queued Msg::Pty chunks are concatenated. The first non-Pty message is stashed and handled next, before any blocking recv. Credits are returned with try_send once per chunk, AFTER handling (also after a panic). In passthrough the raw batch is emitted with OSC 697 markers NOT stripped (the test asserts `out\x1b]697;NewCmd\x07`, 2056).
- Stdin panic semantics (602-608): `raw = !menu.intercepting(&settings)` is computed BEFORE on_input and uses intercepting(), not drawable(). On a panic the read is forwarded only if raw. on_keys writes to the PTY only as its last statement (1138-1140). Any earlier write breaks this.
- PtyEof returns `exit_code.is_none()` (634-637): the loop continues until the child exit arrives. ChildExit: if EOF was already seen, stop; else exit_at = now + 200ms. On Windows the master is dropped on a helper thread (655-657). Msg::Term sets exit_code 129 for SIGTERM and SIGHUP alike (664).
- Resize in passthrough resizes only the master PTY, not the model (638-647). on_resize (1177-1182) ignores 0 dims and a size equal to the MODEL's size (not the PTY's).
- Ghost reply accepted only if `req == s.req && req == s.llm_req` (673). It is keyed by the CURRENT `s.sent` buffer, not the request's. text None clears a previous llm ghost. Then redraw() with NO release_held (unlike on_completion).
- guard (694-695) emits renderer.take_clear(). on_output takes the clear LATE (758-759, comment 'Taken late: a panic above leaves the clear cached for guard'). Moving take_clear earlier changes what a panic leaves on screen.
- emit uses `cfg!(test)`, a compile-time branch, to write to the sink (700-704). Session tests never touch stdout. The capturing TerminalWriter must reproduce this for every emit, including the inline Bell `emit(b"\x07")` from on_keys (1122), which happens BEFORE the redraw frame and before fwd goes to the PTY.
- next_deadline (707-725): in passthrough only exit_at counts. Otherwise poll_at is always Some, so recv never blocks forever. It uses the lock DEADLINE (l.0), not the cap. The test asserts `next_deadline().is_some()` in passthrough after ChildExit (2061).
- on_output order (744-765): if resize_at is set, re-arm it to now+150ms before anything else, so output extends the resize quiet time. was_alt is read before feed; leaving the alt screen triggers menu.error_reset. Output = take_clear + body + take_repaint + frame in ONE emit. release_held runs AFTER that emit and may produce a second emit and a PTY write.
- on_event (772-776): NewCmd(None) (a prompt redraw) sets redraw_until and polls files, then RETURNS EARLY. It does NOT clear unechoed, echo_pending, ghost, llm, llm_at or the lock. prompt_redraw_* tests depend on this. NewCmd(Some)/CommandEnded send to the engine BEFORE poll_files, so CommandFinished goes out before Session/Settings. PreExec only error-resets and keeps `sent`.
- refresh (798-861): new = None on the alt screen, else extract filtered by at_prompt. The unechoed base is computed BEFORE cur is replaced (lock.expected, else the OLD cur). Lock: inside its deadline and not applied, return with no request. After the deadline, before the cap, with buf == before (nothing echoed): re-arm and return. Otherwise release. The `_ => self.redraw_until = None` arm (833) clears the grace for any non-empty buffer.
- refresh dedup and empty line (835-851): it skips if (buffer, cursor) equals sent. Otherwise req += 1 and sent/changed_at are updated even for a whitespace-only buffer, which sends NO Complete but does error_reset and clears echo_pending. A late reply for the old req is then dropped.
- on_completion (863-889): stale req is dropped. echo_pending is cleared only if `c.req > r` (strictly). The ghost is updated when phase==Parse OR ghost.is_some(), so a Generators reply without a ghost keeps the old one. LLM debounce needs Parse && no ghost && `c.cursor == c.buffer.len()` (byte length) && llm_enabled, and is measured from changed_at, not now. The spinner is armed only if not already armed. Then menu.on_completion, redraw, release_held, in that order.
- Settings call-site defaults read in pty: `bool("inline.enabled", true)` (892, 902), `i64("inline.debounceMs", 300).max(0) as u64` (880), `bool("autocomplete.onlyShowOnTab", false)` (1036), `bool("autocomplete.disable", false)` (1037). Today's getters use serde_json as_i64/as_bool: a float like 250.0 or a string "true" falls back to the default. A SettingValue::Number(f64)-based i64() would return 250 instead of 300.
- ghost_text (901-918): returns None if inline is disabled, during preexec, on alt, with an empty buffer, a cursor not at the end, or shell_ghost. The local ghost wins over llm (array order [&ghost, &llm]). typed=true uses basis(), and None propagates.
- note_forwarded (933-945): a printable no-mod char counts as typeahead only when the cursor is at the end. Otherwise even a plain char clears unechoed and sets echo_pending = Some(req).
- on_keys (1029-1141): when held is non-empty, the chunk is appended and the function returns WITHOUT decoding, so decoder state is untouched and the test panic hook never fires. Paste rule: `prompt` turns false once typed >= 2 printable keys in this read. On hold it keeps `chunk[ev.bytes.start..]`, sets held_at = now + INSERT_LOCK, and RESETS the decoder before the break.
- on_keys match precedence (1072-1110): intercepting Action -> menu.handle; intercepting Unknown -> swallowed but redraw=true; tab_show; global Show/ToggleAutocomplete; else ghost accept or forward. In the forward path `continue` skips redraw=true. Enter sets submitted = basis() BEFORE note_forwarded. Ctrl-C/Ctrl-D (case-insensitive via is_ctrl) and Enter error-reset the menu and redraw.
- End of on_keys (1131-1140): rerequest (sent=None, then refresh, which can send EngineMsg::Complete) runs BEFORE the redraw, which runs BEFORE the single writer.send(fwd). Effect::Write(b"\r") sets submitted only at the prompt.
- insert (1144-1173): dropped during preexec. The buffer/cursor come from menu.last() (the reply's), else cur. Reconciliation is against basis(). execute sets submitted = expected. Lock = (now+100ms, now+1s, expected, before) with before = cur buffer, else ib. RecordInsert is sent after the lock is set.
- insertion_bytes counts extra typed chars with chars().count() (131). expected_buffer falls back to ib.len() when the cursor is not a char boundary and pops `delete` CHARS (155-157). Both are pinned by tests, including the 'aé' and 'stéé' cases.
- parse_probe (245-262): the last CPR wins. `bg = rgb.or(bg)`, so the last valid colour wins. A malformed OSC 11 body with a valid terminator is CONSUMED, not passed through (300). Colour scale = v*255/(16^len-1) for 1-4 hex digits.
- Late probe window (1010-1025): `Instant::now() < t` is checked, but probe_until is cleared only when a CPR arrives. During the window EVERY CPR- or OSC 11-shaped sequence in user input is stripped. A bg reply also re-themes the renderer with the current settings.
- on_timers (1207-1258): fixed order. resize->repaint; redraw grace->refresh; release_held; lock deadline->refresh; llm_at->send Llm (only if sent is Some; llm_req = req); spinner (menu.loading() reads Instant elapsed internally, 316-318); file poll. `now` is captured once at the top. repaint+frame go out in one emit, else a plain redraw.
- poll_files (1261-1280): the session file reloads only when its mtime is Some and differs, so deleting the file does not reset session_mtime. Settings reload whenever the Option<mtime> differs, including Some->None (file deleted) -> Settings::load() -> defaults. Settings::load logs `settings: {e:#}` and returns the default on a parse error. The session is checked before the settings. Returns true only for a settings change.
- cleanup (1283-1293) order: emit(clear + `\x1b[0m\x1b[?25h`), EngineMsg::Shutdown, kill_live_children, modes.restore, remove the session file (only if session_path resolved; SessionCtx::path errors become None at 515).
- pump (222-236): 16 KiB buffer (the test asserts 16*1024). It takes a credit BEFORE each read, retries Interrupted, maps any error to EOF (Linux EIO), and ALWAYS sends PtyEof at the end.
- Unix wait_pid (1378-1391): retries on EINTR, any other error returns 1, a signal returns 128+sig (test: kill -9 -> 137). wait() uses child.wait() only when process_id is None.
- User-visible strings: `tabsmith had an error: {err:#}` (102), `tabsmith: could not start {}: {err}` (122), `internal error (see pty.log)` (65), `stdin/stdout is not a terminal` (395), `no shell to run (set SHELL or pass --shell)` (399), context `terminal size` (403), and the Windows bails (1473, 1485, 1491). Log lines: `pty: {argv:?} {cols}x{rows} sid {sid} cpr {cpr:?}` (480), `pty: internal error; passing the session through until the shell exits` (692).
- cfg differences: cfg!(windows) shell default (50, 414), fallback /bin/sh vs pwsh (106), Unix exec vs Windows status().code().unwrap_or(1) (115-121), master take_if (655), Tracker.defer = cfg!(windows) (tests force false, 1790). Windows Modes/lf_to_ind feeds tracker.filter.lf_to_ind (420).
- Engine replies arrive on the SAME Msg inbox: engine::spawn(tx.clone(), settings.clone()) at 451 sends Msg::Completion(Box<Completion>) and Msg::Ghost into the PTY loop's channel, interleaved with Pty, Stdin, Resize and ChildExit. The ChannelCompletionEngine/engine-server split must keep that single inbox, or ordering and stash batching change.
- Tests depend on the real clock: slow_echo, split_prompt_redraw and keys_after_an_unmodelled_key set fields to Instant::now() and then call on_timers, which reads Instant::now(). Injecting a FixedClock into these use cases would change what is due.

## Plan gaps
- ghost_key (164-184) takes keys::{Key, KeyCode, Mods} (dropdown VOs from P8). Phase 7.1 moves it, with ghost_keys_and_words, into ghost_text/domain, but section 2 does not allow ghost_text -> dropdown, and in P7 the keys still live in crate::keys. Fix: keep ghost_key in terminal_session KeyRouter and split the test (ghost_key asserts -> key_router.rs, next_word asserts -> ghost_text.rs).
- 'A use case never calls another use case' collides with shared helpers. refresh() is called from on_output, on_keys and on_timers (x2). release_held() (which re-enters on_keys) is called from on_output, on_completion and on_timers. poll_files() is called from on_event and on_timers. redraw()/frame() are called everywhere. The plan does not say where these live; they need to be TerminalSession aggregate methods returning commands, or a domain service, with no copies per use case.
- Event table: late probe replies are 'stripped by the driver', but on_input (1010-1025) also mutates aggregate and renderer state (terminal_bg, renderer.set_theme(Theme::from_settings(..)), probe_until) and today runs inside guard. Doing it in the driver outside guard changes panic handling (fallback shell instead of passthrough). late_probe_reply_is_not_typed asserts that state.
- Phase 9.6 says 'the #[cfg(test)] panic injection stays at the driver's call site', but it sits inside on_keys' per-decoded-key loop (1040-1041), which becomes HandleKeystrokesUseCase. At the driver it would also fire when keys are held (today on_keys returns at 1030-1033 before decoding) and for chunks that decode to nothing. Keep it in the use case's loop; this also means application code references a test-only hook.
- ProcessShellOutputUseCase 'returns one byte buffer; the driver writes once' is not today's behaviour. on_output emits once and THEN release_held (764) may run on_keys, which can emit a Bell, a separate redraw frame and a PTY write. Folding these into the batch buffer reorders stdout against PTY writes.
- SessionContextRepository {save, find, remove, prune_older_than} has no last_modified, but poll_files (1262-1268) reloads the session file only on an mtime change (Option compare, deletion ignored). The settings side relies on SettingsRepository::last_modified returning Option<SystemTime> with None == missing (a deletion triggers a reload to defaults).
- SessionId generation (303-313) needs SystemTime nanos and process::id. The plan's Clock port exposes ms/secs and Instant only, and SessionId is a domain VO. Either generation stays in infra (session_runner) or Clock grows a nanos read. Using ms changes the id's entropy and layout.
- cwd() (731-737) falls back to std::env::current_dir() on every request and LLM call. That is I/O inside what the plan makes the TerminalSession aggregate, and no port is named for it.
- fallback (103) and cleanup (1288) both call crate::js::kill_live_children. The plan bridges only EndSession through GeneratorProcessReaper. fallback_shell.rs in terminal_session infra would have to import specs infrastructure (forbidden by rule 3) unless the reaper is passed down to the driver.
- Session start reads settings::user_home() (463), the user's HOME/USERPROFILE, not the data dir. The plan's shared kernel has DataDirectory only; user_home has no placement (maybe os/process_info or a ShellEnvironment port).
- Phase 9.3 says '7 pure tests' come from pty.rs, but after Phase 7 takes the two ghost tests only 4 pure domain tests remain for the listed terminal_session domain items: insertion_bytes_reconcile, expected_buffer_after_insertion, unechoed_keys_are_consumed_by_their_echo, child_argv. probe_replies is pure but the plan puts it in infra terminal_probe. pty_reader_waits_for_credits and signal_death_exit_code are infra.
- Phase 9.5: 'each test arranges TerminalSession + AlacrittyTerminalScreen + RecordingCompletionEngine + CapturingTerminalWriter' leaves out a WrappedShell double. Most tests assert bytes sent to the shell via sent(&pty) (the `writer` channel), which is separate from stdout (the sink). Also: panic_turns_the_session_into_a_pass_through, panic_while_handling_keys_still_forwards_them and conpty_is_closed_off_the_main_loop exercise guard/step/next_deadline, which belong to the driver (session_runner), not a use case. Most tests span several use cases, so a shared #[cfg(test)] fixture is needed that the plan does not place.
- Phase 6.6 switches pty.rs from Sender<EngineMsg> to the CompletionEngine port before Phase 9. enter_records_the_submitted_line and no_history_command_still_ends swap `s.engine = tx` to inspect messages, so RecordingCompletionEngine must exist and those tests must be restructured in Phase 6, not 9. The double must record every message kind in order (the test filters out Complete and expects exactly [CommandEnded]).
- Phase 2.2's per-key default-equality tests list only autocomplete.height, autocomplete.width, inline.enabled, autocomplete.theme and inline.source. The pty call sites also default inline.debounceMs=300, autocomplete.onlyShowOnTab=false and autocomplete.disable=false (880, 1036, 1037). The catalog agrees today, but these are untested. The wrong-type fallback (as_i64 on 250.0 returns the default 300) is a separate behaviour that the catalog-default getters must keep.
- Phase 8.2 passes `now` into Menu, but pty calls menu.loading() (1243), which reads `t.elapsed()` internally, and menu.on_completion. The call sites must pass a fresh Instant::now(), not on_timers' captured `now`, to stay exact.
- The plan assigns the startup steps to PrepareSessionLaunchUseCase (argv, env, title), but the title is written after spawn and uses write_stdout directly (484). The CommandBuilder env (468-474) and the fallback env (112-114) are two different env sets for two launch paths. The plan does not say whether WrappedShellCommand models both.
- EXIT_GRACE, PTY_CREDITS and the Session plumbing fields (credits, master, modes, passthrough, rx) are not named in the layout. HandleShellExitUseCase cannot own the loop-control return values of step (PtyEof -> exit_code.is_none(), ChildExit -> false when eof); those stay in the driver.
- The architecture fitness test flags any `{crate}::` in application code (architecture_tests.rs), so TermMode/grid reads in suppressed/drawable/alt (727-985) must go through ScreenState before those functions move. The plan lists ScreenState, but it must also carry tracker.at_prompt, cur.is_none, resize_at, repaint, filter.in_string, filter.scroll_region, redraw_until and pwsh_list_view, plus grid columns>=10 and lines>=3 and input_needs_wrap.
