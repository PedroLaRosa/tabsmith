# Source map: src/integrations.rs (at af1b304)

## Behaviour traps
- `integrations status --format json|json-pretty` key order: serde_json is built without preserve_order (Cargo.lock serde_json deps: itoa, memchr, serde, serde_core, no indexmap), so json! at 1106-1113 emits sorted keys: {"errors":[{"error":{"message":null,"title":e},"shell":…}],"integrations":[{"description","file_name","installed","shell"}]}. A #[derive(Serialize)] DTO would print fields in declaration order instead.
- Snapshot test self-blesses: 1380 `if bless || !path.exists() { std::fs::write(&path, &got) }`. If a moved test computes the snapshot path wrong (not CARGO_MANIFEST_DIR/tests/snapshots/init_{shell}_{when}.snap), it writes a new file and passes without checking anything.
- Inverted launch flag: 355 `let launch = |snap| if snap || should_launch().0 { 0 } else { 1 };`, so SHOULD_TABSMITH_LAUNCH=0 means launch. LaunchDecision → script value must keep true→0.
- init_output I/O is lazy and depends on the phase (349-374): exe_path() runs for every phase unless snapshot; parent_exe() runs only for Bash/Zsh Pre; should_launch() (env + stdin) runs only for Pre. With parent None, the TABSMITH_SHELL line is omitted (365). Snapshot mode uses parent '/bin/zsh' even for bash (360-361). Any error becomes stdout '# Could not load source: {e:#}' with exit 0 (331-336).
- Print macros differ on purpose: init_cmd `let _ = writeln!(std::io::stdout(), "{out}")` (335, no panic on EPIPE); should_launch_cmd `println!` (461); get_shell_cmd `print!("{p}")` with no newline and the flush ignored (468-469). Standardising them changes output or broken-pipe behaviour.
- TABSMITH_INIT_SNAPSHOT_TEST is tested with `var_os(..).is_some()` (344), so a set-but-empty value enables snapshot mode. It is read when init runs, and cli::debug_shell (cli.rs:824) goes through the same path.
- launch_decision checks presence, not value: `has = |k| env.contains_key(k)` (413), so `CI=` (empty) still means 'In CI'. The TERM rule applies only under `cfg!(unix)` (439). The stdin message is chosen by `cfg!(windows)` (444-448). Rules are first-match in exactly the order of 415-452. The reason is formatted as `format!("{} {why}", if launch {"✅"} else {"❌"})` (455).
- The two env snapshots are not the same: should_launch keeps lossy values and drops only non-UTF-8 keys (398-400: `k.into_string().ok()?, v.to_string_lossy()`). pre_cmd drops an entry when its key or its value is non-UTF-8 (485-487: `v.into_string().ok()?`). One shared ShellEnvironment env snapshot would change one of them.
- stdin check per platform: Windows `is_console(stdin().as_raw_handle())`, otherwise `stdin().is_terminal()` (401-407).
- pre_cmd id filter (478-484): non-empty, ASCII alphanumeric or '-' or '_'. Anything else returns a silent Ok(1). The comment says 'hex', but tightening the VO to hex would change behaviour.
- pre_cmd order (493-495): write the file, then prune, and prune only after a successful write, using the parent dir. prune_run_files (501-511) deletes ANY regular file (including stray `*.tmp-<pid>` files) whose mtime is strictly more than 24h old. A future mtime gives `elapsed().unwrap_or_default()` = 0, so the file is kept. Directories such as debug-shell-<pid> are kept. All errors are ignored.
- write_private (516-534): `create_dir` (NOT create_dir_all), so a purged data root is never recreated; this is tested at 1801-1802. It chmods the dir to 0700 on every write, even when the dir already exists (528), and sets the file to 0600 via OpenOptions mode, which applies only at creation (529). Temp name `path.with_extension(format!("tmp-{}", pid))` replaces '.json' (522). The temp file is not removed on failure and symlinks are not followed. Rename context: 'writing {path}'.
- Dotfile write (623-647): canonicalize first. A dangling symlink resolves to `path.parent().join(read_link)` (625-628), whereas Store::save falls back to the path and would replace the link with a file. create_dir_all errors are keyed to `dir`; open, rename and write errors are keyed to `path`, the user-facing link (630, 637, 646). It pre-opens an existing target for writing so a read-only file reports PermissionDenied (633-638). Temp ext `tabsmith-tmp-{pid}`: with_extension appends on '.zshrc' but replaces '.ps1' on Microsoft.PowerShell_profile.ps1 (639). Old permissions are copied to the temp file; a new file gets the umask default (641). The temp file is removed on failure (643-645).
- Uninstall normalises whitespace (962-969): `format!("{bom}{}\n", kept.trim())` is written whenever it differs, so leading and trailing blank lines are dropped and an empty file becomes "\n", even with no tabsmith lines. Top-level `tabsmith uninstall` runs it on EVERY integration (`|_| true`, 1253), so it rewrites existing untouched .profile/.bash_profile files. `integrations uninstall` only touches files with has_traces (1026). Merging the two flows changes which user files are rewritten.
- install order (898-931): is_installed returns Ok early, which includes the `# tabsmith ignore` opt-out. Then backup to `data/backups/<now_secs>/<file_name>`; two installs in the same second share and overwrite that backup. Then self.uninstall, then re-read, then write_scripts, then write the dotfile only if `new != contents`. `self.path.exists()` is false for a dangling symlink, so no backup is taken and contents are "". The backup copy follows symlinks. Fish whole files are just written (902-904).
- Dotfile layout (916-926): `{bom}{shebang}{PRE_MARKER}\n{pre}\n{rest}`, then trim_end_matches('\n') + `\n{POST_MARKER}\n{post}\n`. split_shebang without a newline appends one (691).
- is_installed precedence (858-895): an ignore line anywhere means Ok (case-insensitive, after '#' and spaces). The candidate lines are trimmed, non-empty, and drop lines starting with '#' (the markers are such comments). Check order: pre source line → pre script bytes → post source line → post script bytes. Improper vs NotInstalled depends on `lines.contains(&src)` (883). Messages: `{path} does not source {when} integration` + ` first|last` (878-884); check_file gives `{path} should contain:\n{expected}` (662-665).
- IntegrationError Display (593-601): 'Integration not installed: {m}', 'Improper integration installation: {m}', 'File does not exist: {p}', 'Permission denied: {p}', and Io → '{p}: {e}'. doctor.rs:297-306 uses only the inner m for NotInstalled/Improper, to_string() otherwise, and gives no fix for PermissionDenied, so the variants must stay distinguishable.
- is_own_line compares with `line.trim_end()` (935): CRLF and trailing spaces are tolerated, leading spaces are not. Source lines depend on the current home and data dirs: under the home dir they become `${HOME}/` + components joined by '/' even on Windows (833-836); otherwise `p.display()` with native separators (838). They are written unescaped inside double quotes (841-842).
- rc() (786-796): pwsh → 'profile'; otherwise the file name with leading dots trimmed, up to the first '.' ('.bash_profile'→'bash_profile', '00_tabsmith_pre.fish'→'00_tabsmith_pre'). Script ext is 'ps1' for pwsh, else shell.name() (800-804). The pwsh script_contents hardcodes `--rcfile profile` (825). Fish quoting is applied inside fish scripts (812).
- Catalog order and laziness (706-749): Bash is .bashrc, then whichever of [.profile, .bash_login, .bash_profile] exist (Path::exists follows symlinks), else .profile. Zsh uses ZDOTDIR, else home. Fish uses conf.d/00_tabsmith_pre.fish then 99_tabsmith_post.fish. Pwsh spawns `pwsh` (5s) ONLY when ctx.pwsh_profile is None. doctor::script_bins sets `pwsh_profile: Some(..unwrap_or_default())` to avoid that spawn, so the override must stay possible.
- pwsh_profile errors (757-767): context 'could not ask pwsh for $PROFILE'; an empty value gives 'pwsh printed an empty $PROFILE'; the output is trimmed. output_with_timeout reads stdout only after the child exits, so a child that fills the pipe hits the timeout. Message `timed out after {}s` uses integer as_secs (189); poll interval 20ms (191).
- apply() error format (987-1011): a catalog failure becomes `"{shell}: {e:#}"` (996). An op failure becomes `"{paint("1", describe)}: {e}"` (1001), where paint checks STDOUT is a tty even though the error is printed on stderr by main's print_error or uninstall_all's eprintln. The result is `bail!("\n\n{}", errs.join("\n\n"))` (1008); the leading newlines are asserted at 1667. ran=true is set before the op runs, and the loop continues past errors.
- Shell sets differ: `integrations install/uninstall/reinstall/status` and top-level `uninstall` use default_shells() = bash, zsh and fish always, plus pwsh if it is on PATH (977-983, 1032, 1246). `setup` uses `Shell::ALL.filter(which(name))` (1164-1167). manual_text always lists bash and zsh, lists pwsh only if it is in shells, never lists fish (1220-1226), and always says '.bashrc or .zshrc' (1230). Labels are padded: 'bash:   ', 'zsh:    ', 'pwsh ($PROFILE):', joined as `{label} {line}`.
- When environment errors surface: integrations_cmd builds Ctx::from_env() before dispatch (1037), so even `status` fails without HOME or current_exe. setup and uninstall build Ctx only AFTER the confirm prompt (1161-1163, 1239-1245). init, should-launch, get-shell and pre-cmd never build Ctx. Ctx::from_env order: user_home, then settings::home, then exe_path (561-569).
- integrations install (1038-1054): mark_restart runs only on Ok(true). An error propagates with `?`, so there is no restart mark even if earlier integrations were installed. Reinstall runs `uninstall(&target, true)?` and then install, so an uninstall error aborts and there is no 'Uninstalled!' line (1072-1075). Strings: 'Installed!', 'Already installed', 'Uninstalled!', 'Not installed'.
- status always returns Ok(0). Plain format prints ALL rows first, then all `{shell}: {e}` errors (1090-1103), with paint("32","✔") / paint("31","✘"). json is compact; json-pretty uses to_string_pretty.
- mark_restart (283-289) is best effort: if state.json is corrupt, Store::load_state errors and NOTHING is written (the file is not clobbered); a save error is ignored. It is a read-modify-write of the whole flat map shared with recency (engine.rs:1209-1230 keeps other keys) and with doctor (doctor.rs:223-237 reads and clears it). Store::save does create_dir_all, so it can recreate the data dir.
- setup (1149-1210): root without --force prints two epaint (stderr) lines and exits 1. confirm bails with 'You must run with --no-confirm if unattended' when stdin is not a tty (1128-1130). If auto-install fails, it prints bold 'Could not automatically install:' and `{e:#}` to STDOUT and falls back to manual. Manual mode does `print!(manual_text)`, then write_scripts only for file_when None (so not fish), printing 'Could not install required files:'. ensure_extracted runs on every path and is fatal with context 'could not extract the completion specs'; the restart line is printed only if !manual and only after extraction.
- answer() (1137-1146): EOF prints an empty line and returns false; '' / 'y' / 'yes' (trimmed, case-insensitive) return true; anything else is false. confirm uses print!+flush, so the prompt has no newline.
- uninstall_all (1252-1277): apply errors go to `eprintln!("{e:#}")`. Purge runs even after failures (NotFound is fine; any other error prints 'Could not remove {data}: {e}' and sets failed). On failure it prints 'Uninstalled tabsmith with errors (see above).' and returns 1. Otherwise it prints 'Uninstalled tabsmith.', then (on purge) 'Restart open terminals to stop tabsmith in them.', then 'Remove the binary with your package manager, or delete {bin}.' and returns 0.
- which() (160-175) checks `is_file()` with no exec bit, uses PATHEXT default '.EXE;.CMD;.BAT;.COM', keeps empty entries, and returns None when PATH is unset. js::find_exe (js.rs:837) checks the exec bit, defaults to '.COM;.EXE;.BAT;.CMD', filters out empty entries, returns absolute paths as they are, and resolves names with a separator against cwd. Merging them changes behaviour.
- quote (292-298): fish replaces the backslash FIRST and then the quote. pwsh_sq doubles ' and U+2018–U+201B (306). Changing that order breaks integrations_quote and suggest.rs insertion.
- clap help is part of the output-equivalence capture: doc comments on IntegrationTarget, IntegrationsCmd, SetupArgs and UninstallArgs. '--silent' is documented only on Install (70); '-y' exists only on uninstall (110); IntegrationsCmd::Status uses `value_enum, default_value_t` (92). Keep them verbatim.
- Clock semantics: the backup dir uses now_secs() = now_ms()/1000, truncated (906). pre_cmd ts = now_ms(), which falls back to 0 on clock error (491). A Clock port must reproduce both.
- #[cfg(unix)] on 20 tests (should_launch_table, pre_cmd_file, dotfile_write_is_atomic, uninstall_reports_failure, the pty tests, …) and #[allow(clippy::type_complexity)] on should_launch_table must move with them; is_console and windows_parent_exe are cfg(windows) (152, 238).

## Plan gaps
- `Ctx` (543-578) is not placed. `data` maps to DataDirectory, but home, bin, zdotdir, fish_dir and pwsh_profile have no named home: they are presumably ShellEnvironment facts or an explicit VO. doctor.rs builds Ctx literals in tests (~826) and overrides pwsh_profile in script_bins, so diagnostics needs the replacement type through allowed imports.
- `When` and `IntegrationTarget` derive clap ValueEnum/Subcommand but are planned as domain VOs (integration_phase, integration_target). The domain cannot use clap, so the CLI needs mirror enums (`WhenArg`) with the same value names 'pre'/'post'. The plan names only ShellArg in init_command.
- cli::debug_shell (cli.rs:824 `init_script(shell, When::Post)`) and cli::DebugCmd::Shell (cli.rs:119 `ShellArg`) go to terminal_session/infrastructure/cli/debug_shell_command.rs. terminal_session → shell_integration is not an allowed dependency (section 2), and calling RenderInitScriptUseCase from another module breaks rule 3. This needs a bootstrap bridge or port, or debug_shell has to live in bootstrap or shell_integration.
- AtomicFile 'unifies Store::save, write_private, write' (section 4 shared). These three have incompatible semantics: purge guard vs create_dir_all, 0700/0600 vs copied permissions vs 0600 set after the write, dangling-symlink handling, temp file naming and cleanup, error types. Taken literally, unifying them changes behaviour; it needs explicit modes or three entry points.
- Phase 1.6 moves `dotfile_write_is_atomic` (real name `integrations_dotfile_write_is_atomic`) to shared atomic_file.rs, but the test drives Integration::install/uninstall and asserts IntegrationError::PermissionDenied. shared cannot import shell_integration (rule 4), and a rewrite against AtomicFile loses install-level coverage. Split it instead: AtomicFile asserts in shared, the rest in file_dotfile_repository (Phase 4).
- integrations_pre_cmd_file mixes write_private behaviour (Phase 1 → AtomicFile) with the SessionCtx round-trip (Phase 4.5 → terminal_session). It must be split, and only one half can keep the name.
- The IntegrationStatus glossary lists Installed/NotInstalled/Improper/FileDoesNotExist/PermissionDenied but omits `Io(PathBuf, io::Error)` and its Display '{path}: {e}', which install_dotfiles_reports exercises (a directory where .bashrc should be). The error is also used for operation failures (write/remove/backup), not only status.
- Plan section 4 shared: 'executable_lookup ← integrations::which (+ js::find_exe dedupe)'. The two lookups differ (exec bit, PATHEXT default order, empty entries, absolute/relative handling), so deduping changes either `which` callers (setup, doctor, default_shells, tests) or generator exec.
- Section 4 diagnostics says doctor's 'launch rules reuse shell_integration::LaunchPolicy instead of duplicating them'. doctor.rs:488-515 is a different rule set: other messages ('WarpTerminal is not supported', 'Doctor can not run in CI'), a CMD check, a TABSMITH_TERM version compare, and no FORCE/DISABLED/tmux rules. Reusing LaunchPolicy would change doctor output.
- Eager composition: `build_<module>_module(&SharedDependencies { data_directory, .. })` resolves paths at startup. Today `init`, `_ should-launch` and `_ get-shell` never need HOME or TABSMITH_HOME, and setup/uninstall resolve Ctx only after the confirm prompt. Resolution must stay lazy or fallible per command, or `tabsmith init` with HOME unset starts failing.
- IntegrationCatalog is described as '(existence facts passed in)', but the catalog also needs the pwsh $PROFILE, which comes from a 5s process spawn. That fact must be resolved lazily (only when Pwsh is requested and not overridden), and its error must stay a per-shell entry `pwsh: could not ask pwsh for $PROFILE: …` in shell order.
- apply()'s error text uses paint() (stdout tty) and the '\n\n' join, which is presentation inside what becomes application code. Use cases must return structured per-integration errors, and the CLI presenter must rebuild the exact string. The integrations_install_dotfiles_reports assertion on the formatted anyhow error then needs restructuring through the presenter.
- Test helpers are not placed: tmp, ctx, syntax_ok, snapshot_path, snapshot, ALL, pty_run, fake_bin, init_for, run_post, bash_session, GHOSTTY, VSCODE_BASH. syntax_ok is needed both by embedded_shell_scripts tests and by the dotfile adapter tests (install_uninstall, detection, enumeration, bom). It needs a pub(crate) #[cfg(test)] helper inside shell_integration; the plan places only temp_dir.
- Architecture-test scope: integrations_quote_pwsh_smart_quotes moved into shared/domain/services/shell_quoting.rs calls `which` (shared infrastructure) and spawns pwsh. If the fitness test scans #[cfg(test)] code, it flags this. Either the test exempts test modules, or the pwsh half moves to an infra test.
- SessionContext is planned for terminal_session (Phase 4.5), but `EngineMsg::Session(SessionCtx)` feeds completion's ApplySessionContextUseCase, and completion → terminal_session is not allowed. The serde file shape (env/alias/ts with #[serde(default)]) is shared between the pre_cmd writer and the pty reader (pty.rs:1265).
- state.json is read-modify-written by RestartReminderRepository (mark_restart), doctor's reader/clearer (doctor.rs:223-237) and StateFileRecencyRepository. The plan places them separately, with nothing requiring them to go through the same JsonDocumentStore and keep each other's keys.
- Plan Phase 4.3 says use cases return errors and the CLI prints. setup and uninstall_all print progressively ('Installed!' or the manual text before ensure_extracted can fail; stderr errors before the stdout summary). The CLI must keep that interleaving, for example by calling the steps in order rather than rendering one final result.
- Phase 1 moves quote, which, is_root, parent_exe, paint and output_with_timeout out of integrations.rs while the rest stays until Phase 4. The integrations tests use them via `use super::*`, so their imports must be patched in Phase 1. This is pure restructuring, but the plan does not mention it.
