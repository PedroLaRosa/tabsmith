# Source map: src/render.rs (at af1b304)

## Behaviour traps
- Clear is computed at DRAW time from the model as it was then: L382-383 `cup(&mut clear, p.row, xs); restore_cells(&mut clear, row, xs..p.x + p.w + usize::from(right));` and is stored in self.clear (L295). pty takes it BEFORE writing new PTY output (pty.rs:759). Recomputing it lazily from the current model at take_clear would restore post-output cells.
- Dedupe: L286 `if frame == self.last && !self.clear.is_empty() { return Vec::new(); }`. take_clear (L268), drop_clear (L275) and set_theme (L263) all reset `last`. So after a settings reload with an unchanged theme, the same frame is re-emitted. Making set_theme a no-op on equal themes changes the bytes.
- When guards fail, compose returns None and frame returns `self.take_clear()` (L283-284): it emits the pending clear and resets `last`. The test dedupe_guards_and_clear L1136-1139 depends on this.
- Output order in frame(): clear first, then image transmissions, then the frame (L289-294). `sent` is updated only when emitted. It is never cleared by drop_clear, set_theme or full_repaint (L273-276, L302-303), so images are never re-sent after a resize.
- Kitty placement id = patch index + 1: L379 `icons::place(img, k + 1)`. The patch order is list rows, then pop-out or description row, then ghost (L340-345, L416-463). Reordering the patches changes placement ids and byte order. It is placed at `p.x + 1` even when the span is widened left (L378).
- With images == Direct, CLEAR_PLACEMENTS goes only into the clear (L350-352) and into full_repaint (L306-308), never into the frame. With Tmux it is never emitted (test L1350).
- Render guards in compose are duplicated in pty::drawable (pty.rs:974-985): L326-331 `input.suppress || input.scroll_region || model.mode().intersects(ALT_SCREEN|ORIGIN|INSERT) || grid.cursor.input_needs_wrap || cols < 10 || rows < 3`. If both go through one RenderGuard, the set must stay exact. pty's `suppressed()` arrives only through input.suppress.
- Wide-char widening is asymmetric: left checks the start cell is a WIDE_CHAR_SPACER and p.x > 0; right checks the LAST covered cell is a WIDE_CHAR and p.x+p.w < cols (L358-360). The pad pen + ' ' is written before or after p.s (L363-371).
- Layout tie-break: L645-650. When neither side fits, `below >= above` picks Below, and the chosen side shrinks to `n = room - 1` only when items > 0 and room >= 2 (L652-658). Argument-hint mode (items==0) needs only 1 row.
- x0 aligns under the typed token: L660 `(cx as isize - query_w as isize - 4).clamp(0, (cols - w) as isize)`. query_w comes from the SELECTED item's `query` (L402-404), falling back to last().search_term only when there are no items. It is not the menu search term.
- Window scroll clamp, L411-415: `top = scroll_top.min(sel); if sel >= top + n { top = sel + 1 - n }; top = top.min(items.len() - n)`. Pure logic the plan does not place.
- Two selected indices: menu_patches clamps `sel = menu.selected().min(len-1)` (L401), but describe uses the unclamped `menu.items().get(menu.selected())` (L598). Unifying them changes which description shows when selected > len-1.
- describe: a description that is empty after trim counts as missing and falls back to "file"/"folder" by kind, then to the arg hint (L599-611). But the shown text is `clean(&d)`, NOT trimmed (L609).
- desc_row always emits the italic pen, even for an empty desc (L556-559, `r.put(&pen(;3), &fit(&desc,..))`). Skipping empty puts changes the bytes. The label has no ': ' when desc is empty (L546-550). "No description" uses a hard-coded (140,140,140) grey (L541). The spinner is right-aligned, with `end = w - 2` (L536).
- Pop-out placement, L427-432: right if `x0 + w + POP_W <= cols`, else left if `x0 >= POP_W`, else no pop-out and the description bar is used instead, WITH spinner. The pop-out has h = n+1 rows, wraps at POP_W-2 = 28 and has no bold or italic (L570-593).
- list_row: the hint shows only if the FULL title fits: L502 `width(&title) + 1 + width(&hint) <= avail` with `avail = w - 5`. On truncation, the ellipsis is never highlighted: L504-508 `kept = shown.chars().count() - 1`. Highlight indices are char indices in a Vec<usize> (L511).
- The tmux slot pen carries two foregrounds: L495 `self.pen(fg, bg, &icons::color(img.id))` gives `\x1b[0;38;..;48;..;38;5;<id>m`, and the later one wins. The badge pen is white (255,255,255) (L493). The hint pen is dim `;2` (L524).
- pen format, L476: `\x1b[0;{38..};{48..}{extra}m`. Truecolor gives `38;2;r;g;b`, otherwise `38;5;xterm256(..)` (L466-471). Tests assert `48;2;30;90;199` and `48;5;26`.
- xterm256 tie rules: `near` uses min_by_key, so on equal distance the FIRST (lower) level wins (L155-159). Grey vs cube uses a strict `<` (L169), so a tie picks the cube. The grey index is integer i32 maths, `((avg - 8 + 5) / 10).clamp(0, 23)`, truncating toward zero (L161).
- parse_color uses u8::from_str_radix and str::parse::<u8>, which accept a leading '+'. So `#+f0000` and `rgb(+1,2,3)` parse today (L132, L147). A hand-written hex-digit parser would reject them. Input is trim()ed (L130). `#rrggbbaa` is premultiplied with rounding, `(c*a+127)/255` (L137). Only lowercase `rgb(` matches. Exactly 3 components (L149).
- System theme luma is f64 with an inclusive boundary: L75 `(0.299*r + 0.587*g + 0.114*b)/255.0 >= 0.5` gives light. An integer rewrite can flip boundary colours.
- from_settings: `""` maps to dark (L71). A non-string `autocomplete.theme` gives string() None, which defaults to "dark" (L70). Builtin names NEVER read themes/<name>.json. A custom name with no home, a read error or invalid JSON gives Theme::dark() (L81-87), silently.
- from_json: Fig format only when `version` is exactly the string "1.0" AND `theme` is an object (L96-97). Anything else, including `{}` and `{"version":"1.0"}`, gives the BASE16 filler theme (#181818 bg), NOT Theme::dark(). Missing or bad colours in the Fig format fall back per field to dark (L100-109).
- The theme file path is `settings::home()/themes/{name}.json`, read on each call (startup pty.rs:446, late OSC 11 pty.rs:1016, every settings reload pty.rs:1277). TABSMITH_SETTINGS_PATH does NOT move it. The name is not sanitized (`../x` works today).
- Numeric settings are read as f64: L406 `s.f64("autocomplete.width", 40.0).max(10.0) as usize` (20.7 gives 20, -5 gives 10, a string gives 40) and menu::max_rows `.max(1.0)`. If Phase 2 getters switch to i64 or typed catalog checks, fractional or other values change.
- Ghost: L683-685 clips at the first non-blank() cell at or after cx, or at cols. Leading zero-width chars are skipped (L688-690). It is written as `\x1b[0m\x1b[90m{s}` with pad `\x1b[0m` (L701-702) and drawn only if w > 0.
- blank() (L812-819) ignores fg and bold, checks bg == Named(Background), no INVERSE/ALL_UNDERLINES/STRIKEOUT and no zerowidth. It drives both ghost clipping and the full_repaint trailing trim (L313). Changing it changes both.
- sgr(): `\x1b[0` + fg + bg + attributes in the fixed ATTRS order + underline colour (L756-785). A DIM flag plus a Dim* fg colour emits `;2` twice. color() maps by `n as usize` against alacritty's NamedColor repr: 0-7, 8-15, Dim* (fg adds ;2, bg does not), DimForeground fg gives `;2` only. Foreground, Background, Cursor and BrightForeground emit nothing (L789-809). Underline colour Named only if < 16 (L781).
- restore_cells skips WIDE_CHAR_SPACER, writes '\0' as ' ', appends zerowidth chars and emits SGR only on change, starting from an empty pen (so the first cell always gets SGR). Hyperlinks are dropped (L737-752).
- tail re-creates a pending wrap by re-printing the last cell (L714-718). It restores the cursor template pen via sgr and emits `?25h` only if the SHOW_CURSOR mode is set (HEAD always hides it) (L722-726).
- full_repaint: per row `cup(y,0)` + `\x1b[0m\x1b[2K` + cells up to the last non-blank (L309-316). Never ED 2: the test checks history_size()==0 (L1191).
- Text width must stay `UnicodeWidthChar::width` (not width_cjk) to match alacritty (L829-831). The tmux placeholder U+10EEEE counts 1 column and its combining marks 0, which the Run width accounting relies on (L229-232).
- fit(): returns s unchanged if it fits. Otherwise it keeps chars while `used + cw <= w-1` and appends '…' only if w > 0 (L838-854). wrap() uses split_whitespace (tabs and newlines split, runs of spaces collapse), starts with one empty line (empty text gives [""]), hard-breaks long words, and on overflow sets the last line to fit(format!("{l}…"), w) (L857-884).
- Spinner glyph = SPINNER[input.spinner % 10], shown only when menu.loading() (over 200 ms, Instant read inside Menu today) AND no pop-out (L451-453).

## Plan gaps
- 'one parser, not two' (plan §4 dropdown theme_json_mapper) would change behaviour if done literally. cli::parse_theme (cli.rs:340-348, serde ThemeFile) is STRICT: it rejects a non-object author, a non-string version, a non-object theme, and any non-string `shade*`/`accent*` key, and never checks version == "1.0". render::Theme::from_json (L93-125) is LENIENT: anything unparsable falls back to dark or the filler, and only shade0-7/accent0-7 are read. The unified mapper must keep a strict validate path for `theme <name>` and a lenient colour path for drawing.
- Builtin-name sets differ. render treats "" as dark and never reads themes/dark|light|system.json (L71-80). cli BUILTIN_THEMES = [dark, light, system] has no "". `theme dark` reads, validates and prints the banner of themes/dark.json when it exists (cli.rs:375-379), and theme_list hides those names. 'BUILTIN_THEMES (deduped with ThemeChoice)' must not add "" to the CLI list or make the CLI skip the file.
- theme_resolver is domain, so it cannot do I/O. The custom-file lookup must go through ThemeRepository::find, consulted ONLY for non-builtin names, with every error collapsing to Theme::dark() silently. Today nothing is logged, so an adapter that logs would add output. The plan does not say how terminal_session resolves the theme without calling a dropdown use case. It must call the ThemeResolver service + an injected ThemeRepository (the bridges table lists only FileThemeRepository).
- theme_resolver input: the plan's TerminalBackground VO is in terminal_session, but dropdown may not depend on terminal_session (§2 graph). The resolver must take Option<Rgb>.
- SHADES/ACCENTS and the base16 role mapping (L33-39, L112-124) are not placed. They are domain rules sitting inside the JSON parser.
- FrameInput (L176-187) is not placed. From Phase 9 it is the TerminalScreen::draw_overlay contract (a DTO in terminal_session/application/ports). It borrows &Settings and &Menu, which is allowed as cross-module domain types.
- Plan 8.2 makes Menu take `now` (`Instant passed in, never read inside`), but Renderer::menu_patches calls `menu.loading()` (L452) and FrameInput has no `now` or `loading` field. Without a new field the spinner timing cannot be preserved. The test at L1104-1107 relies on 'just created' being under 200 ms.
- Pure presentation rules inside Renderer are not placed: the scroll-window clamp (L410-415), pop-out side choice with POP_W (L427-432) and describe (L597-613). Leaving them in overlay_renderer (infra) is behaviour-safe. Moving pop-out placement to the domain also needs POP_W there.
- colours_and_themes is listed in 8.3 as moving with the pure parts, but L1395-1417 use serde_json (Theme::from_json) and L1419-1432 build Settings from JSON through the settings() fixture. It must be split into color_parser, theme_json_mapper (infra) and theme_resolver tests.
- truncation_and_wrap (8.3, domain text_fitting) asserts on SPINNER (L1279), which stays in the infra renderer. Split that one assertion out.
- completion/domain/test_fixtures.rs (plan) holds menu::tests::settings(json), which uses serde_json (menu.rs:522-527). Rule 1 of the architecture fitness test bans external crates in */domain/ unless it exempts #[cfg(test)] files. The plan says nothing.
- TerminalScreen port (§4 terminal_session) lists draw_overlay, take_clear and full_repaint but not set_theme (pty.rs:1016, 1277) or drop_clear (pty.rs:1194, on resize). with_images(detect()) at construction is not covered either.
- Phase 8.5 moves Renderer into terminal_session/infrastructure/adapters before Phase 9, while it still takes `&types::Model` (alacritty Term). types::Model survives until Phase 9, so this is fine, but types.rs must keep Model through Phase 8.
- Theme field privacy (§1 'Domain struct fields are private') forces accessor rewrites in Renderer (L435, L483-486, L534) and in tests (L1401-1416). Layout's private fields force the layout_decisions literals to be rewritten (restructuring only).
- text_fitting is consumed from terminal_session infra. §1 allows importing another module's 'domain types', so services need to be pub(crate) and count as allowed; the plan does not state this explicitly. icons.rs:293 duplicates width() and is not mentioned for dedupe.
