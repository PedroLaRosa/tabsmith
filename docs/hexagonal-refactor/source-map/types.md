# Source map: src/types.rs (at af1b304)

## Behaviour traps
- Shell::from_name normalisation order (L30-33): rsplit on '/' or '\\', then `trim_start_matches('-')` (all leading dashes), then `strip_suffix(".exe")` (case-sensitive, before lowercasing), then the first whitespace word, then lowercase. So "PWSH.EXE" -> None, "pwsh.exe -NoLogo" -> None, "zsh (tabsmith)" -> Zsh, "/usr/bin/env bash" -> None ("env"), "" -> None. A 'cleanup' that lowercases first, or uses Path::file_stem, changes results. No unit test pins this: add a characterization test before the move.
- `"pwsh" | "powershell" => Shell::Pwsh` (L38), but name() returns "pwsh" (L24). Not a round trip; anything that re-derives a shell string from Shell (e.g. HistoryEntry.shell) changes output.
- Shell::ALL = [Bash, Zsh, Fish, Pwsh] (L17) fixes the order of doctor dotfile/system checks (doctor.rs:255,332), the `setup` install order (integrations.rs:1164) and shell_parser test loops (shell_parser.rs:806). Do not derive Ord and sort, and do not reorder the variants.
- ItemType::from_fig (L60-71) is exact-match and case-sensitive: `"special" | "mixin" => Special`, `_ => ItemType::Arg` (so "arg", "Subcommand" and junk all become Arg). The caller maps only string `type`s (spec.rs:256-259 `.and_then(Value::as_str).map(ItemType::from_fig)`), so a non-string type gives kind None, not Arg. The inverse fig_type(Special) = "special" (suggest.rs:1352) does not round-trip mixin.
- Insertion counts are chars, not bytes (L75): insertion_bytes sends `repeat_n(0x7f, ins.delete)` and `"\x1b[D"` per cursor_back (pty.rs:137-141), and expected_buffer `s.pop()` delete times (pty.rs:156-158). spec_ghost compares `i.insert.cursor_back <= i.insert.text.len() - text.len()` in bytes (inline.rs:269); that is safe only because a single ' ' is stripped. Keep all of it unchanged.
- Item::title (L121-125) is `display_name.clone().unwrap_or_else(|| self.names.join(", "))`, and `highlight` holds char indexes into title() (L104) drawn by render.rs:501. Changing the separator or trimming breaks highlighting. first_name (L128) returns "" for empty names; menu.rs:73 compares it to "../" and menu.rs:362 skips recency when the name contains '↪'.
- Completion::error (L175-194) uses `phase: Phase::Parse` with error:true, loading:false, fuzzy:false. pty.on_completion sets ghost and arms the LLM debounce for Parse replies (pty.rs:870-880 `c.phase == Phase::Parse && c.ghost.is_none() && c.cursor == c.buffer.len()`), and engine.error then attaches a local ghost (engine.rs:563-566). A dedicated Error phase or variant would silently stop LLM ghost text for commands without a spec (guard: llm_ghost_requested_for_commands_without_spec).
- Menu keeps the last Completion with its items moved out: `let items = std::mem::take(&mut c.items);` … `self.last = Some(c);` (menu.rs:102,153); the doc at menu.rs:288-289 says last().items is empty. A CompletionResult with private fields needs a consuming split that keeps the other fields.
- triggered_generators is filled only for Phase::Parse (engine.rs:1101-1105) and read only in the Parse branch (menu.rs:130-132). Retrigger visibility compares GenKey values for equality (`c.triggered_generators.contains(&g)`).
- GenKey is `hash2(Rc::as_ptr(arg) as usize, idx)` (engine.rs:105-107), i.e. Rc-address identity, and arg_key is the same kind of hash (engine.rs:500-503). GeneratorKey must stay a plain Copy u64 newtype: Completion crosses threads in `Msg::Completion(Box<Completion>)` (L262), and keying by name or index instead of the address changes when the menu reopens.
- Request.cursor is a byte offset (L202). The engine clamps it (`req.cursor.min(req.buffer.len())`, engine.rs:464) and returns the clamped value in Completion.cursor; pty uses `c.cursor == c.buffer.len()` (pty.rs:877) to decide on an LLM request. The mid-word guard returns error(req, cursor, false), i.e. without a ghost (engine.rs:466-473).
- HistoryEntry JSONL contract (L210-221): field order command, shell, pid, session_id, cwd, start_time, end_time, exit_code, hostname. None serialises as `null` (no skip_serializing_if). There is no #[serde(default)], so lines missing command/shell/session_id/start_time are dropped as corrupt by `filter_map(|l| serde_json::from_str(l).ok())` (inline.rs:42); missing Option fields load as None and unknown keys are ignored. HistoryRecord must reproduce this exactly.
- HistoryEntry.shell is the raw OSC `Shell` marker value (tracker.rs:658 `self.shell_name = Some(v.to_string())`, 739 `.unwrap_or_default()`), not a Shell. Typing it as the Shell VO would normalise or drop values in history.jsonl. hostname is never set (always null). start_time and end_time are seconds (now_secs, tracker.rs:701,743).
- An empty command is the "do not record" marker: tracker.rs:703-707 turns it into Event::CommandEnded, and History::append skips `entry.command.trim().is_empty()` (inline.rs:63). RecordCommandUseCase must keep trim(), not just is_empty().
- SessionCtx serde (L226-231): every field has #[serde(default)], so `{}` and partial files load. load() (L242) returns None for a missing file, non-UTF-8 content, bad JSON, or an explicit `"env": null` (#[serde(default)] does not accept null). `ts` is written in ms (integrations.rs:491 now_ms()) and never read in production, but the record must still write it.
- An empty SessionCtx.env means "use the wrapper env" (engine.rs:438-442 and 479-483 `if self.session.env.is_empty() { &self.wrapper_env }`), and `alias: Some("")` means no aliases (engine.rs:447-450). SessionCtx::default() is the engine's initial state (engine.rs:338). Do not model 'absent' differently from 'empty'.
- SessionCtx::path (L235-239) is `home()?/run/<sid>.json` with no validation of sid; pre_cmd validates alphanumeric, '-' and '_' first (integrations.rs:478-481). pty does `SessionCtx::path(&sid).ok()` once at start (pty.rs:515): if home() fails, the session runs without context reload instead of failing. Resolving DataDirectory eagerly and failing at startup would change that. home() rejects empty TABSMITH_HOME/HOME values (settings.rs:9,14).
- ExecOutput reaches JS as `serde_json::to_value(o).unwrap_or_default()` (js.rs:570), i.e. {"stdout","stderr","status"}. That is the Fig executeCommand contract. ProcessOutput (no serde) must map to the same keys with status as an i32 number; the Err(String) path goes to JS as an error.
- Single-channel abort: Js::wait returns Aborted as soon as any EngineMsg::Complete is deferred (js.rs:474-479). Other messages are deferred FIFO (js.rs:504) and replayed first by next_msg/try_next_msg (js.rs:334-350). The engine drains everything queued so only the latest Complete is served (engine.rs:370-375). ExecDone/Timer are consumed by Js::internal and are no-ops in engine.handle (engine.rs:425). Js holds its own Sender (js.rs:238), so the inbox never disconnects and only Shutdown stops the loop.
- EngineMsg::Settings (engine.rs:412-418) first pushes settings into the js host (`js.set_settings`), then clears parser caches, slots and the first-token cache. EngineMsg::Session (419-423) clears the alias cache and first-token cache. CommandFinished and CommandEnded share one path (395-404): append (Finished only), clear the ghost cache, reset_slots, cur = None.
- Msg::Resize(u16, u16) is positional (cols, rows) (L259); pty passes it as `PtySize { rows, cols, .. }` (pty.rs:638-645) and the sys threads send `Msg::Resize(c, r)` (pty.rs:1401,1551). Turning it into named fields risks a silent swap. Msg::Pty batching drains consecutive Pty messages and stashes the first other message (pty.rs:612-626), with one credit per chunk.
- now_ms (L297-302) is SystemTime wall clock, `as_millis() as u64`, 0 before the epoch; now_secs is `now_ms() / 1000`. Wall-clock ms drive generator cache TTL (engine.rs:823,933) and the recency timestamps persisted in state.json (engine.rs:1138). Seconds name backups `backups/<secs>` (integrations.rs:906) and `json.bak-<secs>` (doctor.rs:411). The Clock port must keep wall-clock semantics and units for these; do not substitute Instant.
- Model is Term<VoidListener> (L309), but its Config lives at the construction sites: pty uses `scrolling_history: 2000` (pty.rs:405-408), while render tests use Config::default() (render.rs:910). Keep it that way when AlacrittyTerminalScreen takes ownership.
- Request.cwd and EngineMsg::Llm.cwd are PathBuf (L204, L279). The engine uses req.cwd as a Path for parsing and fs work (engine.rs:485) and converts with to_string_lossy only for the generator context (engine.rs:517). A String DTO field would be lossy for non-UTF-8 cwds.

## Plan gaps
- SessionContext is placed in terminal_session (§4, Phase 4.5), but the completion engine consumes it: `session: SessionCtx` (engine.rs:287,338), the Session handler (engine.rs:419-423), the env fallback and alias parsing (engine.rs:438-448, 479-483), plus EngineMsg::Session(SessionCtx) (L283). The §2 graph allows completion → shared, settings, specs, history only, so ApplySessionContextUseCase cannot import terminal_session::SessionContext. Needs a completion-owned DTO (env, alias) that bootstrap converts to, or SessionContext moved to shared.
- SuggestionKind is placed in specs (§4 specs VOs, glossary), but terminal_session code uses ItemType. render::describe matches `Some(ItemType::File)` / `Folder` (render.rs:604-605), and that code moves to terminal_session overlay_renderer in Phase 8.5; pty tests import ItemType (pty.rs:1772). terminal_session → specs is not an allowed edge. Options: move describe to dropdown, add accessors on Suggestion, or add the edge to the graph.
- settings::home() timing conflict: SessionCtx::path calls crate::settings::home() (L236), and L2 imports crate::settings::Settings. Phase 2.5 says 'Delete settings.rs', but Phase 1.4 says 'the old settings::home() family is deleted in Phase 11'. The plan does not say where home() lives from Phase 2 to Phase 4.5 / 11, and types.rs's Settings import must be re-pointed in Phase 2.
- EngineMsg::Timer: §4 table and Phase 6.6 rename EngineMsg to EngineMessage, move ExecDone/Timer out to RuntimeEvent, and say 'Timer … is deleted'. Phase 11.1 still lists 'EngineMsg::Timer' for deletion. Pick one; deleting is behaviour-neutral because nothing constructs Timer (it is only matched at js.rs:572-576 and engine.rs:425).
- The single-channel element type is not designed. The js host and its exec worker threads send ExecDone on `Sender<EngineMsg>` (js.rs:178,198,202,280). After the split the channel type is bootstrap's EngineMessage, which specs adapters cannot name. The plan keeps one channel (§7) but does not say how specs injects RuntimeEvents into it (a specs-owned channel enum, or a sink port). Splitting into two channels would break the abort-on-Complete check (js.rs:474-479).
- No port or bridge covers the engine → PTY reply path. The engine and the LLM worker send Msg::Completion and Msg::Ghost into the PTY's Msg channel (engine.rs:378,998,1176-1196; L262-263). The plan defines only terminal_session::CompletionEngine (pty → engine). The RequestLlmGhostText use case runs on a worker thread and also needs a reply sink.
- The 'domain struct fields are private' rule (§1) conflicts with production cross-module writes: the menu.rs:449-454 Insertion literal, menu.rs:357 `ins.execute = true`, menu.rs:102 `std::mem::take(&mut c.items)`, engine.rs:564-565 `c.ghost = ...`, tracker.rs:699-701 HistoryEntry exit_code/end_time mutation, and tracker.rs:737-745 `..Default::default()`. The VOs need constructors and with_*/take methods the plan does not list, and many tests use literals or patterns (see tests). Restructuring only, but large.
- 'DTOs hold primitives' and the glossary ('CompletionRequest … shell name') conflict with Request.cwd: PathBuf / shell: Shell (L204-205). Converting cwd to String loses non-UTF-8 paths (engine.rs:485 uses the Path), and a shell-name string forces a new fallible from_name branch. Keep PathBuf and the shared Shell VO.
- The domain needs time passed in, and the plan says nothing about it. tracker new_cmd/pre_exec call now_secs() (tracker.rs:701,743), but MarkerTracker becomes a domain entity in 9.1 ('cursor column in') and cannot call SystemClock. engine.record calls now_ms() (engine.rs:1138) for SuggestionRecency. Both must receive wall-clock values (in the same units) from the use case or driver.
- HistoryEntry is an Entity with 'Identity: (session id, start time)' (glossary), but it derives structural PartialEq (L210). If equality becomes identity-based, `assert_eq!(again.entries(), h.entries())` in history_file_round_trip_and_compaction turns vacuous, because every fixture has session_id "" and start_time 0. start_time is in seconds, so identities also collide within one second. Keep structural equality (or compare to_primitives).
- Completion::error (L173-195) is not mentioned anywhere in the plan, yet its Phase::Parse value is load-bearing (see traps).
- The plan does not say to drop the serde derives on Shell (L7-8) and ItemType (L45), but the std-only domain rule forces it. Verified safe: Shell and ItemType are never serialized or deserialized (the only other serde derives are cli.rs:321/329, js.rs:99 and specs.rs:144). ExecOutput's Deserialize is unused; its Serialize is used (js.rs:570) and must be replaced by the mapper.
- Phase 1.5 keeps types::now_ms/now_secs as wrappers until Phase 11, while the domain callers (tracker until Phase 9, engine until Phase 6) keep reading the global clock. That is fine, but it means the Clock port is unused by those slices until their own phase; nothing in Phases 3-4 should switch them.
