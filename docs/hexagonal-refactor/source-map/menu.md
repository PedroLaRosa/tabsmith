# Source map: src/menu.rs (at af1b304)

## Behaviour traps
- Visibility order in on_completion (L126-150), Parse phase only. First the base transition (`HiddenUntilKeypress => Visible`, HiddenByInsertion => Visible only if has_new_arg || retriggered, `v => v`). Then the onlyShowOnTab override `self.vis = orig; if has_new_arg { HiddenUntilShown }` (L141-146), which leaves HiddenByInsertion/HiddenUntilKeypress UNCHANGED, not Visible. Then `if backspaced || (large && !self.just_inserted) { HiddenUntilKeypress }` (L147-149), which overrides even Esc's HiddenUntilShown. Then `just_inserted = false` (L150). Reordering any of these changes the dropdown.
- Generators-phase replies (L108 guard) change no visibility and do NOT clear just_inserted, yet still replace `self.last` (L152). The next Parse reply's has_new_arg/backspaced/large are computed against the Generators reply (l.req, l.tokens, l.arg_key, l.command_text).
- First reply after a reset: `None => (true, false, !typing(&c.command_text, "", 1))` (L111). Any command_text of 2 or more chars counts as large, so the menu stays HiddenUntilKeypress, e.g. the first reply after Ctrl-C/Enter/PreExec error_reset or after a history recall.
- `typing` (L60-63) uses chars().count(), not bytes. `steps = c.req.saturating_sub(l.req).max(1) as usize` (L118) allows one edit per skipped request.
- `backspaced` (L121): `n > 0 && n < l.tokens.len() && l.tokens[n - 1] == c.tokens[n - 1]`. Fewer tokens, and the new last token equals the old token at the same index.
- set_items (L158-177) is called AFTER the vis update. A sticky selection survives only if `self.vis == Vis::Visible` post-transition (L160), so a reply that hides the menu (or a Generators reply while HiddenByInsertion) drops stickiness. The keep path leaves sticky=true and only scroll_into_view. The reset path zeroes selected, sticky and scroll_top. Items are replaced even while hidden (doc L156-157, test L663-664).
- `same_item` (L67-69) compares only names, kind and description (its doc wrongly mentions insertValue). Never replace it with a derived PartialEq on Suggestion: insert.text changes every keystroke and the test at L810-814 would fail.
- `select` (L338-342): `self.sticky = i != self.selected`. Re-selecting the current index (NavigateDown clamped at the bottom, SelectSuggestion of the current row) CLEARS stickiness.
- navigate (L321-336): scrollWrapAround wins (Up at 0 wraps and never hides). navigateToHistory TOGGLES history_mode (`!self.history_mode`, L328), returns [Rerequest] and leaves the selection alone. Otherwise Up at 0 gives HiddenUntilKeypress with the selection unchanged. Down never hides.
- handle (L215-217): `if self.items.is_empty() { return Vec::new(); }` applies to EVERY action, including Execute, Show/Hide/Toggle, ToggleHistoryMode, the description actions and ToggleFuzzySearch.
- SelectSuggestion (L265): `self.scroll_top + usize::from(n.max(1)) - 1`. The index is relative to the scrolled window, 0 is treated as 1, an out-of-range index is silently ignored, and vis is untouched.
- ToggleAutocomplete (L243-247): only Visible goes to HiddenUntilShown. HiddenByInsertion, HiddenUntilKeypress and HiddenUntilShown all go to Visible.
- Description actions (L254-262) are a full no-op when alwaysShowDescription. Inner `a => a == Action::ShowDescription`, so HideDescription gives false. popout() (L311-313) ORs the setting.
- error_reset (L182-185) `*self = Menu { popout: self.popout, ..Menu::new() }`. popout is the ONLY field that survives. history_mode, last, loading_since, last_inserted_gen, just_inserted, sticky and scroll_top are reset. An error reply (L99-101) returns before last/loading_since are touched. Any new field added to Menu silently joins this reset.
- loading (L103-107, L316-319): `self.loading_since.or_else(|| Some(Instant::now()))` keeps the FIRST start across consecutive loading replies. Any non-loading reply of either phase clears it. Spinner only when `t.elapsed() > Duration::from_millis(200)` (strictly greater). Keep monotonic Instant; do not swap in a wall-clock Clock::now_ms.
- show_on_tab (L275-282): exactly one item calls insert_full(0, false) whatever the vis. Otherwise it sets Visible, even with zero items (pty only calls it when has_items).
- insert_full (L353-375): sets `ins.execute = true` only when `execute && item.kind != ItemType::AutoExecute`. The record is None when the name CONTAINS '↪' (not equals) or when last is None, and it uses `c.tokens.get(c.command_index)` of the last reply. `self.last_inserted_gen = item.generator` overwrites with None too. selected and sticky are not reset. `&self.items[idx]` panics on a bad index.
- common_prefix order (L378-399): `items.len() == 1` gives a full insertion BEFORE the Special/AutoExecute guard (a lone ↪ or special row inserts). AutoExecute without original_kind fails through `sel.original_kind?`, so Bell. Auto rows never full-insert: `(!auto).then(..)` at L399 and L433 rings Bell. Every None path returns before mutating, so the fallbacks in L227-232 (navigate / insert_full) see the untouched menu.
- matching_type (L72-78) is ASYMMETRIC. A candidate `../` matches only when the selected is `../`, but a selected `../` matches every file/folder candidate. The auto row itself never matches (AutoExecute vs its original kind).
- Case and Unicode handling: the filter compares lowercased first_name with `starts_with(&q)` lowercased (L392-397). lcp is counted in chars over the sorted LOWERCASED names (L401-405), but `shared` takes that many chars of the ORIGINAL-case selected name (L406). `shared == sel.query` (L407) and `text.strip_prefix(sel.query.as_str())` (L443) are case-sensitive. Typing `CH` gives delete 2 and a retyped `che`.
- Escaping (L410-419): every `c.is_whitespace()` char, tab and newline included, becomes `"\\ "` (backslash + ASCII space).
- Full-insertion reconstruction (L421-425): `query + insert.text` only when `insert.delete == 0`. Full if `text == full || format!("{text} ") == full` (L432). Partial: raw = delete or query chars, and `(0, rest)` only if `raw == q_chars` (L437-446). The partial path sets ONLY `just_inserted = true` (L447): vis stays Visible, no record, no last_inserted_gen.
- `Effect::Insert.full` is never read in production (pty.rs:1114 uses `..`). Only the tests read it (L581, 759, 837, 852, 861, 882, 892, 902, 942).
- max_rows (L55): `settings.f64("autocomplete.height", 7.0).max(1.0) as usize` truncates (2.9 gives 2), clamps 0 or negative to 1, and falls back to 7 on a wrong type. Settings getters fall back to the default on a wrong type (settings.rs:119-133), so `"true"` as a string reads as false for the bool keys.
- `shown` (L189-193): an arg hint alone (non-empty name OR description, L196-202) makes the menu drawn but not intercepting (L205-207). Every `comp()` fixture carries ArgInfo{path, A path}, so test menus are 'shown' even with no items.
- Fixture exact values used across files: comp() always has req 1 (L500), cursor = buffer.len() in BYTES (L504), tokens from split(' ') (a trailing space gives an empty token), command_index 0. item() strips the typed query only when the name starts with a non-empty query (L467), with byte slicing `name[query.len()..]`, otherwise delete = query chars. Description is `about {name}`, priority 50.0. The render tests mutate args_hint, names and description on these.
- Real-time-dependent tests: menu error_reset_and_loading (L725-727), and render.rs `round_trip_arg_hint_spinner_and_wide_ghost` asserts 'no spinner before 200 ms' through Renderer::frame calling menu.loading() (render.rs:451-453).

## Plan gaps
- `max_rows` (L53-56) is not placed in §4. It is shared by Menu (scrolling) and render.rs:407 (layout). Suggestion: keep it as pub(crate) in dropdown/domain/entities/menu.rs, or move it to menu_layout_calculator.
- 'Instant passed in, never read inside' (§4 dropdown) does not cover Menu::loading's second consumer, render.rs:451-453 (Renderer::frame, which goes to terminal_session overlay_renderer). FrameInput (render.rs:177-188) has no `now`. The plan must add `now` to FrameInput or the renderer must read Instant::now() itself (infra, allowed). Callers that change: pty.rs:886 (on_completion), pty.rs:1243 (tick `now` from L1208), render.rs:452, plus every test call of on_completion (menu, render, pty).
- `CommonPrefix` as a domain service: today common_prefix (L378-458) mutates Menu and calls insert_full (L381/399/433), which reads self.last and mutates vis, last_inserted_gen and just_inserted. A pure service needs a result type (Fail | FullInsert | Partial(Insertion)) that is neither in the plan nor in the glossary. The common_prefix test must stay with Menu because it reads private `m.just_inserted` (L842) and checks the fallback navigation.
- Fixtures to completion/domain/test_fixtures.rs: the `settings(json)` fixture (L522-527) uses serde_json and `Settings::from_map(serde_json::Map)`. (a) It breaks fitness-test rule 1 (external crate in */domain/) unless #[cfg(test)] files are exempt. (b) It builds a settings type, not a completion type. (c) Settings::from_map over serde_json will not exist after Phase 2 (std-only domain). Better: a settings-owned #[cfg(test)] builder over SettingValue (e.g. settings/domain/value_objects/settings.rs). Tests then pass typed values; the JSON int `2` for height must stay readable as f64.
- The rule 'Domain struct fields are private' applies to Suggestion (types::Item) and CompletionResult (types::Completion), but Menu reads and moves their fields directly (`std::mem::take(&mut c.items)` L102, c.error/loading/phase/req/tokens/arg_key/command_text/triggered_generators/command_index/current_arg, item.names/kind/description/insert/generator/original_kind/query). Tests use struct-update syntax and field assignment (L610, 619, 691, 723, 802, 906, 921, 967; render tests mutate args_hint/names/description). The plan names no accessors, no `take_suggestions()` or into-parts, and no test builders for these.
- Phase 11 says remove `#![allow(dead_code)]` (main.rs:3) and 'delete whatever the compiler then flags'. That would delete `Menu::vis()` (L306, test-only), the `Effect::Insert.full` field (L23, never read outside tests) and the unused `settings` param of show_on_tab (L276), and break 10+ test assertions. These need #[cfg(test)] or #[allow] instead, not deletion.
- GenKey (u64 alias) to GeneratorKey VO: if the VO is not Copy, `self.last_inserted_gen.is_some_and(|g| c.triggered_generators.contains(&g))` (L130-132) and `self.last_inserted_gen = item.generator` (L367) need as_ref/clone. Tests use the bare literal 7 (L611, L619).
- Test module size: the menu tests span L461-1026 (~566 lines), over the plan's ~500-line rule, so they should move to sibling dropdown/domain/entities/menu/tests.rs (child module, so private-field access keeps working). Without the three moved fixtures it is ~504 lines, still borderline. The plan does not say which.
- Phase 2 catalog defaults: the menu passes literal defaults height 7.0 and false for onlyShowOnTab, disable, alwaysShowDescription (×2), scrollWrapAround and navigateToHistory. Catalog values at af1b304 match ("7", "false"), but the Phase 2.2 per-key equality tests list only height among these. If call sites switch to catalog defaults, add the five bool keys to that test list.
- Plan rule 'match with no `_` arm on domain enums': `v => v` (L139) and the inner `a => a == Action::ShowDescription` (L258) are catch-alls on MenuVisibility/KeyAction. Making them exhaustive must map Visible and HiddenUntilShown to themselves, ShowDescription to true and HideDescription to false.
- Shared fixtures consumers: pty.rs tests (L1771: comp, item, settings), render.rs tests (L890) and icons.rs tests (L378: item) all move in Phases 8.3/8.5/9. Their imports must switch to the new fixture home in the same step as Phase 8.2, or a shim will cross phases.
